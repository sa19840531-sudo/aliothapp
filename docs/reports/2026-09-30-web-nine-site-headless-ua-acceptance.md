# Web 无头 Chromium UA 调整与九站实况探索

测试日期：2026-09-30（北京时间）。代码基线：`codex/web-evidence-recovery`。原八站使用 UA 修复提交 `745e260a`；新增站的最终复测还包含 Web 页面稳定性及清障修复提交 `4012253c`。本报告以隔离测试库的 Task／Run、菜单及阶段账本、页型评估和本地证据文件为依据。网站与网络状态仅代表本次测试时点。

## 范围与判定口径

- 原八站为 `chigua.com`、`heiliao.com`、`hl365.com`、`www.91jav1.com`、`91porna.com`、`huangguoai.com`、`avhub360.com`、`hifans1.com`；另新增 `dys18.com`。先跑原八站，再单独提交新增站点。
- 使用隔离 PostgreSQL、Redis、API 和三个单并发 Worker，执行真实无头 Chromium 的 Web 全流程。每个 Task 冻结 180 分钟时间预算和 10 个菜单额度。登录使用独立浏览器会话，主探索保持原会话；仅导航观察账户与充值入口，不执行付款。
- `failed`、`review`、`incomplete` 与“技术收尾完成”“业务目标完成”分别报告。登录认证状态与未知跨域请求拦截状态分别报告。对未完成的支线不以主线截图替代。
- ready 首屏仍作为动作及遮挡判断主证据；补充整页截图按独立 `supplemental` Capture 和物理 PNG 尺寸核验，不计入页型主输入。

## UA 改动与代码验证

Web 会话从运行中的 Chromium 读取原始 `navigator.userAgent`，仅把 `HeadlessChrome/` 规范为 `Chrome/`，保留浏览器实际版本与操作系统信息。首页主会话、独立登录会话、广告及引导页子会话使用同一规范化 UA；H5 路径维持原行为。运行中的无头 Chromium 探针证实 JavaScript 与 HTTP 请求 UA 一致，均不含 `HeadlessChrome/`。

回归验证：Web UA、登录、引导页、广告定向测试 101 项通过；另有广告／H5 上下文定向测试 37 项通过、4 项按环境跳过；Ruff 检查通过。dys18 暴露的自动播放页面就绪问题另有真实 Chromium 回归：先证明通用监视器已安装和 XG 时钟整体替换时原逻辑失败，再验证修正后的 Web 截图与就绪专项测试 89 项通过；通用页面稳定与桌面 Profile 测试另有 13 项通过。该轮改动不含数据库迁移，未修改 App/H5 代码或跨域放行规则。专项回归规则同步写入 `docs/专项能力与高频回归规则.md`。

### dys18

此站凭据已存在于仓库外的本地只读白名单；账号和密码未进入 Git、命令行参数或报告。首次 Task `d6b82daf-f60b-4140-883c-74d58d0a6430` 形成 11 个 Capture，首页视频已加载、主内容存在，但就绪稳定窗口一直被播放器时间／进度与 Lottie 动画变更重置，最终 `WEB_READINESS_TIMEOUT`，未进入菜单或登录。第一次针对性修正只过滤新装 Web 监视器的自主动画；第二轮 Task `60f3aec6-ab7c-4fe4-ab85-19146d9015af` 仍在 11 个 Capture 后以同样原因失败。对比代码与真实浏览器回归发现，同文档若先安装通用监视器，后续 Web 调用复用旧回调，无法启用过滤；将监视器升级后，第三轮 Task `f11d7302-5458-467e-ba18-5f97bda104b7` 仍以 11 个 Capture、`WEB_READINESS_TIMEOUT` 收口。进一步对真实页面的 MutationObserver 记录发现，播放器每秒会将时间数字周围的 `span.time-min-width` 节点整体替换。现已将这一种明确的 XG 时间节点替换纳入 Web 稳定性过滤；主体内容、菜单、弹窗和页面身份变化仍会阻止就绪。相同 UA 和通用监视器预装条件下，独立 Chrome 实况探针达到就绪法定采样窗口。

第四次 Task `9d0fb2e7-64d2-48ec-aabf-c7c31b7b70df` 已通过首页就绪并保存整页图，但独立登录遇到两个关闭按钮并列的弹窗，返回 `WEB_LOGIN_OBSTRUCTION_LIMIT`。Web 清障逻辑现仅在两个按钮中存在唯一明确“关闭”文案时选择它；实际站点连续两层弹窗的无凭据浏览器探针通过。未对含糊的多按钮弹窗放宽动作授权。

最终 Task `f75ddca3-1e32-416f-985c-80f5e1b5a6f6`／Run `6b53c189-9409-48cf-b9fa-6d2e09f89608` 已达到终态 `failed`。首页导航成功，保存 10 个 Capture，包含一份成功的 `web_full_page_supplemental`：PNG 文件实际存在，1920×1080、958835 字节。该页本身只有一个视口高，因此“整页截图”不必高于 1080px。没有进入任何菜单、详情、广告或引导页，也没有达到最低采集见证。首页实际呈现短视频信息流：左侧有“首页”及分类导航，同时主体有单个视频播放器和重复卡片。模型提议 `video_detail`（置信度 0.55，需复核），首页规则以 `single_player_conflicts_with_home` 排除，详情规则又以 `repeated_cards_conflict_with_detail` 排除，最终 `unknown`／`WEB_HOME_PAGE_TYPE_UNCLASSIFIED`；主线要求首页为 `home` 才继续菜单发现。这是短视频流首页的页型规则缺口，不能把 0 个菜单归因于 10 个菜单上限。终态另有 `WEB_SEALED_CANDIDATE_STALE` 错误，需单独排查，不应掩盖首页页型根因。

独立登录分支已在清障后打开头像，并保存 2 张截图与 1 份 DOM，三份文件均存在，且包含再次打开头像后的账户界面。截图显示个人中心、账户昵称及积分区域；DOM 还包含个人资料链接和退出登录入口。不过自动认证复核返回 `account_auth_unverified`，最终登录状态为 `incomplete`／`WEB_LOGIN_ACCOUNT_UI_UNVERIFIED`，故本轮不能按程序判为登录成功，也未继续钱包／充值导航。可见昵称带站点前缀，而当前通用 `account_auth_state` 只接受与填表标识符完全相同、位于页首的标识符，且把隐藏的退出入口排除；这与现场证据相符，是待验证的识别缺口，不等于站点认证失败。另有 10 个未知跨域请求被登录分支拦截；未放开未知认证源，也未扩展白名单。该分支没有让原会话继续使用登录态。

九站选定终态任务合计 790 个 Capture、102 份成功的整页补充 PNG，文件均存在；99 张高于 1080px，另 3 张因页面高度仅一屏而为 1920×1080。四站登录有 Cookie 变化且通过账户复核；chigua、dys18 均有账户截图但本轮复核未确认；HL365 因瞬时 TLS 验证中止，huangguoai 与 hifans1 未进入成功的登录分支。全部九站的 Task 最终状态均为 `failed`，不能称作全链路验收通过。八站中的六站达到 10 个菜单；huangguoai、hifans1 和 dys18 均为 0。原八站与 dys18 最终轮使用不同代码提交，上述数量是顺序实况结果，不是同一提交下的横向 A/B 对比。

## 结论与待跟进

无头 Chromium 的 UA 修复和 Web 专项回归已通过；九站业务探索未全量通过。下一轮应优先针对 dys18 的“分类导航 + 单播放器”首页建立受证据约束的页型判定与回归，保留真实详情页的冲突保护；再用已保存的个人中心 DOM 验证通用账户复核是否能识别带前缀昵称、可见账户指标和隐藏退出入口的组合，避免仅凭截图宣布登录成功。随后复测 hifans1 的 `/login` 登录门、heiliao 的同页型波动、HL365 的瞬时 TLS 失败和 91porna 的详情弹窗，并将九站置于同一最终提交重新比较。现有菜单额度 10 保持不变，跨域阻断和 App/H5 路径也未改动。
