## 1. 最终结论

本轮严格按用户原始请求体重新提交 8 个 `scan_mode=full` H5 V2 任务，只替换 `target.url`。登录使用 `admin` 获取的 token 只保存在 PowerShell 进程内，未写入文件或输出。Docker 全程只使用 `--no-build --force-recreate` 重建 API/worker，没有 build；API 与 worker 使用的镜像 ID 始终为 `sha256:08f3a602d0210f378e9e75666513bafdc12939353f8cdf3aa5756af810bd2bbb`。

修复验证得到以下结论：

- profile 专属信任边界生效。修复后共执行 13 条 `activity/settings/payment` 候选，13 条的可信 requested-source Capture 都是 `profile`，非 profile 来源为 0。
- `activity/payment/settings` 各有 1 条从真实 `/mine` profile 页面成功进入对应目标页，且结果 Capture 实际识别为目标类型；三类有效链路全部验证成功。
- 修复前从 home/video_list 伪造 activity、从 home 误入 payment 的路径均未再出现。任务 5 修复后只观察到 startup_ad/home，没有再把 `/mine/vip-center` 计为合法 payment。
- 修复后主批次产生 79 个证据 Capture，其中 76 个有页面检测结果；5 个站点完成非零步探索，3 个站点在入口连接被拒绝时零步结束。
- 修复后主批次按实际 Capture 联合观察到用户指定 13 类中的 11 类，缺 `line_loading` 和 `ranking`，为 `11/13 = 84.6%`。`line_loading` 在首轮已由任务 3、7 实际观察；跨首轮与修复验证合并为 `12/13 = 92.3%`，唯一缺失 `ranking`。
- 当前页型目录 `2026-08-25.v12` 不含 `ranking`，但包含额外的 `post_publish/guide_page`。按用户目标与现行目录交集计算，修复后单轮为 `11/12 = 91.7%`，跨两轮为 `12/12 = 100%`。不得为凑齐 13 类伪造 ranking。
- pgvector 确实接入并在页面检测中被调用，但本轮有效决策仍由 static 别名主导：633 次 exact lookup、633 次 vector lookup，static 命中 308，exact/vector 命中均为 0，仓储降级为 0。
- 所有主 run 最终仍是 `review/failed`，没有干净成功的完整探索 run。当前主要剩余问题是 completion gate/Frontier 收口语义、startup_ad 残留、目标站临时拒绝连接、重复 profile 局部重试，以及向量 0 命中。

## 9. 目标拒绝连接与错误分类修复

### 9.1 根因探针

worker 容器内的 Chromium 启停探针成功；`/dev/shm` 空闲 64 MiB，容器内存和磁盘充足。对以下三个 URL 的最小 Playwright `goto` 均得到真实 `net::ERR_CONNECTION_REFUSED`：

- `https://cp14.cipiarot.cc/`
- `https://p1.51pj1.com/`
- `https://p1.51pj1.com/minegoldcenterpage`

因此这是目标端当前拒绝连接，不是 Chromium 无法启动、容器资源耗尽或 worker 并发争用。

### 9.2 平台修复

原实现把上述 Playwright `Error` 统一映射为 `SURFACE_DRIVER_FAILED`。现已只对“真实 Playwright Error + 顶层 Page.goto + ERR_CONNECTION_REFUSED”映射为：

- error code：`TARGET_CONNECTION_REFUSED`
- retryable：false
- public message：`目标站点拒绝连接`
- state summary：只保留 `cause_type=Error` 与 `navigation_error=ERR_CONNECTION_REFUSED`
- 不回显目标 URL、路径或查询参数

一般驱动异常仍为 `SURFACE_DRIVER_FAILED`，Playwright TimeoutError 仍为可重试 `ACTION_TIMED_OUT`。

## 10. 本轮代码修复

### 10.1 profile 专属信任边界

- 页面检测最终候选过滤：非 profile 的 activity/settings/payment 候选全部删除。
- activity/settings/payment 只接受服务端结构能力，不接受普通文字、SVG symbol/data-name 或纯视觉猜测。
- Observation 再次验签来源页型与能力参数。
- Working Memory 比较实际落点页型，预期不一致写入 `EXPECTED_PAGE_TYPE_NOT_REACHED`。

### 10.2 startup_ad

- 支持唯一、可见、文本精确为“跳过”的全局 `.count-down`。
- 检测端签发 DOM 指纹和 `startup_ad_dismissal` 能力，Snapshot/Resolver/Browser 使用同一合同。
- 点击后验证控件消失；没有副作用时不得误报关闭成功。

真实效果是“部分改善”：任务 1 找到并点击了 count-down，但出现一次 `STARTUP_AD_DISMISSAL_NOT_OBSERVED`，随后通用弹窗关闭进入首页；任务 6 仍因找不到可信跳过控件停在 startup_ad。

### 10.3 目标网络错误分类

- 将 `Page.goto: net::ERR_CONNECTION_REFUSED` 从浏览器驱动故障中分离，映射为非重试 `TARGET_CONNECTION_REFUSED`。
- 公共错误继续脱敏，不泄漏 URL。

### 10.4 规则文档

可复用约束已同步更新 `docs/专项能力与高频回归规则.md`，包括 profile 来源、服务端能力、实际落点、count-down 合同、向量审计口径和目标拒绝连接分类。
