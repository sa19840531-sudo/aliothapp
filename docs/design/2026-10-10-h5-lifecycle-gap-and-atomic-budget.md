## 已确认的实际故障与复现边界

### 补采截止遗留空 Action

JHA-128 主 Run `d0e6b471-3827-4ebd-952b-54a92e0c6d8a` 的 Action
`action-execution:e8a4203773b2dc56fd488f1ce6380791e42a865411150c6abc7d84b69bc212b9`
在 17:32:42 建立计划，Probe 截止为 17:32:48.873973；动作前采集超时后 Probe 已失败，Action 却仍为 planned，未开始、没有来源或结果 Capture，也没有动作绑定 Capture。此空账本一直影响关闭排空，直到 18:24 的终态清理。

真实记录证明了生命周期不一致，不足以单独证明当时究竟是二次取消还是补偿围栏失败。回归分别复现“前采集超时、补偿又被取消”“计划已提交但等待返回被取消”“租约围栏拒绝补偿”，不能把一种推测写成唯一现场原因。

修复使用既有账本状态转换：H5 中断时重读本 Action 的持久化状态，在释放命令许可前等待有界补偿结束；未开始与已开始、证据未落库分别保留不同失败事实。租约冲突仍拒绝，并留下日志，不强改成功。

进程中断留下的空计划另由现有逐项排空仓储结算，但必须同时证明：H5 同 Task/Run/Epoch/Session、绑定的 Web Probe 已过截止且终止、Probe 与 Session 无活动许可、Action 未开始且所有 Capture 关联为空。已有 Capture、执行中、未到期、活动租约或错误 Run 均不结算。

### 调用消费与无收益补采

本轮诊断读取的 031 物理调用为 220 次（识别 117、Judge 69、探索 34）；128 为 201 次（识别 110、Judge 60、探索 31）。这些是当前批次旧实现的实际流水，不是修复后节省效果。

此前同缺口比较把采集角色、文档时钟和无关制品纳入整体内容指纹；即使合同所需内容没变，也可能无法命中收敛。另外，成功完成的只读 Probe 即使没有增加证据，也没有进入原 blocked/no_progress 历史证明集合。两项都不能靠更高调用预算解决。

## 本次实现

### 同缺口收敛

- 比较范围仍是同 Task/Run/Epoch/Session、已确认稳定业务对象与状态、同规则合同和同缺口要求。
- 只比较合同要求的全部 PASS 制品校验和、大小和内容元数据；缺制品或缺摘要直接拒绝。仅去除文档时钟；遮挡、认证、可见性等仍参与比较。
- 只有不含角色、时序、显式交互要求的只读逻辑等价目标，才忽略本次采集角色差异。动态内容或截图真实变化仍不收敛，不按 URL 或页型粗缓存。
- 除既有 blocked/no_progress 外，允许引用真正 succeeded 的 Probe，但须完成 Action、真实结果 Capture、probe_result_replay 角色和已附加 Supplement/Manifest 全部绑定。原目标、真实结果和当前目标内容均一致，且存在两次不同结果帧，才证明无新增证据。
- 收敛只停止已证明无收益的再次补采，保留证据不足与历史引用，不写通过、失败或不适用的规则结论。

### 兼容只读取证共享

- 仍限定同一原始目标 Capture 和相同合同要求的制品集合、展示状态、来源等级、依赖与恢复约束。
- 同一批兼容请求分别缺 dom/visible_text/ui_snapshot 时，不再仅因缺失说明中的制品名称不同而拆批；缺失项必须属于请求实际制品集合。
- 每条请求独立 Restoration、等价检查、Probe、Supplement、InputSet 和 Judge；条件性目标、时序、滚动点击与状态漂移继续走原路径。

### 新业务页型调度

仅在当前可信来源存在低风险、尚未覆盖的真实业务链接、profile 本地动作或既有结构化详情入口时，先尝试该入口，再执行 nested_return。必要清障、详情取证、详情滚动和支付横向取证优先级不变；旧来源恢复、风险、深度、采样和页数边界不变。

预计 payment/settings/video_detail 不是已到达页型。实际识别、播放器与媒体取证、规则合格输入和正式 Publication 仍须独立验证；Probe 不升级普通采集证据。

### 物理请求原子准入

- 新预算行以 Task/Epoch 为键，绑定原主 Run；初始已用量取同 Task 全部审计流水。调用上限和绝对截止只允许收紧，计数只允许增加，重复初始化不刷新。
- 模型请求每次发送前原子递增，探索、识别、独立 Judge 和关闭后 Snapshot 补采共同使用；SDK 每次物理重试同样占一次。跨消费者争抢最后两次额度时，最多两次获准。
- 未获准请求不发送，不创建虚假 Token/CNY 用量。已获准却在发送前崩溃时，预留不回收，宁可少一次也不放行超过上限的请求。
- H5 Judge 保留 SDK 包装里的预算拒绝，停止把它当普通可重试异常。证据不足和待复核事实不被升级为规则结论；App/Web 重试行为不变。
- 探索已有终止原因而关闭排空又失败时，报告同时保留两者，错误与复核状态保持不变。
