# H5 同缺口收敛与兼容取证共享

## 范围与事实

- 仅优化 H5 通用补证，不改变任务、探索图、规则质检、补证、等价门禁的架构。
- 当前批次 `20261010-104542` 不修改、不重启、不重跑；API/Worker/监控原进程保留。预算、风险、Publication 和 Completion Gate 不放宽，无数据库迁移。
- 只读检查主 Run 的真实请求：031 有45条，128有53条。按本次严格只读取证合同识别，031无共享候选；128有3条候选，其中 alioth_2/alioth_4 的同目标缺文案请求属于一组。这个结果只证明兼容判定能命中真实案例，不是节省调用或业务验收结果。
- 原缺口自由文本带规则正文，不同规则的取证目标可能相同，但规则不能合并。严格匹配已有“缺来源 …(non_empty)”生成格式，只去除已核对为规则正文的 region，其他约束完整比较；不按产品、站点或固定页型适配。

## 同缺口收敛

1. 领取请求后只读查同 Run/Epoch 的历史；旧请求必须为 blocked/no_progress 导致的证据不可满足，不能复用恢复失败、网络错误、超时或预算耗尽。
2. 比较原目标、旧 Probe 实际来源、当前目标的全部相关 PASS 制品校验和、角色及展示元数据。Task/Session、已确认业务对象、稳定状态、规则合同与规则集版本、requirement_hash 均须相同。缺校验和、加载态、遮挡、外跳、身份不确定或内容变化立即退出收敛。
3. 至少两次不同实际来源帧的独立无收益补证才收敛，保留两条请求引用。同一共享帧复制两次不算两次尝试。请求仍是 UNFULFILLABLE/证据不足，不生成规则通过或失败，不宣称条件已满足。
4. 新版本、新对象、新证据、时序或显式交互需求继续补证；没有充分历史证据沿用原执行路径。

## 兼容只读取证

1. 首条请求正常恢复、识别及等价评估。仅 original_surface_pin、稳定且已确认的基础页、无遮挡和权限锁定才允许保留本批新观察。
2. 读取完全兼容的同目标兄弟请求，精确领取。每条请求独立通过原 Restoration/Gate，发布自己的 Probe；共享真实恢复观察，不重复 OBSERVE/识别。每次领取前核对现场与命令序号，退出批次销毁共享引用。
3. 沿用原动作预算保守预留每个 Probe 的回退动作；扣减已用批次时长，固定批次截止，不新增预算、续期或后台轮询。
4. 确定性缺制品目标在稳定现场直接使用原只读 OBSERVE 合同，不让模型重复选择已经明确的取证动作。弹窗、点击、滚动、条件性或时序补证仍走原候选与交互门禁。
5. 首条 Probe 正常执行真实 OBSERVE、前后采集和识别。兄弟项只在同 Run/Epoch/Session、同恢复来源、已在原动作前派发、现场未推进、前后均稳定同业务对象且有 PASS 清单时引用该动作的真实结果。
6. 每条请求单独记录无动作完成及 `h5_shared_evidence:<origin_work_id>` 引用。挂接前再次独立校验原动作、自己请求的恢复证明及前后 Manifest，独立 Supplement/InputSet/Judge；不复制规则结论或改写 Action Trace 归属。崩溃后补挂仍重新核验。
7. 若首项失败或产生了不兼容后态，尚无自己动作记录的旧来源项原子标记 superseded、请求回队独立恢复。只允许自己当前租约/版本、有效 Task/Epoch 和无在途动作时执行，不增加 max_attempts 或清零 attempt_count；下次恢复不复用已被该原因废弃的旧 Probe 证明。

## 防回退边界

- 不缓存 URL/页型或仅逻辑状态指纹，不把不同作品、弹窗层或条件当作同一证据。
- 不共享关闭、滚动、点击、前后时序、广告失败或下架条件；这些请求仍须真实取证。条件性同缺口只有两次独立且完全相同的证据及失败事实才停止无收益重复，保留缺证。
- 共享候选不能跨 Run、Epoch、Session、恢复来源或原目标，不能复用不同规则版本的失败事实。
- 新业务页型、payment/settings 交接、多层弹窗能力签发、Rule Judge、风险、展示条件和正式报告门禁原逻辑不变。
- 关闭态 Snapshot 重放不启用本次派发共享；App/Web 默认领取和恢复行为不变，公共仓储扩展均有 H5 条件。
