## 已确认缺口与处理

| 已确认缺口 | 本阶段处理 | 保留边界 |
| --- | --- | --- |
| V1 只包含顺序步骤，无法独立冻结业务检查点 | 新增 `journey-dsl.v2`，冻结进入条件、预期事实、证据角色/制品/数量、依赖、退出条件、恢复与副作用策略 | 事实 JSON 尚无生产判定解释器，不按字段名直接判通过 |
| 每个 Task 只有一份执行计划 | `journey-execution-plan.v2` 按 Task/Run/Definition/Scenario 冻结版本、参数与规则合同哈希 | 原 V1 入口仍只读旧任务级计划，不选择任意新计划冒充兼容 |
| 有限校验不能防止内容在原计划 ID 下漂移 | V2 ID 对完整计划内容寻址；解析核验 ID；仓储核验检查点与已发布合同相同 | 尚不等于动作和实际证据内容绑定 |
| 并发冻结可能覆盖或串属 | 数据库唯一索引、Run/Task 复合外键、仓储真实归属校验；相同内容幂等，不同内容拒绝 | 不表示补证/主探索正式执行接线已完成 |
| 顺序 Runner 可误接检查点空步骤 | 在开始持久化或发动作前明确拒绝检查点计划 | 后续需要真正观察、规划和执行端口，不降级成硬编码点击 |

合同不包含 CSS/XPath、Driver、页面或租约句柄，不规定某个站点的固定按钮/路线。依赖须指向先声明检查点；未知依赖、自依赖、循环、重复角色、空义务、未知制品、非法副作用和恢复策略均拒绝。证据数量只是义务，尚不能核验独立帧或自动去重。
