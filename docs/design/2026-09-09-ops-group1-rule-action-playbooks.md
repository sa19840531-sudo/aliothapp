# 运营1组 8 条规则的动作方案（按内容类型细写）

日期：2026-09-09 立，2026-09-10 按运营1组表格批注扩写。范围：`alioth_ops_1`～`alioth_ops_11`（种子 `docs/data/alioth_first_ruleset_qc_rule_seed.csv`，来源运营1组巡检表）。
这份文档把每条规则拆成「进什么页面、做什么动作、看什么、留什么证据、什么时候停」，同一条规则不同内容类型的操作不一样时分开写。判定口径（通过／不过／不适用／证据不足／人工）沿用种子里的 `llm_checks`，这里只补动作和证据。

怎么读每一条：

- **场景**：同一条规则下操作逻辑不同的情况，比如播放里的长视频和漫画。
- **动作脚本**：探索侧要做的事，按顺序写；「观察」是指等一会儿再截图，不是点。
- **留证**：判定要看的材料。`media_state`、`har`、`action_trace` 这些名字对应规则合同里的附件类型。
- **停止条件**：做到哪一步为止，越过就是副作用或风险。
- **不适用／证据不足／人工**：不能判通过也不能判不过时怎么记。
- **接入点**：这条动作现在缺什么，落在谁那边（探索侧＝天枢 H5／星语 App／观星调度与风控；规则合同与采集附件＝立川）。

两条总原则贯穿全部规则：

1. 只按当前页面真实看到的东西判，没做的动作不猜结果；动作没做就记证据不足并留补采缺口，不判不过。
2. 有副作用的动作（下单、付款、发布、关注、安装应用）自动化一律不做；需要的那条走人工，其余规则的动作都是「点进去看一眼」。

## ops_3 视频与短视频播放

适用页面：视频详情页（video_detail）、内容详情页（content_detail）。2026-09-10 按表格批注「可以拆分成多个具体的质检规范」拆开：本条只管长视频与短视频，分集内容见 ops_9、漫画与图文阅读见 ops_10。三条都要先认内容类型，不是本类就记不适用——否则同一个播放页会被三条规则各判一次不过。

### 场景 A：长视频（电影、完整剧集，单个播放器页）

- 动作脚本：
  1. 从列表进入详情页，等待页面稳定（播放器区域出现）。
  2. 如果有贴片广告先等广告结束或按规则允许跳过（贴片本身由 alioth_25／26 管）。
  3. 播放器没有自动播放时点一次中央播放按钮或「播放」；有自动播放就不点。
  4. 观察三次：开始播放后约 3 秒、8 秒、15 秒各截一帧，同时采媒体状态。
  5. 不拖进度条（那是 alioth_44 的动作），不切清晰度，不全屏。
- 留证：三帧截图、`media_state`（就绪状态、是否暂停、播放进度、是否静音、错误码）、媒体文件或分片请求的结果（`har`）、控制台错误。
- 通过信号：进度在三帧之间往前走，画面有变化，不是全黑，分片请求没有连续失败，没有「播放失败」类提示。
- 停止条件：观察到第三帧即停；出现「购买／开通会员后观看」提示就停，不点购买。
- 不适用／证据不足／人工：付费内容没有登录态或没买 → 记「需要权限」不判不过（口径同登录依赖规则）；只采到一帧或媒体状态没采到 → 证据不足，补采方式「等价即可」（同一个内容的播放页再看一次）。
- 接入点：媒体状态现在是可选附件，规则合同要把 `media_state` 改成必需，采集侧才会采；「开始播放后多帧观察」这个动作探索侧目前没有，要加「进播放页后停留观察」的候选动作（天枢）。

### 场景 B：短视频（上下滑的信息流）

2026-09-10 改判：原来只看当前一条，现在要看滑到下一条——短视频的核心风险就在切条。

- 动作脚本：
  1. 进入短视频流，第一条通常自动播放，不点。
  2. 对第一条观察两帧（约 3 秒、8 秒）。
  3. 上滑到第二条，等它开始播放，再观察两帧。
  4. 两条之后停，不点赞、不评论、不关注。
- 留证：每条两帧截图、每条的媒体状态、滑动动作记录（`action_trace`）。
- 通过信号：第一条能播；上滑后第二条自动起播、第一条停止播放。
- 不适用／证据不足／人工：付费内容 → 转人工、原因写「付费内容」；只看了一条、拿不到上滑记录 → 证据不足，补采「等价即可」；上滑后下一条播不了、或上一条没停继续出声 → 不过，写明是第几条。
- 接入点：上滑到下一条这个动作探索侧现在没有，要加（天枢 H5、星语 App）。

## ops_9 短剧与动漫分集播放（2026-09-10 新增）

适用页面：视频详情页（video_detail）、内容详情页（content_detail）。按表格批注「新增规则：短剧播放检测」从 ops_3 拆出；动漫按分集形态并入本条。分集内容的风险在切集，本条要判第 2 集切得过去、且内容真的换了。

### 场景 A：短剧、动漫（分集播放）

- 动作脚本：
  1. 进入剧集详情页，找到选集区域（第 1 集、第 2 集……）。
  2. 播放第 1 集，起播后约 3 秒、8 秒各截一帧，同时采媒体状态。
  3. 点第 2 集，等切换完成，确认播放器标题或集数标记真的换成第 2 集，再观察两帧。
  4. 两集之后停；遇到「第 N 集需要会员」的集数不点，不追更、不收藏。
- 留证：两集各两帧、媒体状态、切集动作记录（`action_trace`）。
- 通过信号：两集都能起播，且切集后标题或集数确实变了。
- 不适用／证据不足／人工：页面没有选集或分集结构 → 不适用（交 ops_3 或 ops_10 判）；只有第 1 集免费其余付费 → 只判第 1 集，付费集记「付费内容」，全部集都付费 → 转人工；切集没反应、或切了内容没变 → 不过；只采到第 1 集、没有切集动作记录 → 证据不足，补采「等价即可」。
- 接入点：切集点击探索侧现在没有，要加（天枢 H5、星语 App）。

## ops_10 漫画与图文阅读（2026-09-10 新增）

适用页面：内容详情页（content_detail）。按表格批注「新增规则：漫画播放检测」从 ops_3 拆出。阅读页没有媒体元素，本条不要求媒体状态附件——合在 ops_3 里时，漫画页会因为采不到媒体状态一律记证据不足。

### 场景 A：漫画阅读页（图片翻页）

- 动作脚本：
  1. 进入阅读页，等待首屏图片加载完。
  2. 向下滚两屏（或点「下一页」两次，看产品是滚动式还是翻页式）。
  3. 每次滚动或翻页后等 2 秒再截图，同时看图片元素是否有真实尺寸。
  4. 翻到章节末尾看「下一章」入口存在即可，不进下一章。
- 留证：首屏和两次翻页后的截图、图片请求结果、页面结构里的图片尺寸、翻页动作记录（`action_trace`）。
- 通过信号：图片按顺序加载出来，没有破图、没有空白占位一直不消失，能翻到下一页。
- 不适用／证据不足／人工：页面有视频播放器 → 不适用（交 ops_3 或 ops_9 判）；章节需要购买 → 转人工、原因写「付费内容」；图片懒加载没触发就截图 → 证据不足，补采「等价即可」。

### 场景 B：图文、小说阅读页

- 动作脚本：进入正文，向下滚一屏，看正文是否连续、是否有下一页或下一章。
- 通过信号：正文文字加载完整、能继续往下读。
- 其余同场景 A。
- 接入点：「滚动后等待再截图」探索侧有滚动动作但没有「等图片加载」的等待，要补（天枢）。

## ops_4 充值入口进入充值页

适用页面：支付页、个人中心、内容详情、视频详情。入口不同，动作一样，但触发位置不同。

### 场景 A：个人中心里的「充值 / 会员中心 / 金币」入口

- 动作脚本：进入个人中心 → 点该入口 → 等待跳转完成 → 截一帧 → 停。
- 通过信号：到达的页面能看到至少一个充值档位、对应价格、至少一种支付方式。
- 停止条件：到充值页为止，不选档位、不点确认。

### 场景 B：详情页付费提示（「开通 VIP 观看」「购买本片」）

- 动作脚本：在详情页看到付费提示 → 点提示按钮 → 等待 → 截图 → 停。
- 注意：这里点的是「去开通」，不是「确认购买」；提示弹层里如果直接是支付确认按钮，不点，记证据不足转 ops_5 的人工流程。

### 场景 C：金币不足弹窗里的「去充值」

- 动作脚本：触发条件是看付费内容时弹出「金币不足」，点「去充值」→ 等待 → 截图 → 停。
- 注意：弹窗本身出现不算不过；弹窗点了没反应才算。

### 场景 D：首页浮标、横幅里的充值活动入口

- 动作脚本：点浮标或横幅 → 落到活动页还是充值页都记下 → 活动页里再找充值按钮点一次 → 截图 → 停。
- 通过信号同 A。

### 场景 E：充值页上的多种会员卡（2026-09-10 新增）

按表格批注「多种会员卡销售时，每一种都要进行操作」。这一步只选不付，不产生订单，所以直接做。

- 动作脚本：到达充值页后，把页面上每一种会员卡或充值档位（月卡、季卡、年卡、终身卡……）逐个点一遍，每点一张截一帧，看能否选中、选中后价格与支付方式是否正常展示。
- 停止条件：点完所有档位即停，绝不点「确认支付／立即支付」。
- 通过信号：每一种都能选中并展示对应价格。
- 不适用／证据不足／人工：只有一档 → 照常判那一档；只点了其中几种 → 已点的照常判，未点的记证据不足，不据此判不过。
- 接入点：逐档点击探索侧现在没有，要加（天枢 H5 入口候选、星语 App）。

共同项：

- 留证：点击前一帧、点击后一帧、逐档点击各一帧、点击动作记录（`action_trace` 已改为必需附件）。
- 不适用／证据不足／人工：入口要登录才显示 → 记「需要权限」；页面看得见入口但探索没点 → 证据不足，补采「等价即可」（回到同类页面点一次）。
- 接入点：这是现在最卡的一条。风控词表把「充值」「购买」列为资金动作词，纯导航入口要靠导航上下文放行，真跑里探索看见入口没点。方案：把「点到充值页为止」的入口点击列为允许导航，「确认支付／立即支付／去支付／付款」继续拦（观星风控＋天枢入口候选）。

## ops_5 充值拉起支付（只到拉起，不付款）

适用页面：支付页。这条会真实创建订单：09-09 拍板自动执行到唤起收银台为止，不付款，每次留一笔未支付订单。

档位口径（2026-09-10 拍板）：表格批注要求「每一种会员卡都要操作」，但拉单有副作用——四张卡各拉一次，一次质检就留四笔垃圾订单。所以先只拉最便宜的一档，档位数写成规则阈值 `order_pull_card_count`（当前为 1）；产品方确认订单与测试账号口径后调大该阈值即可放开到逐档，规则文本与动作脚本都已按可逐档写好。

### 场景 A：H5 微信支付

1. 用测试账号登录（这条规则声明需要登录态）。
2. 进入充值页，选最小档位。
3. 选「微信支付」，点确认。
4. 看到以下任一即停：跳到收银台页面、出现支付二维码、唤起微信。
5. 截图、记录动作、记录下单请求是否成功（没有 4xx／5xx）。
6. 不输入支付密码，不扫码付款；返回产品。

### 场景 B：H5 支付宝

同 A，第 3 步选「支付宝」，第 4 步常见是跳到支付宝收银台页或出现二维码。

### 场景 C：App 内支付（安卓）

同 A，第 4 步常见是唤起微信／支付宝应用（系统切换）；设备没装对应应用时看到「未安装」提示也算拉起动作已发出，但记为需要人工确认。

- 留证：选档位、选支付方式、点确认三步各一帧，收银台或二维码一帧，动作记录，下单请求结果。
- 不适用／证据不足／人工：没有确认支付的动作记录 → 证据不足；本条补采首选转人工，备选「必须原状态」（同账号同订单上下文再来一次）。
- 停止条件：拉起即停，任何情况下不完成付款。
- 接入点：测试账号（谁提供、余额、能否重复下单）；订单副作用的审批口径；人工操作后动作记录怎么进系统（工作台「人工补证」入口目前没有，需要拍板要不要做）。

## ops_11 拉单金额一致性（2026-09-10 新增）

适用页面：支付页。按表格批注「同步检查页面标记金额与实际拉单金额是否一致」新起。ops_5 管拉不拉得起来，本条管拉起的金额对不对。**材料取自 ops_5 那一次拉单，本条不额外下单。**

### 动作脚本

1. 在充值页选中某一档会员卡或充值档位后，先记下它在页面上标的金额（有优惠价时连原价、优惠说明一起记）。
2. 沿用 ops_5 的拉单动作拉起收银台。
3. 记下收银台上显示的金额，以及下单请求里的金额。
4. 三者比对，比完即停，不输支付密码、不扫码、不完成付款。

- 留证：选中档位那一帧（页面标价可读）、收银台或二维码那一帧（实际金额可读）、下单请求与响应（`har`）、页面文字（`visible_text`）、动作记录。
- 通过信号：页面标价、收银台金额、下单请求金额三者一致。
- 不适用／证据不足／人工：有优惠导致差额、且页面写清了优惠 → 通过；页面没有任何优惠说明却有差额 → 不过；有差额但优惠说明看不清、算不出 → 转人工、原因写「优惠口径不明」；三者缺任一 → 证据不足，随 ops_5 的人工流程一起补。
- 停止条件：同 ops_5，拉起即停。
- 接入点：**只靠截图判不了金额**——页面文字与网络日志已在本条改成必需附件，采集侧要保证充值页和收银台两处都采到（合同已改，采集侧看到必需才会采）；下单请求里的金额字段名各产品不一样，判定按网络日志里的金额与页面标价比对，拿不到就记证据不足，不猜。

## ops_6 分享链接有效性

适用页面：内容详情、视频详情、个人中心、活动页。分享链接从哪拿是关键。

### 场景 A：详情页分享按钮 → 分享弹层

1. 点分享按钮，弹层出现（复制链接／二维码／海报）。
2. 拿链接：优先读弹层里的链接文本；只有「复制链接」按钮时点它再读剪贴板；只有二维码时解析二维码。
3. 关闭弹层，回到详情页。
4. 在独立的浏览器环境（没有产品登录态、没有 cookie）打开该链接。
5. 等页面稳定后截图；找到「下载 App」或「打开产品」入口，点一次看是否有响应（跳应用商店、下载页或唤起产品），不安装。

### 场景 B：个人中心「分享推广 / 邀请好友」页

1. 进推广页，页面本身展示推广链接或二维码。
2. 拿链接同上，其余同 A。

### 场景 C：海报分享

1. 生成海报，海报里通常带二维码，解析二维码得到链接，其余同 A。

- 留证：拿到的链接文本、分享弹层截图、独立环境里落地页截图、入口点击前后两帧、落地页请求结果。
- 通过信号：落地页正常返回，内容与分享来源一致（同产品名称；分享具体内容时能看到对应标题或封面），下载／打开入口有响应。
- 不适用／证据不足／人工：页面没有分享功能 → 不适用；拿到链接但没在独立环境打开 → 证据不足，补采「重新观察」。
- 停止条件：落地页看完即停，不安装、不注册。
- 接入点：读剪贴板和解析二维码探索侧没有；独立浏览器环境打开外部页面走天枢已做的外跳隔离（只留证不计覆盖）；App 侧分享弹层是系统分享面板，要星语看能不能拿到链接。

## ops_7 官方群入口跳转

适用页面：首页、个人中心、设置、活动页。入口位置不同，结果分三种。

### 入口位置

- 首页浮标、公告横幅里的「官方群」「加群」。
- 个人中心或设置里的「官方群」「联系我们」。
- 落地页（下载页）上的群入口。

### 动作脚本

1. 点入口。
2. 按结果分三种处理：
   - 外跳到聊天应用（Telegram、Potato 等）：等系统切换或浏览器弹出「打开应用」提示，截图，不在聊天应用里做任何操作，回到产品。
   - 页面上展示群链接或二维码：记下链接文本，解析二维码；对链接做一次访问看是否正常返回（不加群）。
