## 已确认根因与修复

1. 普通候选编译丢弃原InputSet；已有绑定还被统一送入Web序列绑定器。现在从已有生产者执行精确查询已核验原输入，透传至普通发布及Publication准备命令。缺原输入、合同不一致、最新质量降级不补造绑定。新Work首次绑定且幂等；历史成员不改写。
2. Handoff/Judge把页面InputSet按Web序列解释。现在H5原页面经独立只读端口认证Task、Work、Attempt、租约、当前周期及输入哈希，读取精确Manifest；读取前后重新授权。Web序列原合同不放松。页面展示、加载态和视频就绪预检继续执行。
3. 正式结果同步未保存原输入，旧Attempt或外来InputSet也能关联成员。现在同时核对消费标记、原输入哈希、Manifest、实际附件、规则及包归属，不覆盖外来执行指针。观察包幂等身份包含当前原输入消费身份；合法待复核保留待复核。
4. 旧缺口收口把冲突的旧已判执行借给当前成员。现在关闭当前成员为`evidence_insufficient`，不关联旧执行，原执行内容不变，记录`H5_RESULT_INPUT_CONTRACT_UNVERIFIED`及具体冲突身份。Gate保留输入合同缺口；有在途请求仍等待，不能提前结算。
5. 补采封存SQL原先一律跳过已有InputSet成员。现在只对H5原页面绑定允许另封补采，原成员绑定保持不可改写；Web序列仍使用自己的封存路径。复杂多角色补采是否完整消费仍需更大范围验证，不用单页正例代替。
6. Web收口缺显式任务分区时，新冻结目录被错误填成`legacy-task-config`；合集分区继而被快照拒绝。现在继承Run实际冻结的目录版本及哈希，历史无冻结目录不借当前目录。
7. Web v4正式报告漏掉生命周期、未知Capture及补充证据的顶层投影，真实重试走到报告绑定又被拒绝。现在从封存分区精确投影，缺字段不编造空集合，正式报告校验保持严格。
8. Web合集菜单终态只查v4标签及页型，没有复核冻结目录，`old_catalog`负例未拒绝。现在复核Run冻结目录版本/完整正文哈希与Assessment、Capture审计两份投影；旧版本、错哈希、单边审计漂移和两边一致但与冻结源不符均拒绝。
