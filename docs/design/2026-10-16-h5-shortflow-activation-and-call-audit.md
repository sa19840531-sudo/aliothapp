## 本轮实现

### 显式短流程启用

`POST /api/v2/tasks` 新增可选 `h5_shortflows`，默认空列表保持旧路径。
每项只接受 `definition_id`、`version`、`content_hash`、`scenario_key`、`rule_ids`、
`workflow_skill`，不能夹带定位器、脚本、预算或自报规则哈希。

- 只用于 H5 V2 完整质检；其他平台和仅探索入口拒绝，不静默丢弃。
- 提交事务读取已发布 V2 定义和服务端冻结的规则清单；明确规则须适用且已登记为
  `journey/journey_observation` 输入。普通页面规则不能偷换成流程规则。
- 版本、完整定义、真实规则哈希和所选 Skill 内容冻结到任务。
  Skill 哈希同时包含通用探索边界，不能只锁专项正文而漏掉公共边界漂移。
- 主 Run 组合根在创建浏览器运行时前验证权威任务配置并原子冻结所有 Run Plan。
  重复投递复用同内容；第二份计划冲突时第一份也回滚，不留下半启用状态。
- 不支持的事实、采样义务和非只读策略在模型和动作之前拒绝。
  重复流程场景或同规则跨流程绑定拒绝，避免 InputSet 选择歧义。
- 动作后反馈不能作为入口条件；缺失的原生可见性、暂停、就绪、时间和文档时间源
  保持未知，不把字段缺失转成 False/None 事实。支付退出条件同样参与 Skill 路由。
- Adaptive Runner 继续复用现有整段会话锁、租约、Coordinator、尝试账本及冻结预算。
  本轮不建立第二套执行器，也不改变已有 reserved/gap 的不重放边界。

### 播放器和支付 Workflow Skill

新增 `h5-player-workflow`、`h5-payment-workflow`。每个短流程 Agent 只挂载
`h5-explorer-workflow` 与当前专项，不默认把所有专项塞进普通探索上下文。
调用来源登记为 `h5_shortflow_agent`，具体 operation 为 Skill 名，沿用现有物理准入。

`docs/data/journey_definitions/h5_shortflows_v2.json` 提供两个可测量合同模板：
暂停后连续呈现帧观测，以及套餐只读展示反馈。模板未自动写入业务库；仍须由既有
`JourneyDefinitionService.publish` 发布不可变版本，再显式绑定已确认的流程规则。
文件不含规则 ID，不自动开启所有任务，不把模板存在等同于实际流程执行成功。

播放器仍要求原生媒体实例、时间、呈现帧和真实图像证据；无法测量的私有播放器
不伪造事实。支付模板不包含 `order_created=false`，不证明交易完成。

### 支付展示精确回执

修复 Driver 的 `h5_probe_effect` 在公开回执中丢失，进而无法用于流程判定的问题。
公开回执只保留已登记的反馈字段及 URL 哈希，不带定位器或带查询参数的原地址。

`payment_plan_selected` 必须同时满足：成功动作回执、可信反馈、只读隔离且拦截数为零、
同 URL 哈希/合法文档时间源、前后各唯一的同套餐目标、当前实际选中状态。
失败动作、布尔值冒充时间源、目标漂移、加载态、单独选中样式和缺回执都不能通过。
在来源和动作可信时，实测不选中可以为失败；缺因果证据保持不足。

检查点观察、实际动作账本、封存流程 InputSet、通用 Judge 与报告消费接通同一回执。
只对新增支付测量合同增加该字段，旧非支付合同的选择载荷不变。
缺回执的规则执行为 `evidence_insufficient`，正式报告保留缺口，不填假完成记录。

### 固定预算只读审计

`GET /api/v2/tasks/{task_id}/h5-call-audit` 使用既有对象读权限，并在仓储再次检查租户、
部门和提交者范围。只读一致事务返回同任务所有消费者 Run 的逐条用量及全部冻结预算行。

- 按 source/operation/provider/model 统计实际 `ai_calls`，包含物理重试，不拿工作行版本、
  规则条数或截图数当调用数。
- 记录调用数与有物理请求证明的调用数分列；历史缺 `physical_request` 的行保留未知计数，
  不追认成完整物理账单。逐条提供已登记的 HTTP 状态和请求结果，不传播请求路径或异常正文。
- 准入数与流水分开；准入尚无流水可能是在途或记录缺口，不能单独认定浪费。
- 排队未初始化预算显示 `not_initialized`，不是耗尽故障。
- 缺用量、缺定价、缺费用或非 CNY 不给完整总费用；保留已知 CNY 部分和缺口计数。
  准入与记录数不一致时，总 Token/费用保持未知，不把已知部分冒充完整账单。
- 不做美元换算；不变更原账本、额度或熔断作用域。
- 是否 200 次足够仍需对照真实有效证据和调用分布，本轮没有发新模型请求或原站任务。

## 验证与发布阻断

结果和失败过程放在 `docs/validation/2026-10-16-h5-shortflow-activation/`，不可混加重叠套件数量。
受控浏览器案例使用 031 保存的会员外壳，内层控件和处理器明确为重建；网络隔离且不提交支付。
PG 案例只在测试自有库验证真实动作/制品/输入/判定/报告归属，不是原站业务数据。

扩大验证有存量失败，不能宣称分支全部绿色：

- App Explorer 扩大套件出现 26 项失败；已核对受影响实现/用例与基线 HEAD 相同。
  典型用例仍使用 `dark.wwcskrpojs.ebjhyebjbl`，当前精确包名映射为 `com.hj.ttthree`，
  导致旧产品特征不再命中。其余同组用例需要单独对齐产品身份及合同，不擅自恢复包名硬编码。
- 完整任务入口套件的 Web 用例预期漏掉已有 `collection_page`；相关目录和解析实现与 HEAD 相同。
  本轮不改 Web 业务逻辑或放宽预期来掩盖该失败。
- 既有偶发 Canvas 失效、完整分支回归、业务库迁移加载、真实模型费用、当前版本长测及
  原站支付/真实视频验收仍非本轮完成项。未知规则和外部契约阻断不消账。

因此本轮后端改动可以交付审阅，但不能据此合并发布或把排期全部改为完成。
