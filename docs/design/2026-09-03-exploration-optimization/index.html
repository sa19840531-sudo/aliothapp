2. 文档边界与已确认决策

每篇保留原有第 1–14 章：决策与非目标、现状问题与收益、当前基础与改动、职责、核心机制、标准流程、异常闭环、平台差异、跨篇协作、工作台、安全、分期回滚、验收和反馈；新增第 15–19 章技术深化，依据顺延为第 20 章。 本次是文档与离线阅读工具完善，不是业务代码实施、规则启用、设备测试或上线证明。图中组件表示职责切面，可以落在现有模块内，不意味着拆出同等数量的新服务。

六项产品决定保持不变：

  1. 探索是有限度自由发现：优先必检目标和证据缺口，再按预算发现新入口。
  2. 局部 Tab、筛选和展开默认是同一页面的状态版本；实质改变业务职责、路由或返回语义时再判断是否新页面。
  3. 弹窗也是质检目标，但通常不作为业务页面节点；独立支付路由仍是页面，内联二维码仍可只是区域。
  4. 外部广告落地默认只留外跳证据，不计业务页面覆盖；源业务页和可信回源按自身事实处理。
  5. 补采按规则声明原状态、等价状态、当前新观察或人工；登录、支付等高风险场景从严，不能运行中放宽。
  6. 正式 Agent 只有有限 Shell 能力；权限由服务端与执行隔离强制保障，不靠 Skill 提示词自律。

共同术语只用于表达职责：Frontier 是候选动作队列；页面图是事实投影；树是展示或恢复视图；Capture 是一次观察；Manifest 判断证据质量；InputSet 冻结一次判断的实际输入；Gate 判断本次运行的完成条件。 这些术语不等于本文件定义了新数据库表或具体实现对象。

3. 七项分别解决什么

专项 最直接解决的问题 对整体链路的提升 不能独自保证
01 受控探索 自定义 Tool 僵硬、难组合、重复读取和无界漫游 用稳定受控能力承接灵活策略 命令成功不保证页面到达
02 页面状态图 已有 Frontier 路径/恢复事实分散、统一身份和进度投影不足 可解释去重、导航、覆盖与恢复依据 图上存在不保证现在能恢复
03 精准补采 缺证后盲找、错状态补证、重跑覆盖旧结论 缺口定位、验证式恢复和追加判断 同页或同类型不保证等价
04 精准识别 页型漂移、导航型产品误套模板、规则错配 更准确的目标理解与可审计规则范围 高置信度不证明当前层可见
05 就绪判定 截图过早、错帧、固定等待和网络误判 提高首份可用证据比例，保留真实加载失败 就绪不等于规则通过
06 精准交互 误点广告、滚后坐标过期、弹窗循环与外跳中断 可验证动作、安全关闭及有界回源 控件消失不一定是正确关闭
07 可信证据 错层、错数据、长图/DOM 失真、结论不可追溯 正式输入和最终报告可信、复核成本可控 文件质量通过不等于产品质检通过

收益目标在同一任务目标、规则、环境、账号状态和预算下验证；既比较准确性与覆盖，也比较耗时、动作数、Token 和人工成本。 本文不沿用未经实测的点击率、提速比例或节省百分比作为承诺。

4. 整体流程怎样串成闭环

冻结任务 → 受管运行面 → 入口与可见层观察 → 弹窗前态/安全处理 → 产品与页型识别 → 可信图与规则范围 → 证据和候选分流 → 有界动作 → 就绪与后置验证 → 规则判断 → 图路径补采 → 同运行收口与报告。

步骤 主责 进入与继续条件 失败如何结束或恢复
1. 冻结目标和范围 现有任务控制面 + 专项 01、04 规则、必检目标、账号、预算、设备/业务范围明确 配置冲突或缺授权先明确阻断，不启动危险动作
2. 获取运行面与能力 专项 01 租约有效，执行与观察能力经过探测 不可用明确降级，不将不可观测当零数据
3. 保存入口真实观察 专项 05、07 截图和可得结构可追溯，知道当前显示哪一层 业务底页未知可以保留，不伪造首页
4. 处理阻断层 专项 06、07 先冻结适用采集计划并保存前态，再执行允许的关闭 倒计时、无按钮、无效果、误跳、危险确认分别结算
5. 识别产品和当前页型 专项 04 基于可见内容与受信声明，允许未知和冲突 缺证不自动改为不适用，不缩小冻结必检分母
6. 更新可信图与规则范围 专项 02、04 页面身份、状态和到达证明成立；规则条件未被绕过 候选或失败仅留诊断，不新增业务覆盖
7. 分流证据与候选 专项 01、07 合法证据可封存送 Judge；菜单/链接/视觉形成候选 证据不足留缺口，候选不计已到达
8. 有界调度和动作 专项 01、06 必检、恢复、自由发现预算合理；每步重新校验目标 陈旧、越权、模糊或副作用未知时先停动作
9. 后置与外跳观察 专项 05、06、07 验证动作效果、当前层与就绪；外跳保存来源/落地/回源 回源循环共享预算，外部不扩展业务覆盖
10. 规则判断与复用 专项 04、07 + 现有 Judge 只消费封存且适用的材料；复用有具体合同和来源 fail、缺证、人工、技术失败分别保留
11. 缺口恢复与补采 专项 03，调用 01、02、05–07 双门禁、逐边验证、规则等价与时效都满足 原状态无法证明就不足/人工，不能改采新状态填旧洞
12. 收口、Gate 与释放 现有控制面 + 专项 07 停发新动作，排空或终结工作，冻结同 Run/Epoch 输入 Gate 故障单独报告，失败和取消也执行受控清理

Rule Judge 可以与探索并行消费已经封存的静态证据，但始终不直接操作设备。 需要动作结果的规则必须等待后态或合法时间序列；关闭弹窗不必等待所有静态规则判断完毕。 图、规则工作与前端投影可以异步更新，但均从同一批不可变事实追溯，不能各自成为新权威。

UI 动作不具备数据库式原子回滚。动作后崩溃或回执丢失时先观察真实运行面；重试写入不代表可以重试点击。 最终报告固定本次运行与执行阶段，晚到结果不能改写已封存输入，也不能借用其他 Run 的成功结论。

动作观察的新鲜度版本与报告所属的运行阶段是不同概念：逐边恢复会产生新观察，并不要求所有帧属于同一瞬间。各次观察必须属于允许的运行链，后续结果只有通过阶段接纳检查才能消费，已封存报告仍不可改写。

5. 贯穿示例与失败出口

5.1 导航首页被启动广告挡住

先保存广告前态，不创建假首页。安全关闭后观察到导航与广告列表，专项四识别当前内容和暂定产品能力，专项二记录真实入口。 菜单进入候选队列，静态广告素材规则按合同复用，广告位、关闭和有效交互仍保留各自范围。 若广告关不掉，证据充分且规则要求可关闭可判失败；不能用删 DOM 后的底页宣告探索成功。

5.2 虚拟列表先滚动再点击

专项一选择有价值候选，专项六定位容器、有界滚动，专项五观察新帧，随后重新绑定目标再点击。 只有实际详情在当前层可见且后置成立，专项二才建立成功转场；旧坐标和命令退出码不计到达。 详情较长时专项七保存原帧序列。Judge 缺下半页内容，专项三先判断能否就地补帧，再考虑图路径恢复。

5.3 广告在原标签执行 JS 外跳

没有可靠 href 时不能静态猜落地。允许的真实动作产生来源、转场和落地证据；天然新标签优先保留源页，原标签外跳则有限观察并回源。 回源反复弹出同一启动层，共享循环预算并明确结束；不通过重启无限重试。 另开已知 URL 只能补充获准的内容观察，不能替代原按钮有效性证明。

5.4 原登录或支付状态已无法恢复

相同标题、URL 或页面类型不证明用户、价格、一次性上下文一致。 规则要求精确原状态而无法证明时，原缺口保持不足或转人工；只有规则原先独立允许新的当前事实评估，才能另建新请求和新结论。 新结论不能覆盖旧失败，也不能让旧精确补采缺口消失。

7. 实施依赖与代码改动口径

七篇独立评审，但不是七个互不相关的开发包。共同依赖是动作协调、Capture、规则输入和最终 Gate。 各篇标注的高/中影响描述的是涉及链路与风险，不是代码行重写比例；同一模块在多篇出现只能计算一次。

建议顺序：

  1. 建立当前任务/规则/证据基线，冻结风险、识别、状态等价和验收口径。
  2. 优先加强专项 05、06、07 的动作、层级与证据正确性，专项 02 同时只读影子投影。
  3. 串联专项 04 的入口识别、能力解释和规则范围，保证分母与类型身份分离。
  4. 专项 01 先做只读影子适配，再以单一动作所有者低风险灰度；不得同时双写设备动作。
  5. 专项 03 在图、就绪和证据门禁达标后启用精准恢复；所有请求有界且可终结。
  6. 分批完善工作台、跨端真实验收与旧专项分支收敛，保留回退能力和不可变历史。

复用范围：任务、租户与权限、租约、现有 Driver、Frontier、Catalog、Capture、Manifest、InputSet、规则执行和工作台任务入口。 重点改造范围：探索调度与执行适配、图和恢复、识别/规则计划、就绪/目标绑定、证据质量与工作台诊断。 不重建范围：平台整体架构、账号租户体系、前端主菜单路由、第二套规则引擎或独立爬虫控制面。

8. 评审与验收使用方式

产品评审重点看每篇第 1、2、6、7、14 节：是否真正解决问题，失败结果是否可接受。 研发评审先看第 15–19 节的三类图、算法、执行/提交边界与故障矩阵，再回查第 3–5、8–9、11–12 节的现有基础、依赖和回滚。 测试与运营重点看第 10、13、18–19 节：能否从工作台复核、如何注入故障、重试有没有副作用、终态是否诚实。

HTML 静态结构、导航和内容一致性检查只验证文档产物，不验证产品能力。 后续实施仍需按真实 H5/App、Flutter 有/无语义、网络不可见、外跳、长页、弹窗循环、取消和崩溃矩阵验证。 实现完成、测试通过、真实设备验收、Completion Gate 和上线状态分别报告，不能互相替代。
