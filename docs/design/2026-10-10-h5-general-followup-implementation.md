# H5 通用清障与现场检查点修复记录

## 1. 范围

本轮基于 `20261010-012036` 的失败案例实施共享 H5 修复。产品只是诊断样本，运行代码不新增产品编号、域名、URL、站点类名或坐标分支。保留 Task/Run、Explorer/Judge/Probe、Page Graph、Frontier、Publication、EvidenceRequest、SessionCommandGate 和 Completion Gate 的现有架构。

没有清理本轮历史数据、修改任务状态、重启服务、创建或重跑产品任务。原本进程没有加载本次修改，原失败任务也不会因代码更新变成成功。未改 App/Web 的行为、风险与 Gate，未提高任何任务预算，未提交或推送。

## 2. 已确认根因与对应实施

### 2.1 HTTP 本地媒体摘要缺失

部分 HTTP 页面没有 `crypto.subtle`。同结构弹窗的 Blob 媒体失去可比较摘要时，原生点击实际已关闭旧节点、下一层已出现，后验仍可能把下一层认作旧层。隔离浏览器的同结构多层案例复现了摘要缺失；不能用修改网站协议、域名特判或忽略后验解决。

实施：H5 本地 Blob/data 媒体优先用浏览器 SHA-256，不可用时用浏览器运行端标准 SHA-256。补偿通道两端均有 5 MiB 上限，弹窗本地媒体沿用已有大小边界；原本可用的 HTTPS 原生 data 摘要不新增大小限制。不下载远端图片，不输出原始媒体到快照或模型，不修改网站的 `crypto`。每 Page 只注册一次纯摘要绑定；有限缓存只保存不可变本地资源的成功摘要，不缓存失败。

关闭证明仍要求可信原生关闭点击，以及原节点实际隐藏生命周期，或原节点断开且下一层媒体确实不同。图片轮播、文字变化、同层重绘、无效点击不因有了摘要就变成关闭成功。无法区分原层重绘与新层时仍保留不确定，而不是强行通过。

涉及实现：`h5_local_media_digest.py`、`h5_modal_dismissal_target.py`、`page_capture.py`。

### 2.2 单层退场与业务页跳转证明混用

关闭遮挡可能改变页面结构提取结果，但不代表业务导航。此前单层退场被要求满足相同全局业务身份，可能否定已经取得的本地关闭事实。不能通过把逻辑转换强改为可信来解决。

实施：增加独立的 H5 遮挡动作后验。必须同时有目标签名及来源绑定、稳定退场事实、相同真实文档时间源、相同当前位置和页签清单；跨文档、地址变化、新窗口、来源不匹配、未验证关闭和非 H5 路径不取得该证明。非有限时间源、布尔值或缺失时间源也拒绝。

局部关闭证明只供清障动作后验使用，不改写 `logical_surface_transition`，不授予业务页到达、Page Graph 可信导航或恢复路径资格。下一层可见保持 `H5_POPUP_CHAIN_REMAINS_BLOCKED`，协调器封存后态，由既有 Frontier 继续处理遮挡，不允许点击被遮挡业务入口。

前几层真实关闭、后一层目标失效或点击无效时，保留真实前缀进展和最后一层原失败回执。只写“层已推进”，不把最后一次 `dismissal_verified` 改成成功，也不声称整条链已清空。

涉及实现：`h5_obstruction_effect.py`、`capture_runtime.py`、`page_capture.py`。

### 2.3 已耗尽现场工作被无关快照绑住

页面检查点此前要求 Snapshot 请求为零、且所有现场工作均耗尽，才调用已有安全结算仓储。一个已经达到重试上限的工作，也会因另一个合法快照请求仍存在而留在非终态，最终导致整个探索链退出。Snapshot=7/12 的受控用例在修改前复现相同 RuntimeError。

实施：待采集为零、现场补证请求为零时，对存在的已耗尽现场工作调用原来的逐工作结算。数据库仍检查 H5、本 Task/Run/Owner/Epoch、重试耗尽、无租约及无在途请求。未耗尽工作继续正常 Judge，结果不强改为通过，缺证结算仍是 `evidence_insufficient`。

结算后必须重新读权威状态，不能用“结算了 N 项”推断页面已排空。只有现场依赖真实排空，且每个未终态 Snapshot 均通过原恢复合同预检，才允许离页。无法恢复的快照继续阻断；关闭会话前不延期快照。本次没有修改 SQL、数据模型或迁移。

涉及实现：`h5_live_inspection_publish.py`。

### 2.4 健康现场质检被局部累计等待上限截断

页面检查点的固定累计等待上限会在 Judge 持续产出时提前终止。局部等待上限与本轮已冻结的 180 分钟总期限不是同一个限制。

实施：现场检查点的有效结论、正式结算、权威终态事实及待办下降可刷新无进展窗口；健康推进受原 Run 冻结截止约束，不再因该检查点累计超过 900 秒自动失败。无进展仍保留原 300 秒窗口；未来合法调度只能有限等待，900 秒作为无进展兜底。领取、租约心跳或重试安排本身不算收益。

最终关闭的独立绝对排空窗口保持不变。未刷新 Run 截止、未重开预算、未修改公共默认值。恢复测试也明确核对原截止时间向下传递。

## 3. 防回退验证

| 场景 | 必须保留的结果 |
| --- | --- |
| HTTP/HTTPS、Blob/data、多层同结构广告 | 正常原生点击逐层退场，摘要在 HTTP 可用 |
| 10/25/50 层成功链 | 成功不计真实无效次数；样本层数不是线上承诺或新限制 |
| 延迟图片、隐藏后复用、相同素材新层 | 原有异步生命周期证明仍成立 |
| 纯轮播、重绘、无效点击、外跳按钮 | 不误判关闭、不穿透遮挡、不扩大点击权限 |
| 业务身份提取改变、原文档未变 | 只认可独立清障事实，不伪造业务转换 |
| 文档/地址/窗口变化、无签名、Web | 新清障证明拒绝，原路径保留 |
| 现场工作耗尽 + Snapshot=0/7/12 | 逐项安全结算后重新读取，合法快照可按原合同延期 |
| 混合已耗尽与正常工作 | 只结算耗尽项，正常工作必须真实完成后才能离页 |

| 健康 Judge 超过局部累计 900 秒 | 有效推进继续，冻结总截止不延长 |
| 无结论的重复领取、无进展、最终关闭 | 原有界退出与证据不足结果保留 |

## 4. 本轮未扩大实施的内容

同缺口跨 Capture 的精确收敛和多步语义补证不在本次补丁中冒进扩展。现有 Probe 规划选择一条许可动作；即便该动作成功、运输合同满足，也不证明完整规则目标成立，最终结论仍由合格输入与 Judge 决定。

不能用 URL、页型、规则号粗缓存将不同内容条目、支付档位或播放状态混成同一缺口；不能通过更早结算、改 source 角色或伪造下架/广告失败证据提覆盖率。后续只在相同逻辑目标、缺口合同与相关输入版本可证明时实施精确去重或目标序列，沿用既有 Probe/命令门禁，不另建探索架构。

## 5. 真实验收标准

回归通过只证明受控案例与原合同仍成立，不保证动态站点每轮数量相同。本轮没有新的五产品 Gate 或正式报告，不宣称真实效果已全面修复。

经确认安全加载代码后，先验证通用清障和现场检查点，再检查 payment/settings 等业务页型的真实到达、有效独立页面、规则合格输入和有效结论。截图数量、已执行动作、运输请求 satisfied、待复核或证据不足结算都不单独构成进步。031 的页型减少必须保留为待实跑核对项，不能归因于分类器、也不能用其他产品截图增加掩盖。

本次代码和历史原始统计是两个证据层。验收仍需本 Task/Run 的 Work/Request/Session 排空、Gate 与正式报告绑定；任何残留或外部条件阻断都如实列明，不自动盲目重跑。
