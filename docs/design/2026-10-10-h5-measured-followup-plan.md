## 3. 问题一：JHA-031 的 90 分钟花在哪里

### 已确认

- 冻结墙钟预算为 5400 秒，不是当前分支无限运行。
- 108 次采集的稳定等待累计约 1419.2 秒，即 23.7 分钟；采集总耗时累计约 26.8 分钟。累计采集耗时不能与并行 Judge 耗时直接相加充当关键路径。
- 83 帧为 page_settle_complete=false、page_inspection_ready=true，只有 1 帧两者都为 false。大多数不是纯加载页，而是等待窗口耗尽后才被接受的可质检动态页面。
- 54 个动作中，19 个用于返回/恢复来源，16 个用于补采观察。22 个补证请求只有 2 个满足，20 个最终不可满足；15 次恢复中 3 次 divergent。
- 217 条模型物理请求流水中有 172 次失败、45 次成功；主 Run 结束前已有 216 条，不能全部归因于结束后的清理。

### 代码根因

`page_capture.py:3747` 的 `_wait_for_page_settle` 要求全正文稳定、DOM 静默、没有任何 visible_loader、必要媒体就绪及关键网络空闲。`page_capture.py:4510` 的 `_assess_page_inspection_readiness` 在等待耗尽后才允许已有正文的局部加载、背景请求和动态页面。

两阶段判据不一致：页面最终可用，却经常先等满约 15 秒。补采和恢复又生成新 Capture，放大等待与再次识别成本。单帧已有缓存并不能解决新帧的重复工作。

### 方案

在 H5 路径复用现有 readiness / evidence 判据，允许连续轻量样本证明主业务区域可用时提前采集，不要求广告轮播和全站网络静止。涉及规则的媒体或操作证据仍必须满足自己的输入合同。

纯加载、骨架、整页遮挡和过渡态继续有界等待；启动广告只算遮挡证据，不算业务页覆盖。AI 仅处理视觉状态歧义，不在每轮轮询中调用。

早退出所需证据必须在采集前真实取得，不能直接把采集后函数移到等待前、忽略其 artifacts 前提。共用判据而非复制一套更宽松的判断。

同时减少无新增证据的恢复与补采，否则仅优化等待仍会耗尽 90 分钟。不能承诺只改这一处就能覆盖全部规则。

### 追加核对：时间限制与实际收益应分开

主 Run 截止前最后一个可信采集出现在 23:11:37，位于 `/aiUndress2`，选中“图生视频”。最后约八分钟的动作主要是反复观察补采，未产生新的逻辑页面身份。因此，不能把这 90 分钟全部解释为有效探索，也不能认定延长时间没有价值：旧模型故障和补证消耗会掩盖正常条件下的实际耗时。

修订方案：不再坚持 5400 秒，也不直接拍定另一个统一的 120/180 分钟。任务可采用更宽裕的可配置墙钟期限；已冻结的 Task/Run 不在运行中偷偷改预算，新任务按预计工作量配置。健康 Judge 正在出结论、目标补证正在取得相关证据、安全弹层正在逐层消失、新页型或关键业务状态正在增加，都属于有效进展，应继续执行。

防止无限运行应针对具体无收益分支：相同逻辑目标、相同缺口、相同输入且没有新增能力的恢复/观察不能因新 Capture ID 无限重开；后台轮播、流水线心跳和重复截图不能刷新进展。局部分支无收益时保留其他可执行业务分支，不直接结束全任务。模型、采集、恢复各子等待仍有可取消的期限，整体截止后的收尾也必须有界。较长时间和较高正常工作量需要配套核对动作、调用及费用预算，不能只加墙钟却仍在另一硬上限提前退出。

## 5. 问题三：JHA-102 / CloudFront 遮挡阻断

### 已确认

历史截图已经到达业务首页，不能将此终止原因解释为网站访问不通。以下时间为北京时间：

- 22:24:26 一次关闭因 LOGICAL_SOURCE_STATE_STALE 被拦截。
- 22:24:38 一次关闭成功，动作证据明确记录 next_popup_layer_visible：旧层关闭，出现下一层。
- 22:25:29、22:25:48 对下一层的关闭为 POPUP_DISMISSAL_NOT_OBSERVED，证据指向 original_layer_still_visible。
- 22:29:17 以 Frontier 无可执行候选、仍有遮挡结束。

对最终存储的 UI Snapshot 离线运行现有 `h5_modal_close`，仍能找到同层安全关闭证明：`i` 元素，40×40，坐标约 x=329.2、y=187.19，并具备 sibling_close_control 证明。后期弹窗签名相同。

因此已经确认的是：**最终无可执行 Frontier 候选，不等于现场没有可识别关闭控件**。失败历史、逻辑状态漂移、能力投影和后继候选筛选需要一致，不能把仍存在的能力永久丢掉。

### 尚未证实

后两次关闭究竟是点击未生效、原节点仍显示旧层，还是下一层复用了节点导致验证过严，目前证据不足以唯一判断。不能直接改成强制点击、固定坐标或“图片变化即关闭成功”。

### 追加真实浏览器核对

临时普通 Chrome 标签页访问同一 HTTP 入口后自动转为 HTTPS。通过页面真实控件依次完成：启动广告跳过、应用目录弹窗关闭、10 张连续图片广告关闭，最终取得无遮挡业务首页。每张广告共用相似 Dialog 结构与 `.closeSty > i` 关闭控件，广告媒体与 z-index 依次推进；没有强制点击、移除遮罩、跳转广告或改站点脚本。

该结果证明当前入口存在可安全逐层走完的弹窗链，不能把 Frontier 阻断解释成网站不可访问。它使用普通 Chrome 桌面视口，不是原任务隔离会话，也没有调用旧 H5 执行器，不能宣称历史根因全部复现或代码已修复。核对截图：`/tmp/alioth-h5-cloudfront-cleared-20261010.png`。

### 方案

沿用既有有界能力重发现：无候选且仍有遮挡时，检查最新关闭证明与 Frontier 过滤原因；仅在当前层、关闭目标唯一、命中及风险校验满足时更新候选。不得用新 Capture 重置整个失败预算。

补上失败动作后的有限截图、层身份、点击命中和状态转换记录。先用多层弹窗、源状态噪声及节点复用用例区分失败分支，再决定修哪一层。安全关闭仍不能证明时，明确阻断并结束，不能绕过遮挡继续访问底层。

同时纠正关闭后的成功判据，详见第 12 节。不能只重新签发候选，却让同一个错误后验继续把每次有效关闭计作失败。

## 6. 问题四：JHA-204 的三个零与 snapshot=2

### 已确认

错误中的 nonterminal_evidence_requests 是现场依赖维度，不包含单列的 snapshot 请求。snapshot_evidence_requests=2 是实际未终态的快照依赖补证请求，不是可以随便忽略的旧缓存值。

`h5_live_inspection_publish.py:759` 的检查点仅在请求已结束，或者快照请求均有可信恢复路线时允许离开。无法延期的快照请求无收益等待耗尽后，`h5_live_inspection_publish.py:998` 抛出通用 RuntimeError，传播为整个 Main 失败。

14 个请求中只有 4 个满足、10 个不可满足，21 次恢复中 9 次 divergent。运行后段有缺少安全取证动作和可信恢复路线的请求。64 次采集的稳定等待累计约 16.9 分钟。

### 时间证据边界

原始检查点异常在运行层保存后，还执行 finally 清理才写出失败日志。因此不能把最终日志时间直接当作 snapshot=2 的原始取样时间，也不能因为清理后请求全结束，就认定原错误是陈旧计数。现有记录尚未精确定位原始抛错瞬间的两条请求。

### 追加核对：请求在索取什么

14 条请求的真实目标表明，问题不只是检查点收尾：

- `alioth_23` 反复要求“广告加载失败时的页面”，包括稳定首页和稳定视频列表。正常重新观察无法保证制造这种条件，Probe 没有相关安全候选时返回 blocked 是合理的，反复生成同目标请求才是需要收敛的问题。
- `alioth_spec_72` 在广告已清除的 stable 页面要求“关闭按钮热区命中测试结果”。真正可取证的窗口是弹窗存在、关闭前后，而不是恢复到无遮挡列表后重新寻找已消失按钮。
- `alioth_spec_35` 已有滚底请求 satisfied，后续又要求整页截图加滚动位置/内容高度；所有这些请求的 `required_interaction` 都为空。既不能仅按同一规则粗暴去重，也不能把“截图有了”当作几何证据全部满足。应核对具体列表/Tab 身份与滚动容器，将目标所需证据一次取齐。
- `alioth_15` 要求列表封面与同一条目的播放/详情画面配对，但请求的业务目标只保留视频列表及其 `/home` 地址，没有在这些 target invariants 中明确关联内容条目。需要沿既有来源与目标绑定补足条目证据，不能把其他内容的画面混配。
- `alioth_40` 的请求明确缺少 `source` 角色，三次恢复后 divergent。这首先是输入角色/来源合同排查，不宜用一次普通截图或强改 capture_role 掩盖。

`H5ProbeGoalPlanner` 当前从恢复后的 Frontier 选择一条安全动作，依靠 evidence_goal 自由文本告诉模型目标；请求中“滚底/命中/配对”的含义没有充分落入可验证的操作与产物合同。这里不是要让模型放宽相关性筛选，而是使需要的状态、动作与证据实际可取得。

### 修订方案：先补取证能力，再处理收尾

1. 在既有 EvidenceRequest / InputSet / Probe 合同内明确所需状态、关联条目、操作及产物。几何证据不止截图；配对证据必须是同一内容。优先补足已有结构化字段与执行器对应能力，不新增第二套任务系统。
2. 广告规则利用当前弹层关闭前、点击命中与关闭后证据；先检索可绑定到同一目标的已存证据，再决定现场补采。不能拿另一业务页面的广告证明顶替，也不能为补证重新打开广告。
3. 滚底取证在实际滚动容器内确认位置、内容高度、末项与底栏边界、懒加载/分页状态，再形成同一次输入。无穷列表没有天然底部时须诚实标注，不能靠长截图假定触底。
4. 条件型规则如“加载失败”区分条件未观察到与一般证据缺失。复用自然出现的失败事件；没有出现时不反复普通观察去等待它，不自动故障注入，不把未观察到转换为已通过或确认不适用。
5. 先复现 `source` 角色为何不能被现有输入满足，核对生产、绑定、校验三个环节。只修 H5 合同落点，不修改共享规则定义，不将 after_action 全局改名为 source。

上述取证改善之后，再在既有 EvidenceRequest / Probe / Restoration 中逐项处理延期和收尾，不新增调度引擎：

在既有 EvidenceRequest / Probe / Restoration 中逐项分类，不新增调度引擎：

- active-session：现场合同满足或有界结算前不能离开。
- snapshot 且具备可信回放：保留原来源与 InputSet，允许延期，不阻塞其他新页型。
- snapshot 且无可信回放：优先当前现场有界补证；能力、风险或期限不满足时如实结算不可满足，附具体缺口，不一直等待无执行可能的目标。

可信快照延期应逐请求判断。当前 `can_defer_snapshot_requests` 返回整组布尔结果，一个不能延期的请求会使全部不能延期；修订时不能让已满足恢复条件的请求被另一请求一起绑住。但 active-session 与不可延期现场证据仍先处理，不能吞掉检查点异常直接离开。

用明确的检查点处理结果区分局部补证不能完成与整个运行基础设施失败，不能把每个局部缺口都升级成主链 RuntimeError；也不能用提前结算不可满足的数量充当优化收益。整体任务采用用户接受的合理较长期限，结束时停止新增工作、有界排空和输出真实缺口，不把无法满足转成通过或确认不适用。

## 12. 进一步代码核对：不能把有效多层关闭当僵持

### 已确认的实现问题

1. `h5_popup_loop_policy.py:27` 仍设同一业务页 20 轮上限；49-55 行计入 executed、failed、blocked、skipped，不是“成功关闭 20 层”。同签名的 3 次统计同样包含 executed。这个上限不能覆盖用户要求的任意有限多层链，成功关闭本身不应成为停机原因。
2. `next_popup_dismissal_reobserve_state` 只拿候选和旧计数，不拿实际错误阶段/点击结果。过期未点击的 scope mismatch 和真正点不动混成连续失败；YC003 的 4/4 不能等价理解为“四次有效点击都没用”。
3. `_wait_for_popup_dismissal` 只在等待开始前检查一次“原节点移除、下一同结构层媒体不同且可信关闭已点击”。随后轮询不重新计算这个异步媒体检查。下一层较晚出现或解码较晚时，即使是可信关闭，轮询仍可能将同结构替代层当原层。这是代码中确定存在的观察时机缺口；它是否解释某个历史动作仍须受控复现。
4. 签发目标使用 require_hidden；同一 DOM 节点复用且下一广告显示时，旧节点继续可见，会触发未关闭。另一方面，媒体不同又被当成接受同结构新节点的重要前提；合法下一层若复用同素材，也可能被拒绝。DOM 模板与广告图片都不应单独等同于“同一活动层”。
5. 既有多层浏览器用例偏重少量立即替换的不同素材，没有覆盖本次真实站点的长链与关闭/入场动画；已有同素材替代节点拒绝用例应保留“无真实关闭不算成功”的意图，但不能把可信旧层已经结束的新层一并禁止。

### 最小可行修订，不改变风险边界

- 复用现有签发节点/token/真实关闭点击证明，补足“原层生命周期结束”的观察。原节点消失、自然隐藏后新层出现、可信关闭后的层代际变化分别验证；DOM 节点复用时不能仅看最终 visible=true。观察异步变化直到结果明确或单动作超时，不在第一瞬间拍板。
- 结果至少区分原层仍在、原层已结束且下一层出现、已无活动遮挡、证明过期未点击。原层结束是该次动作成功；只有无活动遮挡才允许访问底层业务。成功后重新采集并签发下一层真实关闭目标，不能沿用上一层坐标或签名。
- 图片变化只是辅助证据，不能单独证明关闭；真实点击也不单独证明成功。仅轮播、关闭无响应、旧层重新出现、命中广告图片、站外导航及不明确按钮仍拒绝。
- 不再因成功层数多而停，依次处理全部有限层。识别真正同一层持续无效、已证实循环重现但没有层生命周期进展的分支；无限生成广告等无法有限完成的情况如实说明，受合理整体期限与人工取消约束，不能通过移除遮罩继续。
- 失败同样保留有限的动作前后与命中证据，再做逻辑计数。不能因异常直接丢失点击后的状态，导致后续只靠猜测判断。

### 防回退用例必须同时成立

- 受控 3/10/25/50 层链均能依次清空；50 是回归样本，不是线上层数承诺。
- 相同模板不同图片、合法下一层相同图片、复用节点、自然隐藏/重显、延迟替换/解码与关闭动画都可识别真实进展。
- 同一图片自行轮播、非关闭点击、关闭无响应以及旧层未结束，绝不能被当成功；同层无效操作不能无限重试。
