01 / OVERVIEW

先校正现状，再比较改动

当前平台已经有动态 Frontier、动作前后采集、稳定性检查、局部恢复、证据清单和完成门禁。问题是这些能力尚未充分围绕统一页面事实协同，不能概括为“没有智能探索”。

当前基础

能够发现、执行、观察和局部恢复

H5 与 App 各有成熟片段；候选、识别、遮挡、恢复和证据消费仍包含不同层的专项衔接。

目标变化

每一步都能说明为何继续、为何停止

用可信页面图关联动作与证据；将缺证回流为有界补采，并持续保留任务目标、风险和最终收口约束。

当前执行模式边界：独立探索结束，不等于完整质检通过。
实际链路当前职责结束意味着什么
Web 独立探索Web Handler 的页面采集与 URL 队列；不启动正式规则工作和报告收口。探索阶段终态。不是 Completion Gate 通过。
H5 / Web 完整质检Web FULL_INSPECTION 转入 H5 V2；动态探索、页型评估、规则与证据、正式收口。探索停止后仍需规则、证据、覆盖等完成条件成立。
App 探索 / 质检冻结产品目标，安装启动、截图理解、候选交互、覆盖评估；按任务模式衔接质检。设备就绪、业务页到达、探索结束和正式质检完成分别判断。

模式事实：Worker 模式分流 :870。动态发现、显式目标、产品声明等目标来源，与“是否执行完整质检”是不同维度，不能混为同一个开关。

这不是一次全量替换。 任务、租约、Driver、Frontier、Capture、Catalog、规则执行和 Gate 继续复用；CLI / ADB 是受控执行器，Skills 是操作知识，均不替代平台权限与证据控制。

03 / TARGET LOOP

优化后：以可信页面状态和证据缺口驱动

图中颜色表达改造性质，不表示质量优劣。蓝色复用控制面，绿色增强已有能力，紫色表示新增的共享机制。页面图来自可信观察和转场事实，树只是展示或恢复路径投影。

复用增强 / 统一新增共享机制反馈 / 恢复
同步关系：静态 Rule Judge 可与探索并行；“可关闭、跳转有效”等规则必须等合法后态或序列。无需等待所有静态规则判完再清障。所有设备动作仍由同一个受控 Runtime 负责。
  • 页面与状态：局部 Tab / 筛选 / 展开默认同节点不同状态；实质改变业务职责、对象、路由或返回语义再判新页面。
  • 页面与弹窗：弹窗也是质检目标，但通常不进入业务页面树；独立支付路由仍是页面，内联二维码可能只是区域。
  • 页面与外跳：源页保留自身事实；外部广告落地默认只留证，不计业务覆盖，回源也不新增重复覆盖。
  • 产品与目标：观察到导航型首页可以调整探索优先级，但没找到、被阻断、预算不足不能自动变成“不适用”。
  • 自然与诊断：删 DOM、隐藏层、强制或脚本派发点击等诊断方式不能制造正式自然通过；限制沿后续证据链传播。
  • 失败与不足：材料充分证明关不掉可支持规则失败；缺前后态则不足。证据质量通过不等于产品规则通过。
04 / SEVEN CHANGES

七项优化：具体解决什么，提升在哪里

每项都区分“已有基础、当前不足、设计机制、预期收益”。下面的收益均为待验证目标，不是已测得的提升比例。

专项现状的主要不足优化后的核心变化直接价值
01 受控探索候选、动作组合与专项适配牵动多层。CLI / ADB 作为受控执行器，统一能力、风险、预算和回执。提高操作组合能力，降低执行适配成本。
02 页面图已有候选路径，但身份、状态和完整页面关系不统一。从可信观察形成页面状态图；页型可修订，树只是投影。减少重复和错误合并，让覆盖与恢复有共同依据。
03 精准补采局部恢复已有，正式缺证恢复闭环未开放。缺口 → 就地 / 图路径恢复 → 实际等价验证 → 新证据与新判断。降低重跑成本，避免错状态补证。
04 精准识别H5 / App 判别输入不对齐，页型漂移会影响后续。统一判别指南，分开产品能力、业务页型、展示层与规则范围。减少模板误套、类型漂移和规则错配。
05 截图时机已有整体 settle，仍需动作和规则目标相关证明。窗口 / 对象 / 可见层 / 后置 / 内容 / 网络共同判断。提高首份可用证据比例，减少过早和错帧采集。
06 精准交互单步保护已有，连续操作、弹窗和外跳需统一验证。逐步观察重绑、语义化清障、条件旁路与共享恢复预算。减少误触、旧坐标失败和重复清障。
07 可信证据材料齐全不足以证明对象和当前可见层正确。时间、对象、层级、角色、来源及诊断影响贯穿消费链。减少错证据进入正式判断，提高复核与重判能力。

01受控 CLI / ADB / Skills：提升组合能力

当前基础

已有 Playwright / App Driver、动态候选和控制面。灵活性不仅受 Tool 形式影响，也受候选生成、过滤和运行时专项逻辑影响。

不足与根因

新交互可能同时改识别、候选、执行和恢复；仅换成 Bash 不会自动提高候选质量或到达正确率，反而会扩大未受控操作面。

设计机制

统一受控命令入口，绑定会话 / 租约 / 域名或包名 / 参数 / 风险 / 预算。Skills 提供知识，命令回执说明做了什么，后态再证明效果。连续动作每一步重新检查。

直接与迭代收益

支持有界滚动、定位和点击组合；后续可更换执行器、增加观察能力，而不重写规则、页面身份和完成逻辑。Android 使用 ADB，不能将其泛化为 iOS 执行器。

验收：同预算可信覆盖、无效动作比例、越权拒绝、无归属命令数、总耗时与 Token。只读影子适配后再单执行方灰度，禁止双写设备动作。

专项设计 01 · 当前执行器能力 · Playwright CLI 官方说明

02页面状态图：从候选记忆到可信地图

当前基础

H5 Frontier 已有 visited / executed、动作指纹、来源状态、父状态和 lineage；App 候选有来源截图、身份和导航路径。并非“只有发现、没有路径”。

不足与根因

这些信息主要服务调度，尚不是统一页面图。App 核心身份仍含包名 / Activity / 页型：改判页型可能改变身份；同 Activity 的同类详情又可能具有同一核心身份。

设计机制

稳定身份与页型修订解耦；用业务位置、对象和可靠地标支持分组，缺证则保留未知。图支持多入口和循环，树用于展示。到达、探索、证据与规则状态分别表达。

直接与迭代收益

减少错误去重、重复探索与覆盖失真；后续精准补采、增量探索、路径选择和工作台诊断可以复用同一事实基础。图上存在不等于现在一定能恢复。

验收：同状态重复节点率、不同对象错误合并率、转场证明完整率、冻结分母一致性。初始化时先影子投影，不以图推测直接新增业务覆盖。

03精准补采：让证据缺口返回探索侧

当前基础

已有 BACK / WARM_RESTORE、导航锚点、有限重试与 StateEquivalenceGate。生产构造却固定 runtime_ready=False，正式补采闭环未开放；普通 after Capture 不等于精准补采。

不足与根因

局部恢复不是图路径规划。恢复含类型级父路径启发，不能证明真实产品路线。仅开启配置不能补齐执行、状态验证、证据追加和请求终结。

设计机制

先明确规则缺哪个对象 / 区域 / 前后态，优先就地补采，再按已验证路径逐边恢复。按原状态、等价状态、新观察或人工策略验收，不重放旧坐标，也不放宽高风险状态约束。

直接与迭代收益

减少全量重跑和错目标补证，支持局部重检。恢复失败留下原因与缺口；新材料和新判断只追加，不能覆盖旧失败，也不能拿新的 fresh 判断填平旧 exact 请求。

启用前必须处理的风险：当前 Probe 挂回会把目标不变量合并进恢复快照。正式等价判断必须依赖恢复后的独立观察，不能用目标值证明目标已恢复。这是待启用链路风险，不是本轮已证实的线上错判。

验收：合法恢复成功率、错误等价放行数、补采动作数及 P50 / P95 耗时、缺口终态完整率。支付、登录等高风险规则从严。

专项设计 03 · 生产双门禁 · Probe 事实来源风险

04精准识别：统一判别依据，而不只是补一句描述

当前基础

Catalog 已有 signals、entry / exit hints 和 remark。H5 注入完整目录，App 视觉模型主要接收页型代码与通用视觉说明；静态产品画像已经存在。

不足与根因

跨端判别依据不对齐；相似卡片布局难以区分导航、广告聚合和内容列表；当前页型、产品整体能力及可见层容易互相代替。

设计机制

版本化判别指南包含用途、关键证据、相邻类型差异和反例。入口观察后形成暂定产品能力，允许未知与修订。原冻结目标不能因“没找到”而被删除。

直接与迭代收益

减少模板误套、类型漂移和错配规则。按规则合同复用静态素材 / 全局结果；广告位、曝光、关闭与有效性仍按相应页面状态、位置或发生实例检查。

验收：人工标注误判率、同状态不合理漂移率、规则错配率、无依据“不适用”数量和必要规则范围保留率。不能通过永远保留第一次错误判断来制造“零漂移”。

专项设计 04 · H5 / App 识别输入对照

05截图时机：由动作和规则用途决定何时可用

当前基础

H5 已检查 DOM、核心容器、媒体、loader / transition、Flutter bootstrap 和相关在途请求；不能把现状说成固定 sleep 后盲拍。

不足与根因

整体稳定不等于目标出现。网络安静但正文没出来、按钮消失却外跳、底页加载完但被弹层挡住，都不能证明当前取证条件成立。

设计机制

按动作检查运行面 / 业务对象 / 可见层 / 预期效果 / 核心内容，并进行采集前后身份检查。网络 2～3 秒安静仅作辅助，还要考虑未完成、失败和不可观测情况。

直接与迭代收益

提高首采可用率，减少过早与错帧取证。按导航、关闭、滚动、媒体等分别调优。加载超时和关闭失败可保留为时间证据，不冒充稳定到达。

验收：首采可用率、错帧接受数、等待超时原因覆盖、重采次数和时间成本。网络不可见不是零请求；ADB 不自动赋予任意 App 网络可见性。

专项设计 05 · 已有 settle · Playwright 就绪边界

06精准交互：连续操作、弹窗和外跳的验证闭环

当前基础

已有候选截图绑定、图像签名、几何 / 风险 / 前台检查和动作前后 Capture；已有有限遮挡清理与各层观察。

不足与根因

单次定位不能贯穿滚动后的整个操作串。弹窗控件消失不等于安全关闭。当前主 Web Driver 未开放独立多 Surface 生命周期，外跳不能一律按复制标签处理。

设计机制

逐步“定位 → 操作 → 观察 → 重绑”。区分广告、登录、充值、更新、公告与系统提示；保存前态、验证关闭后态，循环共享预算。分辨率、缩放、方向和安全区按实际坐标链处理。

直接与迭代收益

减少误触与重复清障。天然新标签保留源页；已知允许 URL 可旁路补充内容，但不替代 JS / POST / 一次性点击链证明。支持复杂列表、自绘控件与不同设备规格。

验收：按动作意图区分误触率、正确关闭率、外跳回源成功率、重复阻断次数与未知副作用重试数。UA / 分辨率用于可复现环境，不承诺绕过人机校验。

专项设计 06 · 动作门禁 · 多 Surface 边界 · 可操作性不等于业务到达

07可信证据：正确格式之外，还要对象、层级和用途正确

当前基础

已有附件、角色、数量和文本齐全性裁决；Observation Packet 另有身份和状态检查，InputSet / Gate 负责输入封存和收口。当前 DOM 也有清理与超限截断。

不足与根因

文件正确不等于证明内容正确。标注详情却截到充值弹窗，不能靠格式、大小和时间纠正。多个 Writer 和消费者需要一致的层级与用途约束。

设计机制

校验来源、对象、状态、可见区域、时间关系和规则充分性。区分视口原图、整页扩展图、滚动序列与拼接派生图；区分采集载荷、清洗阅读版、存储压缩和模型有界读取。

直接与迭代收益

减少错层、错对象、错状态材料进入正式判断，支持复核和新版本重判。诊断影响贯穿后续证据链；新证据只追加，本次报告不借用其他 Run 的成功材料。

当前确有受限高 z-index 样式隐藏兜底，选项默认关闭；不是普遍删 DOM，也不能据此断言所有历史证据受污染。正式自然分支不得用删改页面制造“可用”的产品事实。

验收：错层 / 错对象放行数、原图与派生图回溯率、规则输入重放一致率、跨运行串证数。Manifest 质量通过 ≠ 规则通过 ≠ 页面覆盖 ≠ Completion Gate 通过。

05 / ROOT CAUSES

核心问题：四类根因如何放大成本

这里画的是基于代码结构的风险关联，不是本轮运行实测出的故障序列或发生概率。已有局部门禁会拦截部分问题，但不应依赖末端 Gate 替代上游语义正确性。

06 / SCENARIOS

三个典型场景：前后差异更直观

下面是流程设计对照，不是本轮重新跑出的设备结果；“当前”说明已有机制的边界，不表示每次一定失败。

场景一：启动广告挡住了导航 / 广告列表首页

当前：有识别与清障，但目标解释分散

可以识别启动广告、生成关闭候选并采集后态；产品静态目标与运行时可见内容仍需衔接，不能仅凭未发现详情就证明产品没有详情。

优化：先观察层，再解释业务

保留广告前态 → 允许的关闭 → 新观察 → 识别导航型入口 → 候选进入 Frontier。关不掉则按前后态与规则结算，不创建假首页，不删 DOM 制造通过。

主要协作：04 识别与范围 + 06 清障 + 05 就绪 + 07 证据；02 仅从可信到达建立业务图。

场景二：列表滚动后点击，广告在原标签执行 JS 外跳

当前：有坐标门禁和有限回源

旧截图候选可能被门禁拒绝；外跳后的返回和清障依赖当前恢复链。没有可靠 href 时，静态 URL 发现不能替代真正点击后的观察。

优化：每步重绑，外跳和业务覆盖分开

滚动 → 新帧 → 重定位 → 按真实意图点击 → 来源 / 落地留证。天然新标签保留源页；原标签有限回源；反复弹窗共享预算。另开 URL 只补充获准内容，不伪造按钮有效性。

主要协作：01 受控组合 + 06 交互与回源 + 05 后置观察 + 07 成对证据。关闭意图误点广告是误触；获准的广告有效性点击不是误触。

场景三：支付页缺少关键证据，原价格或一次性上下文已变化

当前：有恢复组件，但正式补采未开放

同 Activity、同标题或同页型不足以证明同一订单、账号、金额和发生实例。仅把页面找回来，不能宣告原规则的证据缺口被修复。

优化：先声明等价条件，再决定能否补

按规则核对原目标 → 就地 / 图路径恢复 → 读取真实新状态 → 对照允许的不变量。原 exact 无法证明则保持不足或转人工；独立允许的新观察另建判断，不覆盖旧缺口。

主要协作：03 补采策略 + 02 路径 + 05 就绪 + 07 输入封存；支付、登录等高风险场景不能在执行中放宽约束。

后续迭代优势与落地顺序

迭代方向可以复用的基础带来的长期优势
接入新产品产品声明、入口观察、运行时能力解释和真实转场。减少模板式寻页和每个产品重写路线；保留未知，不缩小冻结分母。
更换模型版本化判别指南、可信观察和有来源的修订记录。可离线比较识别与判别策略；离线分析不冒充新的设备到达或改写已封存报告。
新增规则明确目标、角色、发生范围与封存输入。复用真正合格的材料，减少重复判断，同时保留位置与交互应检范围。
更换执行器受控入口、会话与能力声明、真实回执和后态。逐步接入 CLI 或新 Driver，身份、规则和 Gate 不随工具形式重建。
故障排查页面图、动作前后态、阻断层、规则缺口和最终原因。从报告反查发生位置和执行过程，减少人工拼日志的成本。
持续提效同目标 / 规则 / 环境 / 预算下的成本和有效覆盖事实。优化候选优先级、就绪策略和恢复路径；收益不是靠删证据或放宽标准获得。

如何证明真的改善

  • 正确性：页型误判、重复 / 错误合并、错层错对象放行、错误等价、跨运行串证。
  • 有效产出：同预算下可信业务覆盖、首采可用率、规则应检范围、缺口终态完整率。
  • 操作质量：按意图区分误触、关闭成功、回源成功、重复阻断与未知副作用重试。
  • 资源成本：动作数、等待和重采次数、补采 P50 / P95 耗时、Token、总耗时与人工复核成本。
收益有成本，不能先报百分比。 更多检查、状态管理与取证可能增加单步延迟；净收益应来自减少无效探索、错误判断和重复修复。七项修改会落到共同模块，不能把影响范围机械相加，也不应一次全量切换。
