## 先失败再修

初始合同复现为 **7 failed / 16 passed**，确认：

1. 原始可点击媒体/套餐经判定包压缩后失去祖先结构、选中状态和本页展示证明，真实补证目标变成缺口。
2. 有连续滚动材料时仍生成 vertical_scroll，没有后续按钮或回顶阶段。
3. 已绑定的动作前后序列无法正确定位当前 Capture；旧前帧与新后帧不能混用。
4. 原生视频和无 radio/option 的登记会员卡没有展示目标。

隔离浏览器最初 **4项失败**，覆盖原生全屏、两种回顶及自定义卡片到执行端的贯通。后续增加旧证明损坏、私有合同缺键、目标变为提交/表单/遮挡、仅属性变化和真实已完成档位等反例。测试替身及受控 HTML 的错误不当生产根因，例如卡片 CSS 未表现选中状态、DOM 节点移走后丢失浏览器命名属性，都在用例内修正，不删断言或跳过。

## 四项实现与验证

### 连续滑动后的按钮反馈

- 同地址/同容器、有序至少三帧、两次位移和匹配的 `scroll-effect.v1` 后才切换到反馈目标。
- 登记的展开控件须有明确 aria-controls、唯一受控区域、展开状态和现场命中；回顶按钮则另核对触底条件。不按普通按钮或文案猜操作。
- 点击后 ARIA 和受控区域可见性/尺寸均变化才记录效果。只改 ARIA、无响应或视觉杂变不能作为通过材料。
- 原网络状态、连续性及业务反馈判定仍由原工具和 Judge 决定，不把阶段推进记为整条规则通过。

### 触底回顶

- 源帧真实位置超过一屏并到达底部，回顶目标绑定容器和位置；恢复后/动作前再次复核，不把滚动位置丢失当恢复成功。
- 实际原生按钮点击后读取原容器；同文档、同地址、同容器到达顶部才记录回顶效果，页面和内部容器均有真实浏览器用例。
- 动作已发生但无效果，保留动作后证据，不能抛成“未执行”而再次重放。触底提示和回顶整体业务条件不放宽。

### 原生视频全屏

- 扩展媒体展示目标为固定原生全屏能力，必须是真实加载的唯一业务视频、有 controls、有效媒体尺寸、实例标识、全屏能力、可见及命中事实。
- 仅调用固定 requestFullscreen，不自动播放、跳播或按坐标盲点浏览器阴影控件。原生 API 与取帧共享原传入单动作期限。
- 调用后核对 fullscreenElement 正是原节点，媒体实例及资源不变，并保留实际前后截图和播放状态。
- 未加载、无原生 controls、明确广告、不同实例、未知容器、遮挡或交易结构仍拒绝。全屏动作不新增普通 video_detail 覆盖资格。

### 自定义充值控件

- 标准 radio/option 继续保留；新增精确的 `.member / .card-box / .swiper-wrapper / .swiper-slide` 结构和可交互事实，不允许任意“会员/价格”容器。
- 原始档位文本去除计时器，选择样式及轮播位置不进入内容身份；`swiper-slide-active` 不作为选中后验。每个 Probe 选一个档位，并记录实际选中对象。
- 已完成对象仅从同文档/同地址/同对象键的真实后验去重，旅程事实保留 state_diff。两个档位依次操作后，旧档位不再循环补采；文档/地址不同、未验证、模型摘要、候选都不复用。
- 真正横向屏外且尚未验证的登记档位，生成 SCROLL 阶段复用原有会员横向浏览。仍须原真实前沿候选、来源签名与六段上限；遮挡不是屏外，段数不扩张，轮播移动不算选档。
- 交易文案、表单、外链、禁用/遮挡及内容漂移在动作前拒绝。受控用例验证提交计数始终为零，不据此担保未知原站 JS 的副作用。

## 通用贯通修复

- ObservationPacket 保留有界目标事实；前后序列只读当前 Capture 的后帧，纵向/会员横向序列保留自身角色与终态信息。滚动片段保留对应文档和容器事实，不增加字节、帧或元素上限。
- 模型只能选择候选 ID，不接收模型 selector/脚本。私有展示合同只由 Runtime 签发；缺对象键、错误协议/类型/操作在浏览器读或触碰前拒绝。
- 执行端再读现场并校验对象键；真实点击后无效果保留 unverified 材料，不伪造零触碰、规则通过或新预算。
- 来源恢复、逻辑身份、租约、在途资源及原支付/视频覆盖边界仍由既有流程执行，没有绕过或降低阈值。

## 剩余阻断

1. 原站未复验：仍不能确认真实支付、真实视频详情覆盖无回退，或五项 Task/Run、Snapshot、Session、Publication、Gate 与正式报告均收口。
2. 普通交易/授权/关注等按钮没有只读反馈能力；未知展开/回顶图标、自定义播放器、iframe/canvas/关闭阴影控件、无原生全屏权限的媒体不猜测点击。
3. 新的自定义会员族只覆盖已登记结构。其他结构、只有轮播 active 而无选中事实、需要后台请求才能确认价格或选择状态的控件继续缺证；不自动点击购买、拉单或确认支付。
4. 横向浏览仍受原六段上限、原恢复位置和补证尝试/冻结预算限制。没有到达的档位、超过上限的卡片或无法恢复原滚动位置不强行完成，也不刷新期限。
5. 已完成对象去重严格限制同一文档。重建会话后旧动作材料不能仅凭 URL 或卡名追认；跨恢复文档的可信旅程对齐及数据库并发贯通仍需独立验证。
6. 同版本跨端配对仍未实现。待复核、能力缺口、动作效果已验证、进度100%均不等于规则通过或业务验收。
