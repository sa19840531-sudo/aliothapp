01. 已确认的六项产品决策

1 有限自由发现

指定覆盖优先，同时保留受预算约束的自主发现。

2 局部状态归页面

局部 Tab、筛选、展开默认是同一节点的状态版本。

3 弹窗也要质检

弹窗是一等质检目标，但默认不成为业务页面节点。

4 外跳不计覆盖

外部广告落地留证、熔断和恢复，不计产品业务页面。

5 补采按规则声明

exact/equivalent/fresh/manual 四类，高风险从严。

6 有限 Shell

只允许 Brokered Wrapper，不允许模型输出进入 bash -lc。

Tab 边界修正： 组件名称不能决定页面身份。页面内“简介/评论”是状态；底部“首页/消息/我的”若改变业务合同、 路由或返回栈，仍应提升为不同 PageNode。

03. 七项优化分别解决什么、提升什么

七项优化依次补齐“能操作、知位置、能找回、认得准、截得对、点得准、证据真”七层能力。 它们不是并列插件：前一层产生的可信事实，是后一层能够成立的前提。

优化 1

受控 Playwright CLI / ADB + Skill

解决：自研 Tool 动作有限，碰到新控件、特殊滚动、新窗口或系统 Dialog 时容易中断；H5/App 专项分支持续增加。

提升：增加可组合观察和动作，缩短新页面适配周期；Skill 复用探索方法，Broker 仍统一限制 Session、Origin、Package、风险与命令参数。

验证：unsupported action 下降，verified arrival、唯一可信页面/分钟提升；Receipt 覆盖必须为 100%，越权命令为 0。

优化 2

页面状态图与树形投影

解决：Frontier 只有待执行动作，无法回答页面身份、状态版本、到达路径和质检完成度；单一 explored 布尔值掩盖证据不足。

提升：准确去重、避免重复探索、拆分页面/状态/弹窗覆盖，并为路径解释、循环检测、补采和 Completion Gate 提供统一事实。

验证：重复页面和身份冲突下降；Capture/Action/Graph 对账一致，孤立成功边为 0，Overlay 不进入业务页面分母。

优化 3

基于图路径的精准补采

解决：证据不足后只能从入口盲找、重放旧坐标或依赖脆弱固定路径；登录态、启动广告和页面改版会让路径失效。

提升：按成功率、新鲜度、风险和长度选路，每步验证并支持替代路径；缩短恢复时间、Token 与设备分钟，高风险状态无法证明等价时安全收口。

验证：恢复成功率与等价性通过率提升，平均恢复时长、路径长度和“无法找回页面”导致的证据不足下降。

优化 4

页面描述增强的 PageTypeCard

解决：同一页面因加载态、空态、文案或局部 Tab 不同被识别成多个类型；相似页面缺少正反判别依据，错误类型污染规则匹配。

提升：产品能力评估与入口页型分开；用正反信号、描述和真实可见层判断。类型与 PageNode 身份解耦，不再强迫导航型产品寻找模板页面。

验证：类型翻转、冲突和规则误匹配下降；标注集准确率/召回率提升，改判新增 PageNode 数量为 0。

优化 5

Settle Oracle 与稳定截图

解决：固定等待在慢页面上截早、快页面上空等；截图、DOM/UI Tree、文本和页面身份可能来自不同时间窗。

提升：按动作综合结构、loader、请求、视觉和后置条件形成稳定 quorum；动态页面使用 mask，转场 Witness 与正式 Capture 分离。

验证：稳定页采集成功率提升，等待和错帧重采下降；非稳定帧冒充稳定页面证据为 0，真实超时/关闭失败仍可留证。

优化 6

精准交互与外跳熔断

解决：过期 ref/坐标、广告关闭误点、滑错容器和无效果动作；误跳外部后继续探索会污染后续页面、路径与证据。

提升：动作前 rebind、hit-test 和安全内缩，动作后校验专属 postcondition；Origin/Package 越界立即留证、停止并有界恢复。

验证：stale target、no-effect、misroute 和 external escape 下降，verified arrival 与外跳恢复成功率提升。

优化 7

五层可信证据留存

解决：文件存在或 Hash 正确不能证明证据属于正确页面、动作和时间；before/after 串 Session、补采混入原证据或证据角色缺失都会误导规则。

提升：在来源和时间校验之外，显式绑定当前展示层、可见区域及遮挡；长图/DOM 派生件保留血缘，诊断改造不混入自然证据。

验证：规则和成功页面边可追溯率为 100%；孤立 Artifact、层级错配和诊断证据污染为 0。证据质量通过不等于业务规则通过。

收益判断边界： 所有“提升”都必须在 M0 记录同任务、同预算基线后，用 shadow 与真实 H5/App 对照验证。 拒绝类指标初期上升未必是退化，也可能表示新系统识别出了过去漏掉的错帧、错页或错来源证据。
最终业务结果： 在不放宽权限和证据门禁的前提下，提高单位时间/Token 的可信页面发现量，减少误点、重复探索和补采成本， 同时让规则结论更准确、可复现、可审计。

07. 弹窗：独立质检目标，不混入业务页面

为什么必须保留

广告、充值/支付、登录/凭证、更新、公告、隐私、错误等都需要识别；核心是能否安全解除阻断，不只是补种类。

为什么不进业务树

多数弹窗不改变业务路由和返回栈；把每层弹窗建成页面会让路径、覆盖和恢复全部失真。

如何两者兼得

禁止为了继续探索自动确认： 隐私同意、系统权限、购买、登录提交、删除和发布。此类动作按 R2/R3 策略处理。

覆盖必须分别展示业务页面、页面状态、Overlay 类型、Overlay 规则实例和有效规则覆盖， 不能把它们简单相加成一个“总页面数”。

09. Playwright CLI 与 ADB Adapter

H5 / Web · Playwright CLI

  • 每个 Surface Session 对应一个受管命名会话和临时 Profile；
  • 首批只开放 snapshot、screenshot、trace、console/network 摘要；
  • 低风险阶段再开放 click ref、scroll、back 和 wait；
  • ref 绑定 capture epoch 与 snapshot hash，动作前重新 rebind；
  • 新 Tab、跨域 Frame 和 Popup Window 都形成显式事件；
  • 现有 Python Playwright Driver 保留为 fallback。

App · ADB / Official Adapter

  • 允许 screenshot、UI Tree、foreground identity、tap/swipe/back；
  • 目标优先级：Accessibility/UI Tree → 结构 → 视觉框 → 临时坐标；
  • 坐标只在当前 Capture epoch 有效；
  • 迁移前先补齐旧 Driver 解析入口的本轮 runtime observation 绑定；
  • 每条命令绑定 serial、云手机 env/profile 和 Package allowlist；
  • 设备重连和 Lease 由 Orchestrator 负责；
  • 离开被测 Package 立即进入外跳熔断。
灰度顺序： 先让新 Adapter 只观察并与现有 Driver 比较；再开放低风险动作；只有一致性和收益指标通过后， 才逐步缩减旧的页面/站点专项分支。一个 Session 绝不允许两个执行器同时写动作。

已核验官方 Playwright CLI提供请求查看、截图、快照、标签及脚本等命令； 工具有命令 ≠ 当前安装版本可用 ≠ Agent 被授权。启动时记录版本/能力快照，网络观察默认只读，不开放 mock/route 改写自然证据。

L4 · 外跳单独标签/进程，只截图条件采纳自然 popup 优先保留主面；已知安全 URL 可旁路观察；JS/POST/Activity 不假定可克隆，回源循环熔断。减少破坏主页面和重复关闭；同时保留来源/真实点击证据。

S10 · 规则判断锁定规则版本、scope key、合法证据角色、封存 InputSet。RuleExecution 或 EvidenceRequest；合法复用带来源。fail / 不足 / 人工 / 技术错误分开；Judge 不碰设备。
S11 · 补采回路证据需求、Live Session、预算、图路径、规则等价约束。逐边验证 → Equivalence → 新 Capture/InputSet → 新尝试。不可恢复的一次性/高风险状态明确不足或人工；不覆盖旧结论。
S12 · 最终收口停止新动作，排空 Frontier/计划/外部面/规则/补采，冻结报告输入。同 Run/Epoch 的 Gate、规则分布、分维度覆盖、资源释放结果。预算耗尽不等于产品无功能；Gate 故障写 unavailable，不能借用旧 Run 的通过结论。

动作与异步 Judge 如何接起来

  1. 当前 Capture + Presentation + candidate epoch 创建意图；Session 单写所有者负责每次设备动作。
  2. Broker 校验范围/预算/风险，持久化 planned，再执行、记 Receipt、观察并验证后态。
  3. 先落 Artifact，再提交拥有者事实与 Outbox；数据库可重复投递不等于 UI 可重复点击。
  4. 静态规则证据齐备可先判断；关闭、点击有效性等必须等待 after 或合规时间序列。
  5. Judge 仅声明缺证，Orchestrator 才能在 recovery 队列按图恢复与补采，重新检查授权和等价。
  6. 崩溃后先查命令收据与当前状态；未知副作用禁止盲重放。恢复属于可验证补偿，不是原子回滚。
  7. 停止新探索后给证据/规则/外部面留独立收口预算；晚到结果按 finalization epoch 校验。
  8. 报告固定输入可幂等重试；失败或取消也释放租约并报告释放结果，不能用“已释放”代替 Gate 验收。

四个具体场景

A · 导航型首页 + 启动广告

先记录启动 Overlay，不伪造首页；前态后安全关闭，才识别导航/广告列表。详情/个人中心未找到先 unknown，菜单入候选。素材静态结论可依合同复用，各广告位仍保留交互覆盖。

B · 版本更新“确定 / 取消”

识别 update 而非广告，“确定”可能安装/重启。记录前态后仅执行获准取消；若不消失且规则要求可取消则 fail，若定位证据不足则补采/人工。不改 DOM 来宣称关闭成功。

C · JS 原标签外跳

无可靠 href 就不猜 URL；获准真实点击后留转场与落地，有限回源。相同启动弹窗链重现触发熔断；之后若用 URL 旁路，仅证明落地内容，业务覆盖不增加。

D · 滚动找按钮 + 长页补采

有界滚动后重观察/rebind，点击并验证新页面真实可见。每个长页原帧保留顺序/时间；下半段缺证时图恢复→等价校验→新帧→新 InputSet 重判，断档不得靠拼图抹平。
