# H5 整段会话互斥与视觉拒绝审计

## 范围和结论边界

沿当前需求分支继续修补证、主探索、Probe 和会话关闭之间的公共边界。保留此前未提交修改；无新迁移，不改前端、Gate、风险或预算，不重载、重跑站点任务、发布或操作历史证据。后台依赖型充值缺只读契约，继续保留阻断。

已确认并复现两类会话问题：逐动作串行未覆盖完整旅程，以及取消后没有可靠排空子操作。真实 Chromium 回放证明切页可以引起视觉来源过期，但不能据此将所有历史视觉拒绝归于竞争。扩大回归另捕获了白底破图帧，拒绝本身符合失闭要求，来源采集为何缺画布仍未定位，不能称全部根治或可发布。

## 已复现及修复

### 1. 逐命令串行不等于整段互斥

- 原命令锁只覆盖单次动作/采集。补证读取来源、恢复、发布和 Probe 的相邻动作之间，主探索仍能取得同一会话；原帧可因此在点击前过期。
- 先用两阶段复现主探索插入，以及所有者取消后子动作继续运行；真正行为失败记录在 `/tmp/h5-journey-behavior-before-20261013.xml`。缺模块的初始失败不算行为证据。
- 公共 H5 旅程门禁接入主探索、补证消费和 Probe 生产组合根。补证先读不可变原Capture归属以确定会话，实际当前现场读取和恢复动作在旅程内进行。根工作不能继承另一根的旅程；内部动作可继承同一任务的有效旅程，但每次动作仍领取原命令序号和租约，不复用一个命令许可。
- 同进程用会话局部锁；不同执行器通过独立控制连接持有 PostgreSQL 会话级咨询锁。业务连接池不被整个旅程占用，不在长业务事务中等待浏览器。不同会话及非 H5 命令不做全局串行。
- 恢复会话的随机编号不决定合法性。嵌套恢复只尝试取得目标锁，目标被另一根工作占用则明确拒绝，避免两个旅程互相等待。退出后的继承子任务被作用域失效标记拒绝，不允许偷偷重新取得动作资格。

### 2. 关闭必须看到仍在途的旅程

- 原关闭条件只看命令租约等持久事实，旅程两步之间可能没有命令租约。隔离 PostgreSQL 先复现两种封闭入口及 begin_draining 提前进入，3项失败记录在 `/tmp/h5-journey-pg-reproduction-20261013.xml`。
- H5 关闭就绪增加旅程占用事实；begin_draining 和两种 seal 在原事务内尝试同一咨询锁，仍有旅程就不能封闭。原动作、Capture、补证、Manifest 等排空条件不删减；取得锁也不代表业务通过。
- 控制连接意外丢失时取消旅程所有者，拒绝后续动作和普通成功。正常退出先移除断连监听，不能把正常关闭误报为丢租。

### 3. 重复取消能打断异步清理

- 原 H5 外层取消未排空 guard.run 的子操作；首次修正直接 cancel/await 后，又补第二次取消的反例并真实失败。第二次取消会传入子操作 finally，清理未结束就释放会话。
- 首次修复前失败保留在 `/tmp/h5-journey-repeat-cancel-before-20261013.xml`。追加有续租和无续租路径后，无续租路径仍失败，记录在 `/tmp/h5-journey-stage-repeat-cancel-before-20261013.xml`；不是仅以正常取消反例证明全部正确。
- H5 操作等待与取消排空使用屏蔽传播的等待，子操作只发送一次取消，重复所有者取消不能中断其异步清理。真正退出后仍传播取消，不记普通成功。所有者、丢租等待和续租任务各自清理，不修改 App/Web 续租实现。
- 首次续租和等待旅程均消耗原最早冻结截止；Work、Request 和剩余墙钟取最小值，不刷新180分钟、80动作或200物理调用。丢租时即使仍在锁队列也退出，排队期间不调用模型或浏览器。
- 主探索已开始尝试也不能将明确旅程截止/失效强转 retry_wait；Probe 截止沿原有非重试截止分类结算。请求结算继续核对有效围栏，旧执行器不能释放新 owner。
- 已证明不变的缺口在建立恢复运行时之前止损，避免先建立运行时再判断无新增收益；原完整证据、合同和最新版本验证不变。没有真实调用分布，不能宣称省下具体 Token、费用或次数。

## 视觉点击：事实、推测及未验证项

### 已确认事实

1. 同一受控真实 Chromium 来源卡片在两步间被主探索平移，会得到 `VISUAL_TARGET_SOURCE_STATE_STALE`，零点击；整段互斥后主探索须等点击和旅程退出，点击只执行一次。PNG、DOM 及动作事实保存在 `/tmp/h5-visual-interleave-20261013/`。这是会话竞争的可复现机制，不是原站故障全部归因证明。
2. 扩大回归真实捕获另一失败：`VISUAL_TARGET_OBSTRUCTED`、match_score=1.0，来源和当前PNG同哈希 `04d6522f25e1ece5103c9169cd7845f1076f1987f046f0fe34b25d73fd0fac92`。图像240×320，只有白底和左上角破图图标，目标区域没有测试所需卡片。
3. 哈希相同和模板满分只证明输入帧/模板的某种一致性，不能证明目标存在或可点击。没有降低唯一性、锚点、局部内容或漂移阈值，没有增加重试、延迟重放点击或相同哈希直通。
4. 实际失败PNG字节与哈希固化于 `services/api/tests/fixtures/h5_visual_rejected_frame_20261013.json`；相同测试的已加载画布帧作为反例，严格门禁接受有效卡片、拒绝破图帧。首版 fixture 读取临时目录已被 pytest 保留策略轮换，只修夹具为之前捕获的原字节并核对 SHA，不作为新业务问题统计。
5. 原失败没有保存现场DOM，无法证明当时DOM仍是画布，也不能证明页面确实被另一操作替换。当前测试补存来源DOM、URL、画布尺寸/状态/像素、初始PNG、每次真实解析帧/哈希和拒绝码，保持原解析结果和一次点击断言。

### 合理推测，但不作已修复结论

正确页面取到了错误/尚未绘制的位图，或受控页面内容被替换，均可能解释白底破图；仅保存的PNG不能区分浏览器渲染、页面导航、测试污染和采集异常。不能按破图图标猜网络站点故障，也不能以一次或多次复跑转绿判定消失。

### 仍未验证

原白底破图的生成根因；新链路在原站真实负载下的主探索/补证竞争；支付展示、真实播放器时间/播放与稳定后加载帧、普通正式Publication、Gate和报告绑定。新回归不是原站验收，不能承诺覆盖没有回退。

## 剩余风险和阻断

- 所有者协程可取消，不代表已经送到浏览器/CDP或第三方的物理操作可撤回。底层吞取消、阻塞事件循环或异步清理无限挂起时，只能保持未排空，不能谎称收口；本次没有用清理超时来强放会话。
- PostgreSQL 控制连接异常释放咨询锁后，旧执行器已发出的物理调用仍可能返回。作用域失效及原命令/写回围栏阻止后续普通成功，但这不是跨进程物理调用强撤销保证；连接断开与真实浏览器在途同时发生的原站验收仍未覆盖。
- 独立控制连接不耗尽业务池，但增加数据库连接需求；并发上限和长时间运行容量尚未实测，不能宣称无额外运行成本。
- 排队消耗原期限，可能减少该请求后续可用时间，这是冻结合同边界，不提高预算或刷新截止补偿。互斥不保证已漂移目标可恢复，身份和目标失败仍明确保留。
- 无只读契约的后台充值继续阻断；私有不透明图库和原子旧帧能力缺口不回填历史来追认通过。真实支付和视频覆盖未复验，待复核不能算通过。
- 白底破图来源尚未查清，继续作为剩余阻断，不以绿色回归批准发布。
