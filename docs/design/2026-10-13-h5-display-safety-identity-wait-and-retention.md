# H5 展示补证安全、身份、等待与裁剪修复

## 范围和来源

- 只修改 H5 通用展示补证与快照保留链路，不改 Gate、规则阈值、物理调用额度、动作额度或冻结截止。当前 API/Worker/前端、验收任务、数据库和历史证据均未操作；未重载、重跑、合并或发布。
- 保存的 031 会员外壳来源为 `services/api/tests/fixtures/h5_031_payment_20261012_103747.json`，Task 为 `0456e777-7769-4433-a501-9671e28b7065`，Run 为 `8451a9db-e050-49c3-8a2e-b1208d779612`。本次内层卡片、回调和动画是受控重建，不能宣称完整回放了原站脚本。
- 上轮审查的六个最小 DOM 复现确认：自定义点击可能写后台；Swiper 状态进入身份导致重复操作；延迟选档和平滑回顶被立即判失败；克隆预览仍按原缩略图定位；93 个原始目标裁为 80 个时档位消失。
- 这些复现和反例已保存为 `services/api/tests/test_h5_probe_display_safety_regressions.py`。问题表原行、原文和截图定位沿用 `2026-10-13-h5-sheet-probe-contract-repair.md`，本次没有读取或写回 Google 表。

## 1. 充值只读安全

### 已确认根因

登记 DOM、排除表单和提交按钮只能证明候选结构，不能证明不透明 JavaScript 回调不会发送订单请求。此前“本页展示”字段不构成后台只读保证。

### 修复

- H5 首个业务文档之前安装通信普查；选档之前要求单页面、单框架、无已知活动通信、无在途 HTTP、无 Service Worker，以及已安装的普查证明。未知运行环境或未及时安装时在输入前拒绝，不回退普通点击。
- 选档封闭当前文档的 HTTP/新 WebSocket 出站，并封闭标准 Fetch、XHR、Beacon、Worker、WebTransport、RTC 和 Service Worker 注册入口。当前文档返回补证后仍保持封闭，避免迟到的定时订单请求逃过短观察窗口。
- 出站尝试已被观察时，动作效果留未验证；不会因本地选中样式出现而记效果成功。原额度和模型调用路径不增加。
- 仅可信 GOTO 的精确地址及确实不同的新文档时钟可以解除封闭；同文档跳转、SPA 状态改变或旧文档恢复不能解封。新文档子资源请求也复核该条件，避免提交事件与元数据请求竞态。

### 测试与边界

内存后台验证 POST、GET、Beacon、弹窗、XHR、图片请求、缓存 Fetch、Worker 与动作返回后延迟请求均不能生成后台订单；缺隔离、框架、第二页面、已使用 RTC 和在途请求在点击前拒绝。正常本地选档可观察，可信新文档视频路由及元数据读取可继续，同文档跳转不解封。

这里是受控浏览器能力约束，不是针对恶意页面规避原生接口、未建模协议或浏览器漏洞的完整安全沙箱。需要后台请求才能选档、在 SPA 中继续依赖后台读请求、旧页面恢复或不兼容运行环境时仍有能力缺口。不能按交易接口名称建立猜测白名单，也不能凭结构把未知回调追认为只读。

## 2. 轮播身份去重

- 登记档位身份只移除固定展示状态：selected/active/checked 和已知 Swiper active/prev/next/visible 状态；自/父/祖先类令牌按稳定顺序参与摘要。
- 原档位文本、价格、选择器、业务类和资源仍参与身份。价格变化、档位变化、来源节点替换必须作为新对象复核；不能按轮播位置或同文案永久去重。
- 浏览器串联验证两个档位各点击一次后不再重复选择；三个业务变化反例仍能产生新目标。同地址、同文档及真实动作后验的既有去重要求未改变。
- 去重复用的充值后验还必须证明已隔离且观察到的出站拒绝数为精确整数零。缺字段、有出站尝试和布尔伪零不得追认为已安全完成；原历史制品不修改。

## 3. 动作后等待

- 一次实际输入后，在原单动作期限内最多读取 12 次快照，反馈观察窗口最多 1.2 秒；至少两个连续一致的实际效果快照才能记效果已观察。等待与读帧不重放点击，不刷新截止。
- 点击发生后立即记录“已执行、效果未验证”，再读取后帧；取帧或效果检查被取消时也不能伪装成未执行。
- 延迟 350ms 的选档、平滑回顶、无效果及点击后超时均有反例；只有实际同容器位置、对象、地址和文档满足原条件才能记录效果。
- 超过窗口才反馈的控件仍留未验证，不无限等待，不把焦点或样式变化当业务反馈。动作效果不是规则通过或正式业务覆盖。

## 4. 预览配对

- 同一文档用 WeakMap 登记 Vant/Element 预览根身份。前帧包含隐藏旧根，后帧和压缩包保留根列表及截断标志，不插入业务 DOM 属性。
- 原节点真正放大时仍需原加载/可见/完整视口面积要求，且不能同时出现歧义新预览。克隆节点则要求唯一新根、同源已加载图片与原全屏几何要求；不再强求原缩略图选择器必须全屏。
- 两个重叠根、错误资源、旧隐藏根复用及未加载图保持拒绝。原生视频继续核对播放器实例及真实 fullscreenElement，不用图片放大冒充视频覆盖。
- 高低清资源 URL 不同、未知图库根、已有根复用以及普查截断目前不能建立完整配对，仍待补受信事件关联，不能降低面积或身份阈值。

## 5. 目标裁剪

- 原始快照保留与 Observer 二次裁剪同时照顾已登记只读档位、展开和回顶控件；安全字段、广告/导航标记及预览根血缘贯通。
- 原 80 元素与字节限制、模态优先级和命中检查不变。优先保留不是授权：现场遮挡、禁用、导航/广告、提交与异属目标仍拒绝。
- 90 张图片拥挤场景串联真实快照和 Observer 压缩，验证档位不再在 93→80 时消失。任意数量目标仍不保证全部保留，不能无限扩大材料或只保留业务目标而丢弃清障证明。

## 验证记录

- 首轮新增用例先运行：11 失败、8 通过，其中包括缺少只读隔离实现的预期失败；然后修生产链路。
- 中间扩大回归 1,418 项通过；展示专项 40 项通过。旧选档安全复用反例先得到3失败、6通过，再修复并补布尔伪零反例；该影响范围169项通过。
- 所有代码修改完成后的最终扩大回归为1,427项通过、零失败、零跳过，耗时208.35秒，仅两个既有 Agent Framework 实验性提示。范围包含完整 `test_page_capture_tool.py` 和29个 H5、Observer、规则、Runtime、收口、预算及安全专项文件，不是整个仓库的完整测试套件。
- Ruff 与差异空白检查通过。全部浏览器用例在独立 Chromium 中运行，外部网络被中止或内存响应，不操作当前任务或生产数据库。
- 回归覆盖已有支付横向取证、媒体实际状态、滚动序列、正式发布准入、规则判定、预算准入、恢复、去重、补证及收口路径；这不是新一轮站点实测，不得证明“支付和真实视频覆盖绝无回退”。

## 剩余阻断

1. 后台依赖型选档、SPA 后续后台读取及不兼容运行环境仍须安全拒绝；需要隔离分支与可审计恢复合同或明确后台只读接口证明，不能临时放行未知订单请求。
2. 旧预览根复用和跨资源清晰度配对缺少受信对应关系；暂不能补算媒体放大成功。
3. 未在当前服务加载，也未跑真实站点任务；支付展示面板、真实播放器时间/播放证据、稳定帧、Publication、Gate 与正式报告绑定仍需另行授权验收。待复核、能力缺口和隔离测试通过均不算业务通过。

## 续修：隔离恢复与预览血缘

### 证据与复现边界

- 用户明确回复后台依赖型充值暂无已确认的只读接口定义、Task/Capture请求响应记录。既有031保存资料仅有DOM外壳，不足以证明任何后台调用不会创建订单。不按 GET/POST、catalog/read 名称或响应内容建立白名单，不使用缓存回放响应冒充原站选档。
- 本次用真实 Chromium 最小DOM复现旧隐藏预览根复用、原生 srcset 高清预览、不同 picture 分支和补证文档隔离。它们是代码行为案例，不是新获取的原站运行证据；源资料与模拟回调分别标注。
- 首轮新增测试14失败、9通过，其中包含尚无隔离上下文字段的预期失败及一个重复ID测试夹具断言问题，不把全部失败数声称为原站故障数。后补主探索支付延后用例先得到2失败，再修实际消费链。

### 修复边界

1. 主探索阶段，具备新会话恢复许可且逐请求回放预检通过的支付选档先延后，不在主SPA中封闭通信。原请求、尝试及状态保留，独立恢复阶段继续消费而不是再次延后；未证明路线、原会话强绑定或高等级来源要求不强行转低等级。
2. 已有独立恢复器装配下的活来源展示也能另建会话。上下文读取必须持有真实有效租约，核对Task/Run/Epoch和原会话，目标会话必须不同；活来源不伪造为已关闭。恢复和后续Probe沿既有预算、截止、等价和证据等级，不额外增加额度。
3. 旧根复用要求唯一aria-controls实际根绑定、完整前后根身份普查、实际隐藏转可见、原源关系未漂移且唯一已加载全屏图。相同图片但无绑定、重复ID、另一个根、已可见旧根继续拒绝。
4. 高清图只从原图明确声明的有界原生srcset族配对，picture只选实际资源所属的有效分支。最多8项、2048字符声明，超过界限不推测；HTTP资源不去参数、不按文件名匹配。声明摘要参与图片目标键并贯通Observer，动作前后复核。两帧、原85%视口面积、真实命中和加载条件不降低。
5. 后验补记原/后选择器、原/后资源及实际预览根身份。不是仅改截图标签，也不替代Rule Judge结论；原生视频仍使用原播放器实例、真实全屏与播放时间证据路径。
6. 后补旧根与新根同时显示的反例先复现失败，再修复歧义判断；两个稳定后帧还必须绑定同一实际根实例。持续替换节点但保留相同选择器、图片和几何的反例保持未验证，不重放点击。

### 当前验证与剩余阻断

- 展示、恢复与检查点影响范围219项通过；独立新建PostgreSQL实例由空库迁移到head，租约/跨平台/过期/Epoch及旧关闭恢复链38项通过，零跳过。最初PG失败是测试夹具未提供活会话current_capture_id，补齐夹具后重验，并非放宽生产读取。
- 所有生产修改完成后的最终扩大回归为1,666项通过、零失败、零跳过，耗时230.92秒，覆盖36个H5、Observer、规则、Runtime、预算、补证、恢复、支付及媒体专项文件，不是全仓测试套件。隔离数据库最终重验38项通过、零失败、零跳过，耗时3.49秒；两组均只有两个既有Agent Framework实验性提示。
- Ruff与差异空白检查通过。最终测试记录保留在 `/tmp/alioth-h5-probe-db.mSSV2Q/final-regression.xml` 和 `/tmp/alioth-h5-probe-db.mSSV2Q/final-postgres.xml`。仅本次新建的临时PostgreSQL实例已正常退出，日志保留；当前服务、验收数据库及历史证据未操作。没有新增迁移、重载、任务重跑或发布。
- 后台依赖型充值尚未解决：无可审计只读契约不能放行未知调用；返回本地选中样式也不能算安全效果通过。未实现猜测白名单或模拟订单响应。
- 要求原活会话/原原子状态或高等级证据的SPA补证，不能自动转独立低等级回放；无可信恢复路线也不能延后到另一页面补算。当前服务未重载，这些现场能力仍待验证。
- 未声明资源族的框架私有高清列表、无唯一控制绑定的旧预览根、声明截断仍保留证据不足；不能用更多盲目重试或预算掩盖。
- 延后恢复仍受原剩余动作、物理调用及180分钟截止约束，不保证预算耗尽后还能补完。未进行真实任务重跑，不宣称支付和视频实际覆盖无回退；待复核不算通过。
