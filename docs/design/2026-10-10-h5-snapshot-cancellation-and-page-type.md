## 事实与根因边界

### Snapshot 请求协调

历史 204 离页异常时报告 `pending_captures=0`、现场 Work 和 Active Session 请求为零，但仍有两条 Snapshot 请求。两条请求目标不同，不能用一条可恢复请求代表另一条。后续请求终结也不能反推报错时的精确租约状态。

代码存在两个不同用途的读取：完整未结请求前沿，以及允许领取的未占用请求清单。旧检查点延后判定复用领取清单和新 Probe 准入，可能看不到已占用请求，或因其他 Probe 阻止领取而无法完成只读恢复预检。这是可复现的通用合同混用，不等于已经证明历史两条请求当时都可安全延后。

处理：

1. 增加 H5 检查点专用完整清单，读取当前 Task/Run/Epoch 下 pending/routed/running 的 Snapshot，不用重试就绪、有效期或未占用过滤截断前沿。
2. 完整数量必须与检查点数量一致；缺项、重复、错误 Task、混合 Epoch 或超出现有 50 条边界均拒绝延后。
3. 逐请求验证原恢复合同；已持租约、routed/running、关联在途 Probe 或成功但尚无 Supplement 的 Probe 仍阻止离页。即使租约到期，也不由只读检查点擅自夺取许可。
4. 新 Probe 的领取准入保持原实现；不可恢复请求仍沿原租约消费与结算路径处理。延后不等于完成，最终关闭前不得延后 Snapshot。

因此本次修的是“前沿读取与逐请求恢复协调”，不是取消所有 Snapshot 离页屏障，也不保证所有来源不可达问题都消失。

### 取消检查

历史 102/YC003 出现持久取消读取期间连接池归还/reset 超时。这个异常不能证明用户取消。旧方法把查询结果与连接归还放在同一个异常边界，已成功查询的布尔结果也会因退出连接上下文失败而丢失。

新增 H5 专用读取：只有同一 Run 的查询已经成功返回严格布尔值，且随后发生 `TimeoutError`，才记录连接归还异常并保留本次事实。获取连接失败、查询失败、事实缺失、其他异常仍失败关闭；真实取消返回 True，`CancelledError` 不吞掉。不是缓存旧的 False，也不重试未知动作；后续动作原许可和取消门禁不变。

该入口只由 H5 V2 分支选择，App/Web 继续原读取。连接池故障本身没有因此修好，日志仍须保留；查询成功到下一动作之间也不是原子取消保证。

### 页型误分类

历史 128 Capture `054c5d78-938c-4896-8f76-c2156e9ed3d3` 的阅读详情 DOM 含开始阅读、章节列表、加入书架，模型识别为 `content_detail`，旧路由纠偏却按详情地址推成 `video_detail`。实际没有播放器主体，不能把这个旧标签当作真实视频覆盖。

只读重放原 DOM，确认旧路由返回 `video_detail`，新增 H5 路由证据校验拒绝该提升，基础结果保留 `content_detail`。原历史制品未编辑。

处理：

- H5 模型已经满足现行页型识别指南的必需正信号、混淆排除和负信号要求时，不再由弱路由推断覆盖它；不是无条件信任模型。
- 模型失败或不满足指南时，路由推断视频详情还必须由现场可见播放器主体结构支撑。复用原结构识别合同；隐藏模板、广告播放器、活动弹层不能代替基础视频详情。
- 可信到达、清障、支付和设置等原结构证据路径不移除；Web/App 未启用 H5 识别指南的路径保持原合同。没有改页型目录或加入站点特例。
- 非标准播放器且模型识别也失败时，保守路由兜底仍可能不足，需要后续真实证据再设计，不凭 URL 补成已覆盖。
