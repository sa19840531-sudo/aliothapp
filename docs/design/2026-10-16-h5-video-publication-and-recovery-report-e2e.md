# 普通视频 Publication 与跨会话流程报告

## 范围与完成边界

本轮仅修后端通用链路并进行隔离验证。不修改当前服务、真实任务、历史证据、原问题表、风险 Gate 或模型预算，不重载、重跑、提交、发布。后台充值没有只读契约仍阻断；私有播放器与高清资源没有对应关系证据不猜测。

隔离 PostgreSQL、受控恢复执行器/运输端口、禁网 Chromium 与真实原站验收是不同证据。本轮的库内正式 Gate/报告闭合不代表五站任务已通过，也不证明真实模型的 200 次预算足够。

## 确认的遗漏

1. 普通 H5 Publication 原来只校验 `page_inspection_ready`，没有原生已呈现帧及连续窗口合同。几何、`readyState` 或截图存在均不足以证明视频已加载。
2. 检查点样本在主截图之后采集，后续样本不能追认旧主截图。普通视频必须用最后实际观测 PNG 作主帧，并核对同一 Capture 的附件摘要、唯一主帧标记。
3. `checkpoint_observation` 已进入采集/读取代码，但数据库附件类型白名单和需求词汇未注册。隔离整链实际落库报 `ck_qc_evidence_artifact_type`，不能靠单独读取器桩测试结案。
4. H5 正式封存推进 Epoch，流程证据/InputSet/恢复属于来源 Epoch。原报告绑定要求同一 Epoch，会误拒合法封存；封存后的只读复核也不能因此授权旧 Epoch 继续动作。
5. 新普通采样若只看 `video.visible`，屏外节点、底部广告视频会夺走非视频/支付展示采集；新的最终 UI 若不保留逻辑面参数，会丢失后继探索身份。
6. 广泛回归出现首次播放采样缺帧，新增反例确定复现：观察器注册后同步读取必然可能没有回调，先前DOM播放时间还可能早于原生帧事实。这是采集时序缺口，不通过重复运行转绿结案。
7. 同事务多个PNG的创建时间相同，按时间/UUID取首张可能取到旧样本。可信UI读取器必须优先对应最终主帧；隔离PG使用不同像素、同时间、刻意反向UUID验证，并保留无主帧时非视频原行为。

## 实现

- 复用稳定后加载帧测量：两次原生状态、真实 PNG、来源 bracket、媒体实例、资源代次、解码尺寸、媒体时间与视频区域摘要。暂停要求区域像素稳定，播放要求呈现计数前进；仍是有界顺序观测，不宣称原子截图或整页像素冻结。
- 普通可见正文原生视频在原采集内自动采样。与检查点共用同一次窗口，不重复开会话/导航/点击/模型请求。完整样本存独立`checkpoint_observation`附件，不塞进UI扩大快照预算；最终主截图、UI、DOM和文本来自最后窗口，保留原逻辑面开关。旧预备视觉帧不冒充新主帧。
- 原生首次播放帧最多共享200ms只读等待，超时取消临时回调并保持缺证；不主动播放/seek，已暂停无呈现记录不补造。媒体时间、解码尺寸和seeking随原生帧同次读取，CDP显式等待Promise，原2秒总界限不变。
- 非视频页不要求视频合同；明确广告、隐藏、屏外视频及弹层背景不接管普通正文视频采样。真正 `video_detail` 无合同仍不得进入普通正式质检；加载/截断/遮挡/多实例歧义保持不足。
- 采集 metrics、增量/最终交接读取器、Publication领取和流程输入选择均核对视频合同；正式数据库路径另核对实际截图附件和唯一 `h5_video_primary`。附件角色只索引材料，不替代 Manifest 的质量裁决。
- 新迁移 `20261016_0138` 只补注册 `checkpoint_observation`，保留所有既有 App/Web 类型。有样本时拒绝降级，不删除材料。本轮仅在自有隔离库应用，业务库尚未应用。
- 报告保存 `source_finalization_epoch` 和封存 `finalization_epoch`。仅封存 Gate、Coverage ID/hash/Task/Run/来源 Epoch 均匹配时，报告可以只读复核旧流程输入与恢复链；普通 Judge/规划/准入仍不允许复用旧 Epoch 动作。

## 隔离整链

`第一检查点 → 已关闭来源会话 → Snapshot请求/租约 → 真实Restoration账本和等价评估 → 新会话动作/Capture/Manifest → 第二检查点 → InputSet → 通用Judge → Completion Gate → 报告正文 → 封存后再次绑定`。

恢复动作与图形/视频状态由受控端口产生，JSON/PNG确实存储并由生产可信读取器验证摘要、归属与裁剪。覆盖快照由领域代码构造，受控运输确认当前事件，生产 Gate 和报告仓储不替换。隔离工作和候选结果按实际受控产出排空，正式结果仍为 `quality_outcome=unknown`，不冒充原站全项通过。

反例包括缺失恢复动作、仅同会话许可、旧 Epoch、晚到失败 Manifest、待复核、报告恢复引用篡改、无 Gate 的旧周期读取和封存后新动作。正式审计对象留在自有测试库，不绕过不可变约束删除；该测试库的资料不是业务库历史。

## 验证与剩余风险

实际输出保存在 `docs/validation/2026-10-16-video-publication-recovery-e2e/`，包括红例、夹具修正失败、数据库隔离检查失败和后续结果。最终范围/计数见该目录 README，不叠加有重叠的用例数。

- 没有原站任务、真实 SDK/模型/CNY、Redis实网运输、私有Canvas/WebGL播放器、iframe/shadow播放器或180分钟并发验收。本轮不承诺真实支付/视频覆盖没有回退。
- 首次已暂停但没有原生呈现记录的播放器保持未知，不自动播放/seek凑材料；多业务媒体无法唯一绑定仍阻断。
- 单次截图不是原子观测；高度动态资源在极短窗口切换、字幕/控件覆盖的精细像素归属仍有边界。
- 普通定时/滚动序列没有这一普通帧合同，不自动补算普通视频覆盖。既有正式材料不回写升级；历史报告只读取已冻结正文。
- 普通视频主帧是视口PNG，明确保存`full_page=false`，不冒充整页截图或整页稳定。未来全页视频证据需另有实际全页帧绑定；本轮不把视口主帧补算为全页覆盖。
- 后台充值没有只读契约继续阻断，不猜接口白名单；私有高清没有明确资源配对不猜URL。
- 最终广泛回归4386通过、1失败、7跳过，不报全绿。失败保存的源DOM无video、动作前Canvas已context_lost，三张破图逐字节相同且等于10月13日旧失败帧；视觉拒绝是保护，不是原生视频采样制造的目标丢失。GPU/压力/生命周期具体触发未证实，保留失败材料与阻断，不单独重跑转绿或擅自扩大本轮修复范围。
