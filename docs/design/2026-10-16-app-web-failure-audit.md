## App 根因

`3cbd3761` 明确移除旧包名 `dark.wwcskrpojs.ebjhyebjbl` 及模糊前缀解析，当前产品
改用 `com.hj.ttthree`；同时改动栏目顺序、第一片点位和漫画目标合同。
旧测试把通用候选优先级、旧漫画目标与当前 Airtest 点位混在同一隐式路由中。
未知包携带 `app_curriculum_progress.playbook_id=hjll` 也不能证明它属于该产品。

22 项测试的冻结特征只提取自 `0f60624df85a3f8f3ff1542c958e80c4e5f579d3` 的
`docs/data/hjll_ui_tree_features.json` 中 `home_top_category_tabs` 与 `bottom_navigation`。
夹具位于 `services/api/tests/fixtures/app_home_top_pre_orchestrator.json`，仅指定用例注入
特征加载器，不修改生产路由，不作为现役产品/原站验收。原断言不删、不放宽。
另用旧包、相似前缀、错产品课纲反例验证不能启用产品点位；顺序反转验证夹具恢复。

当前产品另有真实预算问题：优先清障分支先调用像素关闭候选，早于原本带八轮上限的
普通关层选择器；固定点降级只检查同层次数，漏检连续无效动作次数。
修复共用既有八轮检查，优先分支与两种候选入口都必须遵守它；不增加重试或总预算。
这只停止该确定性关层路径的新点击，不证明 Task 已收口或 Gate 通过。

反例确保第 0/1/7 次仍可关层，8/9 次停手，其他产品不套用该产品上限；弹层已经
消失后的旧计数不得挡住后续补证。测试初稿曾同时写入 `popup_visible=false` 与
`dialog_kind=ad_popup`，且课纲尚未完成却期望先做广告补证；这些失败均保留。
最终分别验证无弹层且课纲完成可补证、矛盾弹层事实仍需观察，不改生产策略凑断言。

## Web 根因

`a9d582e6` 在 v11 引入可选集合页。`107f71a9` 升级到 v12，此后目录继续升至 v18，
但 `WebCoverageSnapshot._canonical_types` 仍仅在目录恰等于 v11 时接受集合页。
新任务入口会冻结集合页到 optional 分区，快照创建却以七类目录拒绝它，形成收口阻断。
即使集合页没有实际出现，仅 optional 分区含它也能触发错误。

修复按实际冻结目录版本调用现有目录解析函数，再取业务页型交集；v11–v18 保留集合页，
v8–v10 不被新目录扩充，旧协议兼容保持原行为。未知正式版本明确拒绝，不偷偷解释成
旧七类。生命周期、充值和其他补充证据不进入业务分母。

仅在新合同反例验证后，入口测试增加 `collection_page=not_observed`；首页必检断言不变。
集合页仅可选且未观察不阻断覆盖；实际发现但未覆盖仍为缺口；覆盖后才满足该页型。
Coverage complete 不代表规则通过，待复核不算通过。本轮未更改 Gate 或规则预期。
