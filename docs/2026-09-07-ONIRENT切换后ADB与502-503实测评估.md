> 目的：回答「换成 ONIRENT 后，还会不会因为 ADB 问题造成 Capture／会话 502／503」

| 问题 | 结论 |

**一句话**：换成 ONIRENT 后，就本次两包正式质检长跑证据看，**不会再因旧的 MoreLogin 公网 ADB 问题打出成片 502／503**；通道健康。

## 2. 背景：以前 502／503 从哪来

历史规则（`docs/专项能力与高频回归规则.md`）已沉淀：

1. **Capture 连续 502**（2026-08-29／08-25）  
   - 主因是 **MoreLogin 公网 ADB 通道／设备侧**，不是 Docker。  
   - 表现：`screencap`／pull 失败 → Official Capture 表现为 502／TIMEOUT。

2. **同机连跑第二颗 APK → 会话 503**（2026-08-25）  
   - 第一颗未关干净 → `start_session` 落 `OFFICIAL_HTTP_503`／「MoreLogin 会话 503」。

3. **平台只能加固、不能根治**  
   - 帧内 refresh、换通道、HTTP floor、暂态不 quarantine 等，都是在公网 ADB 易坏前提下的止血。

切换 ONIRENT 的目标，正是去掉这条「易坏公网隧道 + MoreLogin API／ADB 混用」路径，改为 **固定 `host:port` 直连 ADB**（`ALIOTH_ONIRENT_ADB_SOURCE=auto`，本测用静态池）。

## 5. 换成 ONIRENT 后，还可能出现哪些 5xx／类 5xx？

| 风险类型 | 本次是否看到 | 说明 |
|----------|--------------|------|
| MoreLogin 公网 ADB Capture 502 | **未见** | 已不走该通道 |
| MoreLogin 会话 503（同机残留） | **未见** | 无 MoreLogin session API |
| ONIRENT 端点宕机／端口轮换导致 ADB offline | 未见（本窗口） | 仍属厂商／网络风险；应用固定池 + 健康检查 |
| CC智控 WS 不可达 | 配置规避 | `SOURCE=auto` 优先静态 ADB；WS 不是唯一路径 |
| 平台自身 5xx（API／依赖） | 未见 Capture 5xx | 与云手机 ADB 无关的后端故障仍可能独立发生 |

## 6. 建议（后续怎么守）

1. **验收 ADB 健康时，优先看 Capture HTTP／`official_app_api_*`。**  
2. 连跑多 APK 前仍建议：卸载／force-stop 上一包、回桌面；虽已无 MoreLogin 503，但可减少残留进程干扰。  
3. 保留 `ALIOTH_ONIRENT_ADB_SOURCE=auto` + 静态池；不要把 WS 写成唯一发现路径。  
4. 若未来再出现 Capture 失败：先 `adb devices`／同机外部 screencap，再查平台；**禁止只重启 Docker**（与旧 MoreLogin 排查纪律一致）。
