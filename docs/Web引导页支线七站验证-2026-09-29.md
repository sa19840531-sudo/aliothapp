# Web 引导页支线七站验证（2026-09-29）

## 验证范围

本次在 `codex/web-evidence-recovery` 验证新 `guide_page` 支线：从 Web 首屏快照提取 App 引导候选，用独立 Playwright 浏览器只读打开落地页，并核对原浏览器会话能继续采集。浏览器侧脚本使用既有 Web Capture 实现；引导页使用生产 WebGuidePageBrowser。原始截图、DOM 与 UI Snapshot 留在本机测试证据目录，不进入 Git。

本轮浏览器测试不创建正式 Web Worker 任务，不执行模型、阶段账本、Manifest 落库、登录、详情页或质检，因此不能把浏览器侧的成功等同于七站正式任务成功。数据库只执行只读 `EXPLAIN`；正式链路用自动化测试验证组合和失败隔离。

## 代码审核与回归

独立复审发现并已处理四类收口风险：并发领取阶段时要在 Session 命令租约内复查；阶段结果必须写标准 `result_capture_id`；可选引导 Capture 不能进入主线 Manifest／reconciliation 失败门槛；报告不能在引导清单 PENDING、FAIL 或缺失时展示 `confirmed`。普通清单现于 SQL 层先排除引导 Capture，严格解析和裁决；引导清单逐条宽容读取。报告只有最新清单 PASS、子 Capture 截图引用有效时才确认。扩展回归又发现引导调度器误传给辅助导航器、模拟浏览器无独立启动器时初始化失败，均已修复并增加组合回归。最后检查报告读取时补上可选引导查询失败降级，主报告继续生成。修复后的复审未发现其他有明确可复现依据的高优先级问题。

相关 Web 定向、组合、页型、模型和七站修复回归合并执行结果为 **959 passed、5 skipped**；其后新增的可选引导报告查询失败回归与相关报告测试 **44 passed**。修改过的 Python 文件通过 Ruff；`git diff --check` 通过。合并回归结束时有 Windows Playwright 子进程清理警告，但无失败测试；七站实际浏览器复测的 stderr 为空。测试库上新普通／引导清单查询和引导报告查询均通过只读 `EXPLAIN`，另只读核对了普通与补充 Capture 的用途标记、Surface Phase 和页型检查约束。未引入数据库迁移，未改 App 或 H5 文件。

## 限制

- 浏览器侧 URL 访问是直接导航与采集，不代表正式 Worker 对菜单预算、详情页、规则质检和任务终态的验收；正式七站全链路仍需在测试环境建立任务并核对落库。原七站统计中的 chigua 10 个详情卡片已在上方纠正，不应再引用为「61 个菜单」。
- 当前网络条件下没有一站形成可信的已确认引导页，不能以“候选已发现”替代 `guide_page` 分类成功。
- 正式模型与数据库写入仅由隔离测试和 SQL 结构检查覆盖，本轮没有将七站原始浏览器证据写入测试库。
