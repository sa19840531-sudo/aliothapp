## 结论与范围

本轮在 `codex/web-evidence-recovery` 的隔离 worktree 上，以生产 Playwright 采集浏览器、清障器、UI 快照候选提取器和整页补采请求，逐站访问**五个**当前选定的同源菜单，并沿可信页面候选访问对应详情。首次候选落在子栏目、广告或公告时，另起诊断批次核对正文／视频卡片；所有旧结果与错误证据保留。菜单与详情的 ready 首屏截图和 DOM 分别保存，整页 PNG 另作补充证据。没有提交、付款、注册或改动 App/H5。

**代码默认并非 5 个菜单。** `load_web_menu_collection_limit()` 默认读取 `ALIOTH_WEB_MENU_COLLECTION_LIMIT=10`；本轮是按用户提到的五个菜单做诊断样本，不代表正式任务已冻结为 5，也没有执行剩余菜单。正式 Worker/API 此刻不可用，未运行数据库入库、模型页型判定、证据清单质检或完整任务终态；这些浏览器侧结果不能称为正式主线 100% 成功。登录支线沿用前一轮独立报告，本轮没有重新提交凭据。

## 发现的缺口

1. **菜单额度不是五个。** 当前代码默认 10；本轮只覆盖每站前五个目标。对于新站动态发现和已冻结任务，实际额度以任务运行快照为准。
2. **详情候选不能取列表第一条就当成功。** `heiliao` 初选 `/aitech/` 栏目，后来仅按 `/archives/` 筛选仍误选回家地址公告；`91porna` 初选分类列表；`hl365` 旧菜单初选体育直播推广页。定向复测按当前页正文/视频卡片重新选候选，最终 35 条均有对应业务详情证据。这是候选过滤和模型选择需要重点质检的风险，正式流程不能照搬本轮诊断选择规则。
3. **部分菜单需要两次下钻。** `avhub360` 的专题合集、女优；`www.91jav1` 的女优、专题；`huangguoai` 的专题，菜单页先进入子栏目，再能选作品。仅“菜单→一层详情”的统计会高估视频详情覆盖。
4. **Catalog 与站点实时导航漂移。** `hl365.sjb_qm` 的旧 URL `/category/sjb-qm/` 当前不在首页导航；首页显示“优选投放” `/category/youxuan/`。已对当前链接及正文 `/archives/217948.html` 单独完成截图、DOM、整页补图，但正式 Catalog 仍需审查同步。
5. **首页清障仍有缺口。** `91porna` 的首页有自称 20 秒关闭的公告弹窗，首页 ready 未通过。等待后五个菜单及详情分别清障并采集成功，不能由此推断正式首页基线成功。
6. **整页图不是 100%。** `chigua` 有三张菜单、三张详情长图未能保存：菜单均为 `WEB_FULL_PAGE_SCREENSHOT_STATE_DRIFT`，详情均为 `WEB_FULL_PAGE_SCREENSHOT_LIMIT_EXCEEDED`（单图 16 MiB 上限）。这些页面的 ready 首屏和 DOM 仍在；没有用滚动后 1920×1080 视口图冒充长图。
7. **候选目标重定向。** `avhub360` 女优菜单初选 `/actress/detail/3536`，落到 `/actress/detail/2080`，原链路标为身份不一致；经子栏目复测后进入 `/videos/fthtd-109`。原错误未被覆盖。

浏览器测试没有修改生产代码、数据库、App 或 H5。正式 API 健康接口在本轮检查中超时，`docker` 命令在当前 Shell 不可用，因此尚无正式任务 ID、数据库清单或质检结果可宣称成功。
