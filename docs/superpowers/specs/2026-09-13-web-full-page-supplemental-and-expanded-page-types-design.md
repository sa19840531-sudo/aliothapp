# Web 长图补采与九类页面类型设计

## 文档状态

- 状态：方案已确认，书面设计与实施计划已完成自审，待实施
- 设计日期：2026-09-13
- 适用范围：Web 探索截图证据、页面类型 Catalog、正式分类、覆盖率、报告与审计
- 平台边界：仅适用于 `platform=web`；App/H5 不在本次改动范围内
- 数据库迁移：首版复用现有 Capture、Evidence 与持久化 Phase 能力，不新增数据库迁移
- 前端菜单与路由：无需同步调整

## 背景与结论

当前 Web 探索以视口截图作为页面动作、命中测试和页面类型判定的主要视觉证据。底层截图工具已经具备 `full_page` 能力，但探索流程没有把长图作为独立补充证据稳定保存；部分业务流程还显式使用 `full_page=false`，以避免截图改变当前页面的滚动和动作状态。

当前 Web 页面类型 Catalog 是严格的五类闭集：`home`、`content_list`、`content_detail`、`video_list`、`video_detail`。附件进一步明确了内容详情和视频详情的媒体区分规则，并要求新增 `age_gate`、`activity`、`search_page`、`unknown`。这会同时影响 Catalog 校验、分类器候选集、覆盖率分母、菜单落地验收、报告输出和历史策略恢复，不能只改 JSON 文本。

本设计采用以下结论：

1. 保留现有视口截图作为主证据；页面就绪后额外保存一张全页长图，角色为 `supplemental`。
2. 页面类型扩展为九类，并明确分为业务覆盖、生命周期和兜底三组。
3. `age_gate` 在关闭前正式分类并持久化；关闭后对同一 URL 重新创建 Capture，再分类真实业务页。
4. 搜索探索只读且零点击、零输入、零提交；仅从 DOM 提取有效同源 HTTP(S) `href` 并由当前页面直接导航，无 `href` 的搜索图标不执行。
5. 同源活动链接按普通页面使用当前 Playwright 页面直接导航；跨域活动或推广只进入既有广告落地证据链。
6. Catalog、分类、覆盖、报告只维护一份规范页型集合；历史 Run 始终使用其冻结 Catalog 和版本内置语义，不被新规则重新解释。

## 目标

1. 为每个稳定就绪的 Web 页面状态保留“视口主证据 + 全页补充证据”。
2. 完整吸收附件中的 `content_detail`、`video_detail` 媒体规则和详情分类原则。
3. 将 `age_gate`、`activity`、`search_page`、`unknown` 纳入正式、可审计的分类结果。
4. 让页面类型继续由 DOM、截图、最终 URL 和主体结构共同判定，置信度阈值保持 `0.7`。
5. 保持菜单导航、详情入口、搜索入口、活动入口和外域广告之间的执行边界清晰。
6. 保证覆盖率、正式报告、策略快照和历史恢复对新增页型有确定语义。

## 非目标

- 不修改 App/H5 的 Catalog、页面分类、截图策略、探索编排、覆盖率、报告、接口契约或测试基线。
- 不把 Web 新页型、`0.7` 阈值、长图策略、年龄门生命周期或搜索发现动作下沉为 App/H5 默认行为。
- 不用全页长图替换视口截图，也不用长图承担点击坐标、命中测试或动作到达证明。
- 不通过显式滚动、点击弹层或修改页面来制造长图；长图补采是只读证据动作。
- 不在搜索页输入关键词、提交搜索表单或自动探索查询结果。
- 不把顶部单独存在的搜索图标判定为 `search_page`。
- 不把跨域活动、下载、约会、药品或其他推广落地页纳入站内业务覆盖。
- 不把七个业务类型全部强制为所有网站的固定必达分母。
- 不取消同源、安全动作、危险入口、deadline、幂等和审计门禁。
- 不在本设计阶段修改生产代码或执行三站实况探索。

## 术语与页型集合

### 页面状态与 Capture

“逻辑页面状态”由一个页面就绪 Capture 标识，而不是仅由 URL 标识。同一 URL 在年龄门关闭前后属于两个不同页面状态，因此必须产生两个 Capture、两组截图和两次分类结果。

“主证据截图”是当前视口截图，继续用于动作来源、元素命中、遮挡判断和页面到达证明。

“补充长图”是与来源 Capture 绑定的全页截图，仅用于页面结构补证、分类复核和报告展示，不改变当前动作游标。

### 九类规范页面类型

| 分组 | 页面类型 | 覆盖语义 |
|---|---|---|
| 业务 | `home` | 站点首页；由根角色、导航和多板块主体共同佐证 |
| 业务 | `content_list` | 多条文字、图文或帖子条目的列表/聚合页 |
| 业务 | `content_detail` | 单条文字、图文、图集、漫画翻页或图片查看主体 |
| 业务 | `video_list` | 多个重复视频卡片或视频条目的列表/聚合页 |
| 业务 | `video_detail` | 单个已确认视频资源构成页面主要主体 |
| 业务 | `activity` | 单一运营活动、专题、推广或福利主体 |
| 业务 | `search_page` | 已打开的搜索交互页，或自然到达的查询结果页 |
| 生命周期 | `age_gate` | 阻断真实业务主体的成年/进入确认层 |
| 兜底 | `unknown` | 证据不足、冲突、异常或无法唯一归类 |

`activity` 和 `search_page` 是规范业务类型，但不是所有站点的无条件必达项。现有站点适用性评估根据真实导航、页面结构和自然可达入口，把业务类型标记为 required、optional 或 not_applicable。`age_gate` 不进入业务覆盖率；`unknown` 既不进入业务覆盖率，也不算生命周期达标。

## 截图证据契约

### 双截图模型

每个成功达到稳定就绪条件的 Web 页面状态按以下顺序取证：

1. 保存现有视口截图和 DOM，创建来源 Capture。
2. 在同一页面、同一稳定状态发起一次 `full_page=true` 的补充截图。
3. 把长图以独立证据记录绑定到来源 Capture，并保存规范 URL、Task、Run、Session 和页面状态身份。
4. 页面分类可以同时消费 DOM、视口截图和长图，但输出必须指出每条证据来自哪一种截图。

补充截图的规范逻辑角色为 `web_full_page_supplemental`。它不得替代来源 Capture，不得推进当前 Capture 指针，不得成为后续点击或导航动作的 `source_capture_id`。

### 幂等与状态隔离

长图以“生产者 Run + 来源就绪 Capture + 证据角色”作为幂等身份，每个来源 Capture 最多成功保存一次。年龄门关闭前后的两个 Capture 即使 URL 相同，也分别允许一张长图。

长图流程不得显式执行滚动命令、点击、键盘输入、表单提交、遮挡关闭或页面重载。浏览器为生成全页截图而执行的内部布局/拼接不计作探索动作，但完成后必须验证页面 URL、DOM epoch 和已知滚动位置没有形成不可接受漂移；发生漂移时标记补采失败，并保留原视口主证据。

### 失败行为

长图超时、页面过长、像素或文件大小超限、浏览器拒绝、页面状态漂移、持久化失败时：

- 保留视口截图和来源 Capture；
- 不生成伪造的长图成功记录；
- 不把视口截图复制成 supplemental；
- 记录结构化错误和 `supplemental_evidence_gap`；
- 页面分类可继续，但必须反映缺失证据，不得因长图失败自动改判 `unknown`。

错误码统一为：

- `WEB_FULL_PAGE_SCREENSHOT_TIMEOUT`
- `WEB_FULL_PAGE_SCREENSHOT_LIMIT_EXCEEDED`
- `WEB_FULL_PAGE_SCREENSHOT_STATE_DRIFT`
- `WEB_FULL_PAGE_SCREENSHOT_PERSIST_FAILED`

尺寸、像素和文件大小限制复用现有浏览器与证据持久化上限，不另建一套无限制通道。

### 分类与报告使用边界

长图可以佐证首屏以下的主体、图集、长正文、重复卡片和活动内容，但不能单独证明元素可见可点，也不能覆盖视口截图已经证明的顶层年龄门或广告遮挡。若长图和视口图显示的页面状态不一致，分类器必须产生状态冲突并转人工复核，不得选择性忽略其中一张。

正式报告默认展示视口主证据，并把长图作为可展开的 supplemental 证据引用。报告必须区分“未尝试长图”“长图失败”和“长图成功”。

## Catalog 模型与版本契约

### 版本策略

Catalog 保持 `schema_version=page-type-catalog.v2`，发布新的 Web 内容版本。原因是通用页面类型字段语义不变，本次新增的是 Web 专属严格字段、页型成员和消费契约。新版本加载器必须严格校验九类集合、字段形状和分组语义；旧 Run 使用冻结 Catalog 和对应版本适配器。

新运行不得用当前九类常量反序列化旧五类 assessment 或 coverage snapshot。历史版本保留自己的候选集合、覆盖分母和错误语义。

### Web 专属根字段

Web Catalog 根模型至少包含：

- `schema_version`
- `version`
- `platform`
- `page_types`
- `page_type_groups`
- `navigation_signals`
- `detail_link_signals`
- `detail_classification_principles`
- `common_site_observations`
- `notes`

`page_type_groups` 是唯一规范分组来源：

```json
{
  "business": [
    "home",
    "content_list",
    "content_detail",
    "video_list",
    "video_detail",
    "activity",
    "search_page"
  ],
  "lifecycle": ["age_gate"],
  "neither": ["unknown"]
}
```

每个页型仍可携带可读的 `coverage` 字段，但加载器必须校验它与根分组一致，避免分类器和覆盖率各维护一份不同集合。根字段和页型对象继续拒绝未声明字段、重复代码、无效相互引用和空规则。

附件文本中的 `unkonw` 统一纠正为规范代码 `unknown`，任何新持久化结果、接口或报告都不得发布错误拼写。附件在 `activity.confusable_with` 中提到的 `profile` 不会因此扩展为第十个规范页型；在 Catalog 中应改为普通对照说明或强否定语义，不能保留为指向不存在页型的悬空引用。若未来正式引入个人中心页型，必须另行设计其分类和覆盖契约。

### 附件特征保真要求

附件为 `content_detail`、`video_detail`、`age_gate`、`activity`、`search_page` 和 `unknown` 提供的 `purpose`、必需正向信号、辅助信号、强否定信号、易混淆类型、缺失证据动作、媒体规则与说明必须逐字段纳入 Catalog。实现可以把 Web 专属字段规范化到根级强类型结构，但不得删除或弱化以下区分：

- 单条主体与重复列表；
- 图集/图片查看器与真实主视频；
- 正文内嵌媒体与整页唯一媒体主体；
- 播放器外壳与已确认视频资源；
- 年龄确认阻断与普通广告插屏；
- 单一活动落地与多板块首页；
- 已打开搜索能力/查询结果与顶栏搜索入口；
- 证据不足或冲突与可稳定签发的业务页面。

Catalog 中的 `missing_evidence_actions` 是补证建议，不是自动执行授权。涉及滚动时，必须作为独立只读探索动作产生新 Capture；涉及搜索提交、跨域深入探索或危险交互时仍受本设计的禁止和安全边界约束。

### 详情媒体规则

`content_detail` 必须吸收附件中的以下语义：

- 单条文字、图文、图集、漫画翻页或图片查看器可成立；
- 正文内嵌少量视频或图片时，仍按主内容判定，通常是 `content_detail`；
- 只有播放器外壳、类名或按钮，不能据此转成 `video_detail`；
- 已确认视频资源若成为唯一或主要主体，应优先考虑 `video_detail`；
- 页面仍被年龄门或顶层广告遮挡时，不得签发真实详情页型。

`video_detail` 必须同时满足：

- 页面主体聚焦一个视频，而不是多个重复视频条目；
- 存在已确认的视频资源或等效可信播放状态；
- 视频位于主内容区，不是广告、背景视频、导航预览或悬浮推荐。

可信视频资源可以来自可审计的 `video/source`、可信视频 iframe 或等效播放状态。仅有 canvas、不可读跨域 iframe、关闭的 shadow root 或播放器外壳属于不透明媒体，不自动成立，进入补证或复核。

全局详情分类原则固定为：按主内容判定，不按页面中是否出现过 `player` 类名或 `video` 标签的全局计数判定；图片查看器、图集和漫画翻页归 `content_detail`；真实视频资源且为页面主体归 `video_detail`；证据不足时保持 `unknown`，不强判。

## 分类优先级与签发规则

所有正式页型继续使用统一最低置信度 `minimum_confidence=0.7`。达到阈值只允许进入结构门槛校验，不会绕过强否定信号、顶层遮挡、主体证据或唯一性要求。

分类按以下优先级执行：

1. 顶层存在阻断业务主体的成年或进入确认层时，签发 `age_gate`。
2. 年龄门关闭后创建新的 Capture，对新状态重新执行完整分类，不能复用或覆盖关闭前结果。
3. 页面主体是单一活动、专题或推广时考虑 `activity`；包含稳定导航和多个并列业务板块的首页仍为 `home`。
4. 已打开搜索输入界面，或页面主体为自然到达的查询结果时考虑 `search_page`；仅有顶栏搜索图标不成立。
5. 单条图文、图集、漫画翻页或图片查看器优先为 `content_detail`。
6. 只有已确认视频资源位于主内容区且构成主要主体时，才允许 `video_detail`。
7. 列表页继续由多个重复同类单元、稳定详情入口和落地页主体共同区分 `content_list`、`video_list`。
8. 没有任何类型达到 `0.7` 并通过结构门槛，或多个类型存在无法消解的强冲突时，签发 `unknown`。

URL、域名、静态菜单 Catalog 和文案只能提供辅助证据。裸域名或规范根路径是 `home` 的强辅助信号，但不能覆盖单一详情、活动、年龄门或异常主体的结构证据。

### `age_gate` 生命周期

年龄门必须满足：最上层存在年龄/进入确认语义、存在明确确认动作、确认前真实业务主体不可见或不可操作。普通广告关闭按钮、加载态和选线态不属于年龄门。

流程固定为：

1. 对关闭前状态保存 DOM、视口截图和可用的补充长图；
2. 正式签发并持久化 `age_gate`；
3. 记录与动作来源 Capture 绑定的成年确认动作；
4. 动作完成后创建新的就绪 Capture；
5. 对同一最终 URL 的新状态重新采集双截图并分类业务页；
6. 使用 `pre_gate_capture_id`、`dismiss_action_id`、`post_gate_capture_id` 保留谱系。

持久化成年声明只授权执行明确的成年确认动作，不授权登录、付费、下载、外域跳转或其他危险操作。

### `activity` 与 `home`

`activity` 的核心是单一运营/推广主体，通常具有参与、领取、跳转或推广导向，并具有明显时效性或专题属性。首页存在“官方推荐”“每日大赛”“优选投放”等多个运营板块时，只要页面仍有稳定全局导航和多个并列业务区域，应判为 `home`，不能因出现活动文案把整页改判为 `activity`。

首页弹窗中的活动广告不是当前业务页面的 `activity` 类型。关闭或隔离弹窗后分类当前页；弹窗目标若跨域，只采集广告落地证据。

### `search_page`

`search_page` 必须出现已打开的搜索输入区及触发动作，或自然到达的查询结果态。空搜索界面可以成立，不要求自动产生结果。结果卡片即使形似列表，也应由查询驱动事实与固定频道列表区分。

探索过程中不得输入关键词、粘贴、自动补全选择、按回车或点击提交按钮。若目标 URL 本身已经包含查询参数，只读采集现有结果，不修改查询。

### `unknown`

`unknown` 是正式、可持久化的分类结果，不是异常字符串或空值。它用于页面仍在加载、证据过少、主体被不可处理遮挡、媒体不透明、错误/空白页或类型强冲突等情况。

不能仅因为某个辅助信号缺失就降为 `unknown`；若某一类型已稳定满足必需信号和结构门槛，应签发该类型并记录补证缺口。普通可关闭广告必须先按既有授权尝试处理后再决定是否 `unknown`。

## 探索执行边界

### 菜单导航

菜单候选继续只从 DOM 中具有有效 HTTP(S) `href` 的导航链接产生。满足同源、非广告、非搜索、非危险入口后，使用当前 Playwright 页面 `goto(canonical_url)`，不点击导航菜单。隐藏和可见属性作为审计信息保存，不作为是否抽取 `href` 的区别；可信导航容器、导航语义和安全规则仍必须成立。

页面落地后由 DOM、视口截图、长图和最终 URL 判定其实际类型，可以是 `content_list`、`video_list`、`search_page`、`activity` 或其他规范类型。静态菜单类型提示不能定案。

### 搜索入口

带有效同源 `href` 的搜索入口使用当前页面直接导航。没有 `href` 的搜索图标不作为候选，也不进入独立点击动作。此零 CLICK 约束取代早期的受控 `search_discovery` 点击设计。

搜索 href 导航后只采集新的 DOM 和双截图并分类，不输入、不提交、不点击结果。动作结果未知、无变化或仍未形成搜索界面时不重试，并记录诊断。

### 活动与广告入口

具有有效同源 HTTP(S) `href` 的活动入口使用当前 Playwright 页面 `goto(canonical_url)`，落地后按普通业务页面分类。没有 `href` 的活动按钮不自动点击。

跨域活动、广告或推广入口不得扩大普通站内探索边界，只能进入既有隔离广告落地取证流程：在新 Playwright 页面或标签打开，保存最终 URL、DOM 和截图后关闭，不继续探索，不污染当前业务页面指针，也不计入站内 `activity` 覆盖。

## 覆盖率、报告与审计

覆盖快照必须分别保存：

- 规范业务页型集合；
- 当前站点 required、optional、not_applicable 适用性结果；
- 生命周期观察结果；
- `unknown` 页面及待复核原因；
- 每个正式判定的规则命中、强冲突、置信度和证据引用；
- 视口截图与长图的成功、失败或未尝试状态。

业务覆盖率分母只包含当前站点判定为 required 的业务类型。`activity`、`search_page` 未被发现且无适用性证据时可以是 not_applicable，不得自动拉低覆盖率。若导航中存在明确可达入口却未完成探索，应标为 applicable but uncovered，并在报告中给出原因。

`age_gate` 作为生命周期记录单独报告关闭前分类、确认动作和关闭后分类谱系。`unknown` 单独进入“未分类/需复核”统计，不计为成功覆盖，也不进入业务分母。

正式报告中，同一个页面状态只显示一个最终规范类型；模型原始候选、冲突和历史改判保留在审计明细，不得在摘要中把 `age_gate -> home` 合并成一个模糊页型。

## 持久化与历史兼容

新 Run 的策略快照保存完整 Web Catalog 正文、Catalog 版本、九类分组、阈值、详情媒体规则和截图策略。恢复时重新执行对应版本的严格校验。

旧 Run、旧 assessment 和旧 coverage snapshot 使用版本内置的五类集合恢复，不补入 `activity`、`search_page`、`age_gate` 或 `unknown`，也不重新计算历史覆盖率。新报告读取旧数据时明确显示 legacy schema，而不是静默升级。

首版复用现有 Capture/Evidence 关系和通用持久化 Phase 保存 supplemental 长图幂等状态；如果实施阶段证明确实缺少可表达“来源 Capture + 证据角色”的字段，必须先回到设计复核，不能临时塞入无语义的 metadata 或增加未经设计的迁移。

## 组件影响

实施计划至少应覆盖以下职责，不限定最终文件拆分：

- Web 专属截图补采服务、浏览器截图基础设施：补充长图请求、限制和错误映射；共享 `page_capture_tool` 已具备 `full_page` 参数，本次不改变其默认值或 App/H5 调用语义；
- Web 页面就绪与探索编排：双截图时序、幂等、状态漂移验证；
- Web Catalog 加载器与领域模型：九类闭集、分组、媒体规则、详情原则；
- 页面结构事实和正式分类器：新页型事实、优先级、`0.7` 阈值和 `unknown` 兜底；
- 年龄门处理：关闭前后双 Capture 及谱系；
- 菜单、搜索、活动和广告探索：不同动作类型与导航边界；
- 覆盖率、适用性、正式报告和策略快照：新分组与历史版本适配；
- 专项能力与高频回归规则：同步记录可复用规则。

所有改动必须从 Web 专属编排或 `platform=web` 的显式参数进入。若浏览器截图共享基础设施必须增加字段或能力，其默认值和既有调用语义必须保持不变，并新增 App/H5 不受影响的回归断言。禁止为了复用 Web 页型集合而修改 App/H5 常量、Catalog 或分类消费者。

## 测试策略

### 截图证据

1. 页面就绪后保存一张视口主截图和一张全页 supplemental，二者绑定同一来源 Capture。
2. 同一来源 Capture 重试不会产生重复长图；年龄门关闭前后两个 Capture 各可产生一张。
3. 长图不推进当前 Capture 指针，也不能作为点击动作来源。
4. 长图超时、超限、状态漂移和持久化失败均保留主截图并产生结构化缺口。
5. 报告正确区分长图成功、失败和未尝试。

### Catalog 与分类

1. 九类集合、顺序、分组和相互引用严格校验；附件中的媒体规则和详情原则无遗漏。
2. `0.69` 被拒绝，`0.70` 仍需通过结构门槛才可正式签发。
3. 图片查看器、图集和漫画翻页判为 `content_detail`。
4. 文章内嵌视频通常保持 `content_detail`；播放器外壳不能成立 `video_detail`。
5. 已确认视频资源位于主内容区且构成唯一主要主体时判为 `video_detail`。
6. 不透明 iframe/canvas、证据不足或强冲突产生 `unknown`，而不是误判视频详情。
7. 多板块首页包含活动推荐时仍为 `home`；单一运营落地页判为 `activity`。
8. 只有搜索图标不成立；打开搜索输入界面或自然查询结果可以判为 `search_page`。

### 生命周期与探索

1. 年龄门关闭前正式保存 `age_gate`，关闭后同 URL 新 Capture 分类为真实业务类型，谱系完整。
2. 普通广告弹窗不会误判为 `age_gate` 或当前页 `activity`。
3. 带 `href` 的同源菜单、搜索和活动链接按各自规则直接导航；普通菜单无点击路径。
4. 无 `href` 搜索图标不执行，整个流程没有 CLICK、文本输入和表单提交。
5. 无 `href` 活动按钮不自动点击；跨域推广仅进入隔离广告取证。
6. `activity`、`search_page` 的适用性不会被无条件加入每站 required 分母。

### 兼容与回归

1. 旧五类 Catalog、assessment 和 coverage snapshot 按历史语义恢复，覆盖率不漂移。
2. 新策略快照能恢复九类分组、媒体规则、阈值和截图策略。
3. 页面分类、菜单、详情、年龄门、广告、报告和持久化全量 Web 回归通过。
4. 实况测试覆盖超长页、年龄门双状态、活动页、空搜索界面、图集详情和真实视频详情。
5. App/H5 相关测试、截图参数、页型候选集和报告序列化结果与改动前一致。

## 验收标准

- 每个稳定就绪的 Web 页面状态都有视口主证据，并且最多有一张与来源 Capture 绑定的全页 supplemental；长图失败不破坏主流程。
- `web_page_type_catalog.json` 完整表达九类页型、分组、详情媒体规则和分类原则，并被强类型领域模型实际消费。
- `age_gate` 关闭前后形成两个正式 Capture 和可追溯谱系。
- `activity`、`search_page` 成为可分类、可报告的业务类型，但仅在站点适用时进入覆盖要求。
- `unknown` 成为精度保护型正式结果，不参与业务覆盖率或生命周期达标。
- 图集不会因播放器外壳误判为视频详情，真实主视频也不会被长文本或全局标签计数掩盖。
- 搜索探索全程零 CLICK、零关键词、零表单提交；无 `href` 搜索控件不执行。
- 同源活动使用当前页面直接导航，跨域推广只保留隔离广告证据。
- 新旧 Run 的 Catalog、候选集和覆盖率语义互不污染。
- App/H5 代码与运行行为不受影响；任何共享基础设施扩展都保持默认关闭且由 Web 显式启用。

## 实施风险

- 极长页面的全页截图可能触发浏览器像素限制或显著增加存储，应通过现有限制和结构化降级收口。
- 某些全页截图实现可能改变滚动或触发布局懒加载，必须验证状态漂移，不能默认视为纯读取成功。
- `search_page` 与查询驱动列表、`activity` 与多板块首页容易混淆，必须同时保留主内容事实和强否定信号。
- 九类集合扩展涉及多个硬编码五类常量，实施计划必须先建立单一规范分组来源，再逐个迁移消费者。
- 年龄门前后同 URL 的两个状态如果只按 URL 去重，会丢失生命周期证据；所有幂等键必须以来源 Capture 为核心。
