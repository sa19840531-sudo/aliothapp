# Web 不限菜单预算与三站探索增量设计

## 背景与目标

现有 Web 探索已经支持 `home`、内容/视频列表、内容/视频详情五类正式业务页面，能够从 DOM、截图和最终 URL 形成页面类型证据，并能从运行时导航中发现未登记菜单。当前仍有三项需要调整：正式页型置信度默认阈值仍为 `0.8`；菜单采集与打开受单站 10 条固定预算约束；页面类型 Catalog 尚未完整收录最新的导航和详情链接判定信号。

本次增量实现以下目标：

- Web 正式页面类型默认判定阈值统一为 `0.7`，包括 `home`。
- 菜单采集和菜单链接打开不再受 10 条固定数量上限约束。
- Web 站点 Catalog/白名单仅作为排序、别名和页型提示，不作为页面类型或菜单可执行性的主要判定依据。
- 导航以当前可见 DOM、截图与可点击事实为准，排除面包屑和隐藏节点。
- 详情入口以重复列表单元及实际落地单条主体为核心证据，并正常打开验证。
- 支持没有静态站点 Catalog 的裸域运行时探索。
- Docker 不重新构建镜像，迁移并重启现有服务后实况探索 `heiliao.com`、`hl365.com` 和 `both.pnsmxatxp.cc`。

## 设计原则

### 页面类型证据权威性

正式页型由当前页面的 DOM 结构、可见截图、最终 URL 和主体内容共同判定。URL 路径、菜单文案和静态 Catalog 只提供候选与排序信息，不得单独形成正式结论。

裸域或规范根路径是 `home` 的强辅助信号，但仍必须至少得到可见主导航、多板块或重复内容卡片之一的主体佐证。列表页和详情页不得只凭 URL 形态区分。

### 导航与面包屑隔离

主导航判定以“可见、可直接点击、多个并列入口、站点级复用”为核心。默认收起且尚未展开的入口不进入有效菜单；采集过程已经安全展开时，展开后的可见入口可以加入候选。面包屑是当前位置路径，只能辅助列表或详情页判定，不能计入主导航正向信号。

### 详情链接验证

详情候选必须位于列表主体中的重复卡片或重复行，并包含标题、封面或摘要类信息。候选打开后必须到达单条内容主体或单个播放器主体；仍为同类列表、分类、筛选、分页、广告或外链推广时，不得认定为详情入口。

详情打开优先使用可信 `href` 直接导航；没有可信链接时才使用与源 Capture 绑定的可点击热区。两种方式都要记录菜单页、动作、详情页 DOM、截图、最终 URL 和正式页型证据。

## 不限菜单预算模型

### 数据模型

`qc_web_exploration_budget.menu_limit` 改为可空：

- `NULL` 表示不使用菜单数量上限。
- 非空正整数仅用于读取历史任务或显式兼容旧预算。
- 新建 Web 探索预算写入 `NULL`。

`qc_web_menu_ledger_entry.execution_slot` 改为不带 10 条上界的正整数序号。数据库保留同一运行、站点和执行序号唯一约束，但删除 `execution_slot <= menu_limit`、`menu_limit IN (5, 10)` 以及 `execution_slot <= 10` 等门禁。

新增迁移只放宽约束和字段类型，不改写既有账本事实。历史预算中的 `5` 或 `10` 保留原值并继续表达历史运行当时的显式上限。

### 应用行为

新运行不再对 Catalog 菜单或运行时发现菜单做数量切片，也不再因为数量产生 `menu_limit_skipped`。同一规范逻辑 URL 仍只执行一次；别名保留审计关系但不重复打开。

运行时菜单持续加入 Frontier，直到出现下列终止条件之一：

- 到达运行 deadline，并为持久化收口预留安全时间；
- 当前可执行 Frontier 为空；
- 人机验证阻断且无法按已授权成年声明处理；
- 当前页面或导航状态无法建立可信交接；
- 候选违反同源、安全 scheme 或危险操作规则。

“不限”仅表示没有菜单条数上限，不表示取消时间、安全或幂等边界。逻辑目标去重、候选已见集合、持久化 reservation 和菜单父子 lineage 共同防止循环访问。

## 静态 Catalog 与未知站点

静态站点菜单 Catalog 继续承担以下辅助职责：

- 提供已知入口的稳定名称、顺序和别名关系；
- 提供非权威页面类型提示；
- 保存版本、来源和历史审计信息。

运行时 DOM 导航才决定入口当前是否存在、可见、可点击和安全。未登记 origin 通过裸域建立运行时首页上下文，并使用相同的导航发现、详情验证、广告取证与正式页型流程，不因缺少静态白名单而拒绝探索。

普通菜单与详情导航保持同源。外域广告使用独立广告证据流程：在新 Playwright 页面或标签打开，保存落地 URL、DOM 和截图后关闭，不污染业务页面的当前指针。

## Catalog 信号更新

`web_page_type_catalog.json` 保持 `page-type-catalog.v2` 结构并提升内容版本。`navigation_signals` 更新为以下语义组：

- 通用正向信号；
- 辅助信号；
- 默认收起与当前可见导航规则；
- 强负向信号；
- 主导航与面包屑的区分规则；
- 使用说明。

新增 `detail_link_signals`，包含用途、必需正向信号、辅助信号、强负向信号、与导航/广告的区别、内容详情与视频详情的区别以及使用说明。

Catalog 文本规则用于生成和审计识别依据；正式结果仍必须由结构化运行时事实满足规则后产生。

## 阈值策略

Web 正式页型分类器的默认 `minimum_confidence` 从 `0.8` 改为 `0.7`。所有未显式覆盖阈值的 Web 正式分类入口复用同一常量，避免工具层、工作流层和测试夹具出现不同默认值。

强负向冲突、证据不足和模型主动要求复核的门禁保持不变。置信度达到 `0.7` 不会绕过主体证据、遮挡层清理或详情落地验证。

导航别名匹配阈值维持已经调整的 `0.7`，与正式页型阈值数值一致，但两者属于独立判定阶段。

## 执行器与报告

现有六站实况脚本扩展为可接受任意合法 HTTPS 目标 URL，不再要求目标必须位于固定站点元组。报告按实际请求目标生成动态预期，不再计算固定菜单上限或限额跳过数量。

每个站点报告至少包含：

- 首页最终 URL、阻断层处理和正式页型；
- 识别出的可见主导航及层级；
- 实际打开的菜单、导航方式和最终 URL；
- 列表页详情候选、选择依据、实际详情页类型；
- 首页及已打开菜单页各抽取一个外域广告时的落地 URL、DOM 和截图证据；
- 被同源、安全、验证或 deadline 门禁阻断的候选及原因；
- Frontier 收口状态和异常诊断。

## 错误处理与安全边界

- 仅接受 HTTP/HTTPS URL，HTTPS 站点不得降级到 HTTP。
- 普通菜单与详情跳转必须留在目标站点允许的同源范围。
- 登录、购买、下载、上传、发布、支付等危险操作继续阻断。
- 成年声明仍从 `.env` 持久配置读取，不跟随账号、会话或站点变化。
- 年龄门关闭后重新采集页面，避免把弹层按钮识别为导航。
- 广告外域取证使用隔离页面并限制为证据采集，不继续探索落地站点。
- deadline 前预留持久化收口时间；超时不得留下未知 reservation。

## 测试与验收

按 TDD 顺序增加或调整以下测试：

1. `0.69` 被正式页型阈值拒绝、`0.70` 可进入后续结构证据判定。
2. `home`、列表和详情统一使用 `0.7` 默认阈值。
3. 至少 11 个及更多可见同源菜单均能进入计划，不产生第 11 条限额跳过。
4. 数据库能够为第 11 个以上菜单分配唯一正整数 `execution_slot`。
5. 未登记站点可建立运行时首页并执行当前可见菜单。
6. 隐藏/未展开入口不计入菜单，安全展开后的可见入口可以加入。
7. 面包屑不进入菜单候选。
8. 重复列表卡片可获取并打开真实详情；分类、分页和广告候选被排除。
9. 详情点击和直接导航均携带正确的 `navigation_depth` 并形成落地证据。
10. 实况执行器接受三个指定裸域并动态生成报告。

完成单元、集成和数据库迁移测试后，在现有 Docker 镜像上执行迁移并重启 API/worker，不运行 build。最终以三站新鲜实况结果和保存的证据文件作为验收依据。

## 非目标

- 不取消同源、危险操作、人机验证、deadline 或审计约束。
- 不把静态 Catalog 删除；只降低其决策权威性。
- 不探索广告落地站点的后续页面。
- 不把成人声明绑定到登录账号或服务端用户资料。
- 不更改非 Web 平台的页面类型阈值。
