# 四站判定异常分析、通用特征修复与页面类型方案

## 1. 结论和本轮边界

核对原报告、13 份已分类列表/未分类页的 Snapshot、相关完整 DOM、分类审计，以及失败 Capture 的 PostgreSQL 就绪元数据后，结论是：**主要问题是结构特征缺失/错误归属、就绪窗口和探索路径，不是现有页面类型不足。**

- 本轮增加通用 Web 特征，未增加/重命名页面类型，未改类型目录版本、数据库结构、前端菜单/路由。
- 详情模型优先、原有结构兜底和正式置信度下限 0.70 保持不变；模型复核信号不清除。
- 不使用域名、URL 路径、站点标题、演员姓名或具体内容作为补丁条件。
- 不修改 App/H5 专用代码。共享采集器新增行为仅在 Web 专用标志开启时生效。
- 顶部菜单 href 的获取、隐藏菜单可执行 GOTO、菜单配置数量、广告独立会话及截图策略均未修改；卡片辅助链接过滤不用于删顶部菜单。
- 未重跑在线四站，未改历史分类、证据或原报告，也未启动旧 API/Worker。

分析对象是 `2026-09-18-web-four-sites-current-exploration-results.md` 对应的新轮次，不是早期 baseline。

## 3. 已增加的通用特征

### 3.1 显式正文根与裁剪保留

统一识别 article、role=article，以及正文容器的完整 class/ID：article-body、post-content、entry-content、content-detail、detail-content、markdown-body。

- 只读取当前节点完整标记，不从 URL、标题、任意包含词或属性值猜正文。
- 对正文根采集有界数字长度，仍排除隐藏内容、导航、广告、推荐和控件；空正文不能成立。
- 正文根优先进入 Web 有界 Snapshot，并在 512KiB 裁剪中保留；不取消元素/字节上限。
- 已证明的正文内视频仍为内嵌媒体，不另算独立主视频资源。
- 主体补证目标与长正文曝光复用同一正文根语义，避免“能分类但找不到补证目标”。

### 3.2 推荐边界留存

Web 采集优先保留明确“相关推荐/猜你喜欢/related content”等标题及局部容器，供既有区域提取区分正文与次要推荐。容器不能是正文根；未把含糊的“更多内容”加入新的采集优先项。边界最多取 8 组，弹窗关闭证据仍保持最高保留优先级。

### 3.3 全局搜索与页面搜索分离

依据可信父链排除全局 header/banner、nav、aside、footer 内的搜索入口。main/文章内部搜索区域仍可建立搜索输入与提交控件的配对事实。没有按搜索按钮文案删搜索功能，也没有删除 search_page 类型或其强负规则。

### 3.4 卡片主链接、辅助链接与正文分离

卡片的标签、分类、筛选、广告等辅助链接不计入主目标数量；封面与标题指向同一内容按一个主目标处理。这样才能建立外层卡片边界并排除其描述段落，而不是只排除标题锚点、把相邻描述误当正文。

普通 main 中存在主体重复卡片时，直接导语和 main 的总文本长度不得把整个列表提升成文章。独立、非重复、未包含主卡片的正文子树继续保留，显式文章正文根也仍可吸收自身内部的重复引用链接，推荐和广告继续独立排除。原有“独立多段正文加推荐卡片”的回归未改预期。

### 3.5 媒体卡片命名空间/BEM

在原有完整媒体记号之外识别通用 `命名空间-drama/video/movie/media-card__body/title/link/cover/...` 组合。拒绝 non/not/no 等否定记号、editorial-card、videocardish 等噪声。此特征只说明列表卡片的媒体语义，不证明可播放资源，不强制模型选 video_list。

## 4. loading 的证据链与后续修复建议（本轮未实施）

五个最终失败 Capture 的数据库结果如下；原静默门槛均为 600ms：

| URL | 稳定等待时 quiet_ms | 采集末端 quiet_ms | 实际拒绝条件 |
| --- | ---: | ---: | --- |
| 91jav /heiliao | 1210.4 | 485.3 | dom_not_quiet |
| 91jav /movie | 1216.6 | 113.5 | dom_not_quiet |
| 91jav /my | 1216.6 | 241.2 | dom_not_quiet |
| AVHub /movie | 1217.0 | 535.6 | dom_not_quiet |
| AVHub /my/history | 1214.0 | 480.3 | dom_not_quiet |

五页均为 core_present=true、visible_loader=false、network_pending=0；三个 91jav 代表页另核实 necessary_media_ready=true、settle_complete=true、quorum_met=true、capture_consistent=true，准入拒绝项仅 dom_not_quiet。**因此直接原因是采集前后静默窗口不一致，不是没有加载出页面。**

代码在暂停页面运动并完成有界稳定等待后采制品，再读取末端 readiness；MutationObserver 监听整棵 DOM 的属性、子节点及文本变化。制品窗口内出现新变动时，即使身份和结构一致，仍可能因末端 quiet_ms 不足被记为 loading。现有证据没有每一次 mutation 的来源，不能断言全部由采集器、CSS 动画或广告造成；“采集辅助变动污染窗口”是需要定向复现的假设，而非已经证明的唯一根因。

建议单独修复：记录末端未静默的变动来源、时间和区域；区分业务内容/路由变化与明确的采集辅助变动；在同一制品窗口做一次有界稳定复核。发生业务变化必须重新采证据，不能直接沿用较早的 quiet_ms。禁止降低 600ms 门槛、用 complete 代替就绪，或关闭身份/证据一致性校验。

## 5. 页面类型方案：先保留类型，补状态和列表语义

### 5.1 推荐方案

保留七种业务类型：home、content_list、content_detail、video_list、video_detail、activity、search_page。age_gate 仍为生命周期类型，ad_page 仍仅证据型，unknown 仍保留复核职责。

- 人物目录：content_list，可后续增加 **list_subject_kind=entity_directory** 的审计特征。
- 人物作品集合：video_list，可增加 **list_subject_kind=entity_collection**。不得挪用当前 primary_subject_kind 的 article/video/gallery 枚举。
- 人物集合的条目才可能是 video_detail；人物资料若自身形成单一完整图文主体，则允许模型选 content_detail。
- 地址发布/说明页：有单篇完整正文时仍为 content_detail；没有正文时不能凭 /gohome 路径分类。
- 上游错误、加载、空结果、登录要求：优先作为单独的 **page_state** / readiness 状态轴，不计业务覆盖，不作为 home。

91porna 建议状态 `upstream_error`，保存状态码（OBSERVE 没有响应码时不能伪造）、错误结构依据、请求/最终 URL、DOM/首屏证据，给出明确上游错误缺口，不尝试关闭不存在的弹窗。仅凭任意正文中出现“504”不能成立错误状态。

### 5.2 有界列表中转方案

允许明确的实体目录→作品集合→单条详情路径，默认最多 **1 层中间列表**。每次到达先由模型判定真实页面类型；若目标还是列表，不伪改成详情，而是从该列表重新建立可信候选闭集后选择一个详情。

保持菜单配置最多 5 个不变；中转动作另记深度和动作预算，记录父 Capture、源候选、真实类型、URL、DOM、截图。用既有规范 URL 去重防循环。普通列表跳转到其他无关列表不得无限递归，耗尽按缺口收口。广告仍在每个适用页面判定后走独立会话，不影响主路径。

这是探索策略方案，本轮没有据此改变任务完成分母、详情覆盖或菜单预算。

### 5.3 何时才新增 page_type

暂不建议新增 entity_detail、utility_page、loading_page。新增它们会联动类型闭集、模型响应、覆盖分母、规则匹配、任务范围、报告投影和前端配置，无法解决缺证据或 0.65 的复核。

若后续业务明确要求独立质检“无正文的地址发布/工具/个人中心”，再设计 utility_page / profile_page 的主体特征、允许动作、范围配置和规则合同。若仅要求报告单列错误页，可设计证据型 error_page（默认不计业务覆盖），但它与 upstream_error 状态二选一，避免双重权威。这些类型均需先确认业务职责及反例，再升级目录版本与冻结合同。

## 6. 详情选择理由失败的限制

已证明失败发生在理由脱敏，而不是候选不存在、GOTO 或页型判定。现有诊断刻意不保存原始模型理由，所以无法证明本次是否因为理由复制了 `web-candidate:<64位摘要>` 而触发凭证/高熵检测；代码确实可能把长十六进制摘要拒绝为敏感内容。

后续可在闭集成员校验成功后，把理由内**精确命中本次公开候选 ID**的值替换成固定安全标签，再继续原脱敏；不得放过任意摘要、凭证或未授权候选。需要增加固定枚举的拒绝细分诊断，不记录模型原文。该建议是响应边界修复，不是新增页型，本轮未实施。
