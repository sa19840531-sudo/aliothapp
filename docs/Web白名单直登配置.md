# Web 探索白名单直登

Web 直登在首页清障与 ready 首屏完成后运行。它在同一个 Chromium 中创建不共享 Cookie 的独立 Browser Context；登录支线结束后销毁该 Context，主 Web 探索继续使用原会话。不会创建账号，也不会启动注册流程。App 和 H5 探索不读取这项配置。

设置 `ALIOTH_WEB_LOGIN_ENABLED=true` 和 `ALIOTH_WEB_LOGIN_ALLOWLIST_PATH` 后，新建的 Web Runtime 才读取仓库外的凭据文件。文件使用 UTF-8，每个站点三行，站点之间留一空行：

```text
网址：https://example.com
账号：此处填写账号
密码：此处填写密码
```

生产环境应通过受控文件挂载提供路径，并限制文件读取权限。凭据文件不提交到 Git；配置中的账号和密码不作为参数写入日志、阶段游标或模型提示。登录后的网页可能自行显示账号，此类页面信息仍会进入正常 Web 证据，须沿用证据存储的访问控制。每个源站只能出现一次；子域名不自动继承白名单。账号可为手机号、邮箱或用户名，字段类型由文件内容判定，不为站点生成新账号。

HTTP 入口只有在浏览器实际跳转到对应 HTTPS 源站、且独立 TLS 证书验证通过时才允许填写。TLS 校验使用浏览器配置的代理并保持证书验证。首页人像、登录文字与弹层切换由可见 DOM 语义和实时命中检查定位；年龄门禁仅在任务具备成年声明时点击确认，普通遮挡弹层逐层有界清理。登录表单可位于主文档或唯一可见的同源 iframe，账号字段、密码字段与提交控件必须唯一。支持初始 disabled、填写后才启用的提交控件，以及位于表单外但仍在同一登录弹层内的提交按钮。跨源表单、Service Worker、验证码和无法确定的目标仍停止自动登录；提交最多执行一次。

凭据首次进入页面后，独立登录 Context 持续阻断未授权跨源请求并静默原始网络观察器，以免延迟请求把秘密送到第三方或进入 HAR。仓库内的 `infra/env/web-login-auth-origins.json` 仅配置已确认的四个 HTTPS 认证源站，分别绑定 chigua、hl365；它不包含账号密码，也不支持通配符、自动继承子域名或以 IP 代替域名的动态放宽。未知跨源请求一律中止，并记录目的源站与方法。认证结果与跨源策略分别记录：若同源认证 Cookie 变化且表单消失，仍保留已证实的登录事实，同时标记跨源策略存在拦截；认证未证实时支线未完成，主探索继续。浏览器不保存请求体、Cookie 或秘密；Service Worker 和 WebSocket 在隔离 Context 中关闭。

登录结果以同源认证类 Cookie 的签名变化且登录表单消失作为本地确认。当前运行时只接入本地 DOM 与 Cookie 路径，不会将登录页面截图发送给外部模型。表单消失或 URL 变化本身不足以证明登录。未配置或未命中白名单时保持原 Web 探索路径；登录未证实时在 ready 阶段游标记录 `login_branch_status` 与 `login_branch_reason`，但不使主探索失败，也不声明主探索已登录。

账户菜单进入同源账户页后，允许在新页面再找一次人像及登录菜单；每次点击仍需以当前截图和可见 DOM 复核，不能循环重试提交。`span` 形式的登录入口只在账户菜单内、文字与登录语义均唯一时允许点击，注册入口始终排除。提交后若页面仍在 HTML 标记中保留密码，独立 Context 禁止后续截图及模型调用，仅允许本地只读 Cookie／表单复核，随后立即销毁。无论登录结果如何，主探索会话及其截图链均不接触凭据。现阶段不自动处理第三方身份提供商、验证码或未在四个源站配置中的跨域认证接口。

登录成功后的账户检查只在隔离 Context 中运行：先在新同源文档中确认秘密已清除，再保存页面截图；点击可见且唯一的人像／账户入口后重新截图与脱敏 DOM。账户页以可见 DOM、图片文字、本地 OCR 和同源 URL 路径查找钱包与充值入口；OCR 结果必须落到当前可见、可命中的同源链接。若钱包与充值均存在，先进入钱包并留证，再从钱包进入充值；没有钱包才直接尝试充值。只允许 GET／HEAD 导航，不提交支付或金额。截图、DOM 制品 ID、存储路径、检查状态及跨源策略写入 Web 阶段游标；主探索 Capture 不得冒充隔离会话截图。找不到入口时记录未发现，不推断不存在。

若当前视口未见入口，账户检查会在 DOM 中寻找唯一、同源且可见于页面布局的屏外链接，滚动到该链接后重新截图和核对命中。图片中的“钱包／去充值”可经本地 OCR 提供线索，但必须与真实链接的矩形范围相交；无文字链接可由明确的同源 `wallet`、`recharge`、`topup` 或 `deposit` 路径提供候选。链接打开的同 URL 弹窗、新页面或新 URL 均须在可见加载层消失后重新截图、保存脱敏 DOM，并核对独立页面主体；持续加载只记入口未证实。只有钱包标题或路径与数字余额共同成立才记 `recharge_page`；只有充值金额与支付方式等独立主体成立才记 `topup_page`。两种类型均仅作隔离会话补充证据，阶段游标保留按访问顺序排列的页型、脱敏 URL、截图和 DOM 引用，不进入主探索页型覆盖或质检规则匹配；无入口时直接跳过。
