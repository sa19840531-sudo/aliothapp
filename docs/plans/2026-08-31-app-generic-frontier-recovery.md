# App 通用探索与清障修复

## 目标与边界

修复真实导航入口丢失、临时遮挡误关分支、动作前截图变化后仍点旧目标的共性问题。不配置 APK 包名、品牌文案、固定控件坐标或固定底栏数量；不降低任务页型分母、不改历史任务结果、不把点击成功当作到达。

## 方案

1. 视觉候选增加签名字段 `control_role=dismiss|skip|null`，新候选用 v3，保留 v1/v2 原哈希与读取合同。角色描述当前可见控件，不授予越权点击。
2. 覆盖寻页仅提高真实视觉候选优先级，不合成几何。真实候选允许登记全局 Frontier，同一 pending 入口重现刷新当前帧绑定，不重复占用配额。旧合成合同失败关闭。
3. 首页先执行仍缺失的全局导航；嵌套页继续先探索当前页独占入口。弹窗、广告、加载未清除时不穿透点击业务入口。
4. 当前页被遮挡时先执行本帧确认的关闭/跳过控件，保留待探索分支。复用既有每分支两次恢复预算；清障后重新验签，稳定页上候选确实缺席才关闭分支。
5. 每次触控在 before_action 重新读取视觉证据，确认包、Activity、页面状态、尺寸和当前控件；画面变化且目标不再可信时不调用 Driver，重新截图选路。恢复失败保留审计原因，不改成成功。
6. 业务覆盖要求稳定、无遮挡且页型置信度不低于 0.70；广告/倒计时事实与业务页分类冲突时不计覆盖。规则质检继续依据独立证据和 Completion Gate。

## 提交与验证

- 第一批：V2 180 分钟公开预算、请求与内部校验、预算测试。
- 第二批：v3 视觉角色合同、生产解析和旧协议回归。
- 第三批：通用清障、动作前复验、队列和寻页修复及对应回归。
- 第四批：全量回归发现的旧测试合同与隔离 PostgreSQL 种子适配，不放宽生产约束。
- 第五批：专项规则与实施验证报告。
- 验证包含不同包名/栏数、不同语言/图标、角色篡改、旧协议、移位/消失/遮挡/风险升级、候选持久化与有界恢复。用冻结任务事实回放调度，不触发设备操作。
- 同步远端采用普通 fetch/rebase/push；白名单暂存，保留现有报告与其他无关工作。无数据库迁移，无新增前端菜单或路由。

代码回归与冻结证据回放不代表新云手机端到端验收；重跑结果需另列新任务 ID、实际页型和规则证据，不能套用历史统计。
