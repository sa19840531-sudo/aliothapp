# Web 引导页导航与第八站登录复核（2026-09-29）

## 范围与结论

基线为 `codex/web-evidence-recovery`。本轮继续对原七站进行独立浏览器侧采集、清障前后导航识别与引导入口来源复核，并尝试新增 `https://hifans1.com/` 的白名单隔离登录。未修改 App/H5 代码，未建立正式 Worker 任务或写入测试库，以下结果不能代表七站完整任务或质检终态。

**导航菜单没有整体消失。**七站的首个未清障帧受成年门、广告或倒计时弹层影响，动作候选常被标为 `obstructed`。清障后五站立即恢复可操作导航；91jav1 与 91porna 在另一次 36 秒倒计时等待后恢复。引导入口识别与落地页判型是两件事：部分站点找到 App 链接，但本轮 `guide_page` 可信确认仍为 0。

七站在独立引导尝试前后的主 `Page`、`Context` 和 URL 保持一致。原烟测直接访问 61 个 URL 并保存截图、DOM、UI 快照，但其中 **chigua 的 10 个 URL 是正文详情卡片，不是菜单**；验证脚本已改用正式导航提取器作后备来源，并对 chigua 单独补测了 5 个真实 `/category/` 菜单。其余直接导航也只证明链接可达和浏览器原件已留存，不证明正式 Worker 的菜单动作、详情选择、模型分类或质检通过。

另有一个尚未通过正式任务复现的预算风险：chigua 不在冻结站点菜单目录中，清障后的动态导航提取结果把 `/github.html`、`/qun.html`、`/telegram.html`、`/twitter.html` 排在分类菜单前；四条均通过当前 `discovery_safety_reason` 检查。若正式 Run 启用目录外动态菜单探索，它们可能先占用默认 10 个菜单名额。这里能确认的是候选顺序和静态安全检查结果，不能据此声称正式任务已实际访问这四条。后续应将站点社交/联络跳板与业务菜单分账，并用真实 Run 验证预算使用。

引导候选从来源页的 UI 快照提取；只有独立落地页内容足够明确才可确认 `guide_page`。本轮 chigua、heiliao、hl365 的支线停在安全网络传输；91jav1 和 huangguoai 保存了落地原件但内容不完整，所以保留 `uncertain`。本机普通 HTTP 客户端能读取 chigua/hl365 对应 App URL，不能据此替代独立支线的固定地址传输结果，也不应直接关闭其网络保护。当前候选选择按快照顺序、Run 总额度 2 个；chigua 的页脚链接排在顶部 App 图标之前，可能先占用额度，后续值得把导航与页脚的优先级及首次失败后的额度策略列入回归。

## hifans1 隔离登录

仓库外账号白名单中已经包含 `https://hifans1.com`，本轮没有在代码、文档、日志或测试结果中写入密码。`GET /` 返回 302 至 `/login`，普通 HTTP 客户端读取 `/login` 返回 200，静态 HTML 中有用户名、密码和登录提交结构。但**生产同类的本机隔离 Playwright** Chrome 在主文档 `commit`/`domcontentloaded` 前超时，页面保持 `about:blank`；Edge 亦如此。分别尝试无代理与本机测试代理仍超时，而普通 HTTP 客户端通过两条网络路径均返回 200。仅凭这些证据不能确定是站点、Chromium 或网络中间层的哪一环拒绝了该浏览器路径。

另在 Codex 内置浏览器的独立标签中做了**浏览器侧手工验证**：真实登录页渲染账号/密码表单；按用户给定的该站凭据提交后，表单消失、导航出现「我的」，URL 回到首页。随后点击「我的」到达 `/my`，页面显示账户资料与「退出登录」，可确认此浏览器会话登录成功。账户页截图已在验证对话中留证，标签已保留；可见链接/按钮中没有钱包或充值入口，仅有「订阅会员」。没有点击订阅或执行支付。

这不等于自动化登录分支通过：**本机隔离 Playwright 尚未完成首页 Capture，也未填表或提交凭据**，没有该分支的登录账本、截图/DOM 落库或主会话隔离验收。现有跨域认证目的地限制保持不变；不能为了补齐自动化结果将账号密码改由裸 HTTP 请求提交。此站应在与正式 Worker 相同的浏览器和网络环境中复测首文档响应，成功后再运行生产隔离登录与账户入口取证。
