# 绿色规则三端实施规范

本文件是绿色八条规则的唯一现行规范。规则定义、证据留存、Skill/Tool分工、三端适配和业务接入统一以本文件为准；历史设计移入归档，仅用于追溯。实际验证结果另存于`docs/reports`，不能用规范声明代替验收。

## 1. 来源与版本

- 来源：[规范汇总①](https://docs.google.com/spreadsheets/d/1BzFpZYqmELVvo58VYFng2Qw8XwF29iYVH3Eri9XK12M/edit?gid=1730171659)，工作表“9月新增规则优先级”，物理第13—20行。[原文、映射及参考备注快照](source-materials/2026-10-17-green-rules-source.json)完整保留。
- 本轮规则集为`alioth_green_ruleset`第4版，新合同`green-rule-contract.v2`。八条规则编码为`alioth_green_102/s72/41/62/s35/s49/s73/32`；来源41不是旧数据库`alioth_41`二维码规则。
- 旧规则及旧Task保持其冻结定义、Skill正文、输入成员和判定结果。旧green第1—3版继续按原合同读取；第4版使用有序分类/增量Skill正文和摘要，不从运行中磁盘更新旧Task。
- 网络延迟、等待、采样次数、容量和测量精度属于采证参数。参考备注中的1秒、2秒、3次、30个、10%、20%—80%不自动成为产品合格线；正式业务阈值必须在规则版本集中声明。

## 2. 八条业务定义

| 来源行/规范 | 检查对象和合格条件 | 必需证据及判定边界 |
| --- | --- | --- |
| 13/102 | 首页及一级目录中的等价首页、首页所有内容列表；其他内容列表前两屏按原文19:9范围扣除固定功能和导航。排除广告，图文联合，涉未、涉政、涉恐独立输出结果、置信度、触发证据和复核建议 | 原图与可识别文字、内容范围及实际覆盖、广告排除来源。不得猜精确年龄；年龄或类别不确定进入复核。普通战争、枪械等元素不能单独证明涉恐；具体红线政策引用受控版本，不由模型临时发明 |
| 14/S72 | 同一模块、同次请求周期，真实空数据有“暂无数据”类说明；加载失败应引导刷新或重试，不能把失败显示为空 | 唯一关联的真实请求结果与模块呈现。空态可以有插图/引导；普通刷新功能存在本身不证明状态错误。HTTP200、空白截图不能单独证明空数据，未知保留未验证 |

| 16/62 | 有广告时，正常结束或手动关闭后与正片顺畅衔接，包含正片预加载；自然结束、手动关闭分别覆盖 | 同一广告/正片身份、真实结束或关闭、预加载、实际呈现首帧和中间过程。呈现事件不冒充首帧PNG；广告加载失败兜底是独立旧场景。缺完整过程不能据末帧通过 |
| 17/S35 | 分项检查点击响应正确、列表/弹窗无影响使用的错位重叠遮挡、同一操作在可核验的相同前置条件下表现稳定 | 正式独立Action及前后/过程、真实反馈因果、命中及布局事实、可比前态。不同前态不能作不稳定反例；合法蒙层叠放不自动违规。危险或不可安全重复的操作保留一致性未验证 |
| 18/S49 | 实际断网、加载失败、超时时说明原因并提供重试/刷新路径；视频异常有切线恢复路径，账号支付异常有客服路径，支付关键过程不被客服打断 | 当前模块真实异常、原因/入口、可信条件业务类型和支付阶段。页面自报“普通内容”不能免除视频、账号、支付义务；分类或阶段未知保留缺证。入口存在不等于实际打断；入口可用与重试后业务恢复分别记录。不为验证提交真实支付或联系客户 |
| 19/S73 | 加载过程有进度反馈；真实空态有插图或有效引导；真实业务成功后有本次明确提示或动效。分项按实际条件报告 | 完整加载过程、真实空态、可信业务结果及本次新反馈。Driver执行成功、HTTP200、常驻旧Toast不是业务成功证明；不同产品可由受控响应合同、业务状态或明确回执证明，无法验证时未知 |
| 20/32 | 同级2—4类在导航可用区域等宽分布；5类以上完整容纳时文字完整且间距均衡，否则横向滚动；初始右侧还有分类时露出下一项部分文字 | 完整分类及容器、真实文字边界、视口/缩放/滚动位置和初始状态。不能以中间滚动帧代替初始状态，也不能用不完整枚举或空数组证明产品没有导航 |

## 3. Skill、Tool与端适配

规则决定“检查什么”；Skill决定“怎样读取合同和证据”；Tool负责执行已授权能力；端适配器生产真实事实。判读侧只读，不借新Skill扩大采集权限。

| 规则 | 第4版冻结Skill程序 | 复用及增量 |
| --- | --- | --- |
| 102 | `green-content-safety` | 专项三风险结构与范围规程；复用截图、文字、语义Gateway和复核写回；不将UGC分类规程扩大为全站内容安全 |
| S72 | `visual-rule` + `green-process-evidence` | 原视觉规程加共享过程证据边界 |
| 41 | `interaction-rule` | 外链身份由设备适配器证明，不额外复制规程 |
| 62 | `ad-rule` + `green-process-evidence` | 广告主分类及媒体过程事实；不拼接互斥category路由 |
| S35/S49/S73 | `interaction-rule` + `green-process-evidence` | 交互主规程及完整窗口、因果、业务结果与分支覆盖 |
| 32 | `visual-rule` | 使用当前规则声明的导航分支与可信几何 |

组合程序按顺序保存每份Skill的名称、版本、完整正文和SHA256，组合正文也保存摘要。已有分类Skill原文不修改；旧专项Skill作为旧合同兼容材料保留，不作为第4版的另一套规范入口。

| 能力 | 接入方式与职责 |
| --- | --- |
| `page_capture_tool`及正式执行器 | 复用原权限、会话、命令租约、截图/多帧/网络/UI/媒体采集与归档；业务对象的增量事实在采集层生产 |
| `deterministic_assertion_tool`、`rule_judge_tool`及批量入口 | 按冻结合同路由判定，不按端复制业务标准 |
| 结果Writer及`record_rule_execution_tool`等入口 | 复用原校验、幂等、复核、报告和完成事务，不另开第二套结果表 |
| 网络、状态差异、瞬时提示、几何、命中、媒体和广告内部能力 | 复用现有框架；逐项核对真实生产器，不把摘要字段或导出映射名当成已实现能力 |
| `green_rule_evidence_tool` | 内部固定分派的只读证据判读，不是模型可自由调用的独立FunctionTool |
| `network-resilience-collection`及`network_condition_probe_tool` | 第2版采证规程区分独立计划授权与绿色全质检单次服务端许可，两者均重读真实Task/Run/Session/Epoch及范围；施加会话内有界条件，记录命中、撤销、取消和恢复。Tool为敏感级，Judge不能调用；延迟不冒充断网/超时，内部恢复请求不参与业务判定 |

## 4. 三端边界

| 端 | 事实来源 | 交付与适用边界 |
| --- | --- | --- |
| Web | 正式浏览器会话、DOM、原生事件、请求、截图、媒体和几何 | 与H5可复用底层但独立接入、独立验证；H5通过不代表Web通过；不适用App41 |
| H5 | 移动视口/触控下的浏览器会话及实际文档事实 | 各过程仍按模块/动作/媒体实例判断；真实控制场景与实际产品验收分别标明；不适用App41 |
| App | 授权设备会话、UI树、实际动作、应用/浏览器身份、网络和原生媒体事实 | Android/iOS分别证明能力；不能将DOM/HAR改名当UI树/设备网络。共享设备不能全局限速模拟独占会话；具体能力和验收状态在对应报告逐项列明 |

所有端共用规则版本、分项语义和结果词表。未支持、采集失败、条件没发生与产品确实不适用分别记录，不能降低定义弥补端能力缺失。

## 5. 证据留存

每次判定须能从结果回到原始材料，不依赖模型自报或页面声明：

1. 冻结规则版本、Skill程序、能力版本与采证参数，保留来源行、原文及参考备注。
2. 保存Task/Run/Session/Epoch、业务对象、正式Action及前后Capture、Manifest和原件身份；不跨会话拼同一次动作前后。
3. 保存前态、过程、后态及观察窗口、完整性、截断/缺口、视口/坐标/滚动、请求/媒体/系统身份等必要事实。
4. 原始截图、UI、网络、动作及相关材料按原存储链路保存字节、摘要、大小和质量结果。最终InputSet固定成员及摘要，不能选早期正常样本掩盖后续反例。
5. 时间因果须有同源时钟证明。新浏览器点击使用同一私有文档观察器的原生事件和PerformanceResourceTiming，保留原CDP时间，不加容差或改写原值；多请求/多资源项/换文档/超限时拒绝唯一绑定。
6. 技术执行、业务结果、证据充分性分别保存；取消或异常仍保留已有原件及网络恢复审计。实际模型调用的身份与用量绑定正式消费者Task/Run，不能用无归属调用或仅输出存在替代逐任务审计。公开出口使用字段白名单和脱敏，不暴露存储路径或原始敏感响应。

## 6. 业务接入及结果

正式链路：规则集发布与任务提交冻结 → 按端能力和授权执行采集 → Manifest统一裁定质量 → 按具体业务实例冻结页面/过程输入 → 只读事实检查与语义判定 → 原事务写结果及复核队列 → 报告与Task收口。

第4版102、32及App41使用原页面判定路径；S35使用`green_interaction_stability.v1`输入范围，S72/S49/S73/62使用`green_temporal_rules.v1`。TASK只是过程输入发布载体，不表示全产品已覆盖。新时序选择保留全部有关过程及逐项缺口，原有容量/超限边界单独审计。

| 状态 | 使用条件 |
| --- | --- |
| `pass` | 适用条件实际发生，必要证据充分，当前分项符合要求 |
| `fail` | 证据充分且有明确反例，指出对象、过程、分项及原件 |
| `evidence_insufficient` | 缺条件/材料、因果歧义、窗口不完整或端能力缺失；不是产品失败 |
| `manual_review` | 年龄/政策/语义不确定，或命中冻结复核策略；必须进入实际复核链路 |
| 不适用 | 有端、业务类型或产品能力的可靠排除依据，沿用已有状态并保存原因；未采到不构成依据 |

同一规则保留各分项覆盖情况，一个通过不能抵销反例或其他缺证；已有明确失败时仍保留尚缺项目。多次操作须独立Action和可比前态，不重复使用一个动作身份；只读Judge不补点击、不制造业务数据。

## 7. 旧规则兼容与发布准入

- 不纳入按旧`alioth_7`全局跳过App、按旧`alioth_26`硬切首帧1000ms的分支；新语义只由显式新合同激活。普通任务不能因新增green能力自动弱网、重复点击、扩大必需材料或切换Writer。
- 不使用按旧`rule_code`跨规则集覆盖正文的迁移发布新标准。若环境已应用此类覆盖，另核实际行和后续编辑，按精确规则身份与变更前值纠正，禁止盲目整链downgrade。
- 不整提交回退其他团队的App脚本、截图、H5短流程、图谱、采证、迁移归属或CI修复；旧Task冻结输入及历史结果不改写。
- 发布前核对实际API子进程、Worker进程、共享源码挂载和数据库迁移版本；容器启动时间不代表运行代码未热更新。新规则须在版本一致且迁移归属明确的环境接入，不能以管理读取兼容代替完整执行链兼容，也不能在旧结构写入时静默丢弃新字段。
- 旧标准未变时，用同一批真实原件对照判定，再验证受影响执行链路；纠正旧误判或升级业务标准单列版本和人工确认样本，不混入兼容性结论。
- 同适用范围比较有效判定、误报/漏报、缺证、跳过、复核、技术失败、任务完成、耗时和成本。产品通过率不是系统成功率，不靠增加skip或减少覆盖维持表面成功率。
- 真实验证须贯通正式入口、Worker、实际浏览器/设备、模型、数据库及原件。受控HTTP或媒体夹具明确标注，不能冒充实际产品验收；未验证端和条件单列。验收记录和临时资源清理遵守AGENTS及专项回归要求。
