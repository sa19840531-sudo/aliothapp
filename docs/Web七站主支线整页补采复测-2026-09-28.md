## 范围与方法

在隔离 worktree 的 `codex/web-evidence-recovery` 上，使用生产 `WebDesktopCapturePolicyBrowser` 逐站直接导航和观察页面，使用 `WebLoginBranch`、`WebLoginSessionBrowser` 和 `WebLoginAccountInspector` 执行独立 Context 的白名单登录、头像后账户复核及钱包／充值入口的仅导航检查。首页先清障、留 ready 截图与 DOM；Catalog 菜单及 chigua 首页发现的入口按每站最多 10 个执行，每个成功菜单留截图与 DOM；首页及首个成功菜单补采原始整页 PNG。登录在菜单之后执行，分支关闭后用原主会话复采首页。成年确认使用用户已配置、已声明的测试条件；没有注册、充值提交或付款。

未知跨源请求被拦数量分别为：91jav1 11、huangguoai 20、avhub360 12、chigua 9、heiliao 0、hl365 9、91porna 10。已认证的前三站也有非凭据跨源请求被拦，因此不能只凭拦截数量断定认证失败。chigua 和 hl365 均有发向 `https://13.229.106.237:15212`、`https://54.169.219.76:15212`、`https://api-dc-prod-001.cyou`、`https://api-dc2-prod-06.cyou` 的 POST 被拦；chigua 另有 `https://54.151.247.122:15212`，hl365 另有 `https://52.221.236.23:15212`。这些是新观察到的**目的源站和方法**，没有请求体；目前不能证明它们是认证所必需，也没有将其加入白名单。

登录与账户检查使用新的 Browser Context，关闭后验证原主 Context、Page、URL 和隔离 Context 关闭状态。七站四项均通过；六站认证类 Cookie 签名也未变。heiliao 的签名变化已由无凭据等待对照复现。登录支线没有使七站的主会话复采失败；这不等于证明所有站点的正式主线或所有支线都成功。

首次四站 `inspection_failed` 的共同异常定位在 `LocalEvidenceArtifactStore` 创建临时文件：测试证据根路径约 151 字符，附加任务 ID、Capture ID 与临时文件名后约 267 字符，Windows 抛出 `FileNotFoundError`。将独立登录证据根路径缩至约 89 字符后，91jav1、huangguoai、avhub360 完成账户复核；91porna 从异常转为可解释的 `WEB_LOGIN_ACCOUNT_UI_UNVERIFIED`。该异常由本轮诊断目录布局触发，不能据此认定站点认证失败。

本轮没有运行正式 Worker、数据库入库、质检模型、广告分支、播放器视觉补判或逐菜单的整页补采。主线菜单采用直接导航，且仅首页和每站首个成功菜单做整页图抽样；报告中的 57 个菜单截图／DOM 成功不代表这 57 页都已有长图。91porna 首页清障、chigua 的 `twitter.html` 导航、四站登录未证实仍是明确缺口。未修改 App、H5、站点配置或数据库。
