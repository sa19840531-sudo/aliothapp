# Web Explorer Workflow

## 核心原则

Web Explorer 只解释平台提供的当前 Capture、候选和结构事实。候选不是到达证明；命令成功也不是到达证明。页面变更必须经过新的可信观察与到达验证，才能进入页面分类和质检。

## 受控流程

1. 先识别当前可见层：业务层、成年入口、普通弹窗、广告遮挡或人机验证。
2. 保存阻断前态。只有操作者已声明成年，且平台提供唯一、语义明确的“年满 18 / 已成年 / 进入 / 继续”候选时，才建议该候选；验证码和滑块始终阻断。
3. 普通弹窗只选择候选闭集中的明确关闭、取消、稍后、知道了或跳过控件。每次动作后消费新 Capture，不基于旧证据连续决策。
4. 从平台证明的顶部导航收集全部 href，包括折叠或隐藏菜单；隐藏状态不取消已证明的同源 href 的 GOTO 资格。广告、危险操作和未核准外链不能成为业务探索动作；外域跳转本身不能证明广告。
5. 依据预算、同源、风险、白名单提示和覆盖缺口进行有界调度；白名单只辅助优先级和预期类型，不签发页面类型或到达结论。
6. 新观察通过页面就绪和到达验证后，只从本次请求的 allowed_page_types 与冻结页面目录选择类型，不使用旧固定四类闭集。业务页可包含 home、`video_list`、`video_detail`、`content_list`、`content_detail`、activity、search_page 和 `collection_page`；实际可选集合以当前请求为准。证据冲突、不足或低置信度仍进入复核，不根据结构过线覆盖模型复核。
7. 每个正式逻辑页面只产生一条质检时间线。通知质检后再返回上一可信状态或结束当前分支。

## 权限边界

- 不得直接调用 Playwright、浏览器 Driver、数据库、脚本解释器或运行时写回能力。
- 不得生成 selector、坐标、URL、命令或新候选；只能引用平台给出的候选 ID 和证据 ID。
- 不得自动处理登录、支付、购买、下载、删除、发布、授权或跨域外跳。
- Skill 不改变服务端预算、租约、同源、动作白名单和证据门禁；局部探索终态不等于任务完成。

## 集合页边界

- `collection_page` 的主体是多个主题、人物、频道或系列的集合入口；入口对应一组作品，不是一个作品。集合名称、封面与条目数量可以支持判断，但名称或数字不能单独签发类型。
- `video_list` / `content_list` 的主体卡片分别对应单个视频或单篇内容。集合入口进入列表，只支持入口的集合语义，不能把当前目录页反签为列表。
- 无需要求目录页本身有播放器或正文；播放器与单篇正文反而是集合页的冲突证据。顶部菜单、侧栏、推荐区不构成独立集合主体。
- 同帧证据清晰时按目录定义输出类型与真实置信度；确有缺证、语义混合时注明具体缺口，不因类型是新增类型而默认降分，也不为了通过验收提高分数。

## 快速判定

| 观察 | 处理 |
|---|---|
| 成年入口且唯一安全候选 | 在已有成年声明下建议候选，等待新观察 |
| 普通遮挡且唯一关闭候选 | 建议候选，保留前态并等待新观察 |
| 人机验证或高风险动作 | 阻断并记录原因 |
| 页面稳定且到达可信 | 分类并触发质检通知 |
| 同一规范 URL 已有正式终态 | 仅保留来源引用，不重复采集或质检 |

## 常见错误

- 仅凭 URL、菜单文字或白名单确定页面类型。
- 把无目标按钮、动作退出码或候选发现当作业务到达。
- 跳过阻断前态，或通过修改 DOM 制造无遮挡截图。
- 在未取得新 Capture 时连续点击，导致证据错帧。
