# 绿色过程证据只读增量规程

本Skill仅补充冻结规则指定的原分类规程，按冻结顺序读取完整程序，不替代分类、不拼接互斥category、不重写历史Task正文。业务标准来自green-rule-contract.v2及同版本规则正文。

1. 核对Task、来源Run、Session、Epoch、业务对象、正式Action、前后Capture、Manifest版本及原件集合。输入须来自已授权生产器，不能从页面声明、模型摘要或字段改名推定真实事实。
2. S35使用green_interaction_stability.v1；S72、S49、S73及广告衔接使用green_temporal_rules.v1。task仅是过程输入发布载体，不代表全产品已覆盖；不得强行映射为H5 Journey检查点。
3. 同次动作或请求必须有唯一同源关联和完整观察窗口，保留全部相关过程、截断、缺口及容量或超限审计。不能选早期正常样本掩盖后续反例，不能跨会话拼动作前后。
4. 时间因果只采用可信同源时钟证明，保留原生事件、PerformanceResourceTiming和原CDP时间。多请求、多资源项、换文档或超限时拒绝唯一绑定，不改原值、不加容差。
5. 技术执行成功、业务成功和证据充分性分别记录。Driver成功、HTTP200、截图变化、常驻旧Toast不是业务成功或本次反馈的证明；无法确认保持证据不足。
6. 空态须有同一模块同次请求的真实空结果。加载失败不得冒充空数据；普通刷新功能存在不证明状态错误。S72与S73共享事实但分别输出语义与插图、引导或节点反馈结论。
7. 交互稳定性须有独立Action和可核验的可比前态。不同前态不构成不稳定反例；合法蒙层不自动违规。危险或不可安全重复的操作保留一致性未验证，只读Judge不得重复点击。
8. 异常恢复分开记录原因、入口可用、重试后的业务恢复及条件分支。可信业务分类或支付阶段未知时保留缺证，不能因页面自报普通内容免除视频、账号或支付义务；客服入口存在不等于实际打断支付。
9. 广告自然结束和手动关闭分别覆盖，保留广告、正片身份、预加载、实际呈现首帧及中间过程。呈现事件不能冒充首帧PNG；广告加载失败兜底沿用独立旧场景，不按旧编号切到新标准。
10. 加载反馈需要完整过程；业务成功反馈必须是本次新反馈。分项适用条件未发生、缺证、端不支持、采集失败与可靠不适用依据分别记录。
11. pass要求当前适用分项证据充分且满足要求；fail要求充分证据和明确反例；缺条件、因果歧义或窗口不完整使用evidence_insufficient；语义、政策不确定或冻结复核策略命中使用manual_review。已有失败仍保留其他缺项，一个通过不能抵销反例。
12. 不自定1秒、2秒、3次、30个、10%或20%—80%等产品合格线。采证参数与正式业务阈值分开，阈值必须在规则版本集中声明。
13. 不补采、不制造业务数据、不施加弱网、不提交真实支付、不联系客户。网络条件Tool不属于只读Judge可调用能力；原始材料、取消与恢复审计沿原链路保留。
14. 使用既有规则Judge、结果Writer、复核、报告及Task收口事务；公开结果只输出白名单字段，保留精确原件引用，不暴露存储路径、原始敏感响应或模型凭据。
