# domain/iam 权限与账号域

支撑 [AGENTS.md](../../../../../AGENTS.md) "权限模型可扩展"这一最高优先级原则，是管理后台鉴权与操作审计的基础。

## 核心实体（规划，设计文档未详述，实现前需先补充设计）

- 用户（账号、状态、所属团队）。
- 角色（角色定义，可组合权限点）。
- 权限点（资源 + 操作粒度，如 `rule:write`、`review:approve`）。
- 操作审计日志（谁在何时对什么资源做了什么操作），呼应"审计链路完整"原则，与 [domain/task](../task/README.md) 的 `qc_agent_action_trace`（AI 执行留痕）互为补充——本域覆盖的是**人类操作者**的操作留痕。

## 职责

- 账号认证（登录、Token/Session 管理）。
- 基于角色的权限校验（RBAC），供 `api/` 层的鉴权中间件调用。
- 权限模型需可扩展：新增业务模块（如后续新增质检渠道）时，权限点可平滑扩展，不需要改动核心账号/角色结构。

## 待确认事项

- 权限模型具体粒度（RBAC 是否需要叠加数据级权限，如"仅能查看自己团队的任务"）。
- 是否需要对接企业已有的统一身份认证（SSO）。

以上事项在进入编码阶段前应先与业务确认，遵循"先定义领域，再写页面"的原则。
