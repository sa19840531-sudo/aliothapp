# domain/page 页面类型知识域

本目录承接页面类型识别、页面状态理解、下一页候选预测所需的稳定业务知识。它不执行浏览器操作，也不调用大模型，只提供可被 Agent、应用服务或后续数据库仓储读取的页面类型知识。

## 当前落地

- [page_type_catalog.json](page_type_catalog.json)：页面类型定义的唯一数据源，保存类型元数据、识别信号、运行特征、导航别名、路由前缀与页面转移关系。
- [catalog.py](catalog.py)：JSON 领域模型与兼容加载器，仅供 Registry 和测试复用。
- [registry.py](registry.py)：生产代码唯一读取出口，负责校验 Catalog、派生分类/映射并生成版本摘要与 Agent Context。

## 边界

- 页面类型知识属于领域知识，不放进 `agents/skills/phase/` 正文，避免 Skill 变成数据仓库。
- 规则判定标准仍归 `domain/rule` 与 `agents/skills/rule/` 管理。
- 页面截图、DOM、OCR、操作日志等运行时观测结果仍归 `domain/evidence` 与任务执行链路管理。
- 真实页面点击、截图、OCR、数据库写入仍通过应用服务、基础设施或 Agent Tool 完成。

## V1 使用方式

运行时页面识别应把当前页面观测包与本目录的页面类型知识一起交给模型或规则判定逻辑：

1. 从页面操作 Tool 获取 URL、DOM 摘要、可见文本、截图/OCR、可点击元素。
2. 读取页面类型知识，生成候选页面类型、识别信号和下一页候选。
3. 让模型输出当前页面类型、置信度、覆盖层状态、可能下一页和推荐动作。
4. 执行动作后必须重新识别实际到达页面，不得仅凭动作假设页面转移成功。
